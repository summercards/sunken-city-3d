# 晴空水巷：游戏体验交互检查与优化方案

检查日期：2026-10-19。对象：当前工作区实际版本，包括尚未提交的改动。

## 结论

项目已经具备采集、修建、种植、交易、改船、航行与潜水的系统基础。主要体验问题集中在操作意图不清、误触消耗、新手目标不突出，以及短周期经营对探索的打断。建议先提高操作可靠性和首局可理解性，再扩充内容。

本次只进行检查与方案整理，没有修改游戏实现。检查包括设计文档、输入与状态处理、经济规则、界面代码、现有测试，以及 Chrome 桌面画面和 390×844 竖屏模拟。实际执行了打开面板、采集物资、右键建筑、潜水和返回；没有完成真实计时的全流程通关，也没有进行真机触控、手柄、音频听测或性能基准测试。以下明确区分运行复现、代码确认与待验证判断。

## 优先级与发现

P0：先修复的可靠性问题。P1：首局体验与核心循环。P2：后续完善。

| 编号 | 优先级 / 依据 | 发现与影响 | 优化方案 | 验收要求 |

| 02 | P0 / 代码确认+运行复现 | 面板称“点击场景物件可查看配方，确认操作后才会消耗物资”，但建筑模型直接调用activateSite，材料足够便开工。预览与执行入口不一致。 | 建筑点击打开紧凑预览，显示升级前后差异及成本，再点明确的建造按钮；免费收获保留快捷操作。不要对所有动作都增加确认弹窗。 | 查看建筑不扣费；只有标明成本的建造动作扣一次；所有入口规则一致。 |
| 03 | P1，持续试玩前完成 / 代码和界面确认 | 试玩不保存，提示藏在物资面板。玩家可能投入一轮经营后刷新丢失进度。 | 增加带版本号的本地存档，覆盖资源、建筑、作物、设施、探索奖励与解锁；交易和建造结果落盘；中途状态恢复到合法停靠点。暂未支持时首局显著告知。 | 刷新、关闭重开、建造中退出、存档损坏均有明确行为；不重复发奖、不重复扣款。 |
| 04 | P1 / 画面确认，影响待新手测试 | 初始多处灰色升级箭头，没有突出首个可做动作；“潜水”比主循环下一步更显眼。面板有流程文字，但首屏不可见。 | 一次只提示一步：取屋顶物资→修复木屋→播种→收获→改船。用可收起的一行目标与目标物轻提示，完成后退场；保留自主探索。 | 首次玩家不看文档能找到物资箱；记录首个有效操作时间、首次建造时间和求助次数。 |
| 05 | P1 / 画面和CSS确认 | 悬停说明被整体隐藏；建筑通用箭头、资源小图标缺少名称与动作含义，触屏没有hover补偿。 | 聚焦/悬停只显示“名称+动作+必要条件”的短标签；触屏首次选中预览；明确区分可收获、可建造、未解锁、忙碌。 | 同类标记语义一致；颜色以外也有图形或文字区分；禁用目标仍能查看原因。 |
| 06 | P1 / 运行确认 | 360px物资面板把每张卡的成本、收益、前置、缺口、来源全部展开，首屏只能看到约一张完整卡。 | 默认显示当前选中目标与本区可操作项目；其余按区域折叠。常态只显示收益、关键成本、主按钮，缺材料时展开缺口和来源。保留全量浏览入口。 | 常见采集/种植/建造动作无需跨多张卡滚动；“去哪找材料”可直接定位来源。 |
| 07 | P1 / 代码确认，节奏待试玩 | 作物18秒失水，成熟需34秒，温室后26秒；失水停长。首次播种后，玩家很快必须返回照看，探索易被打断。 | 首轮作物一次浇水即可成熟；后续可试验延长湿润期或把浇水变为产量/速度奖励。数值围绕一次完整探索往返时长调整。 | 实测播种→邻区探索→回家时的停长占比、往返次数；先做小范围对比，不直接全量重平衡。 |
| 08 | P1 / 代码确认 | 同一个建筑动作在“升级”和“收钱”之间随累计产出切换。玩家熟练连点时，动作含义可能改变。 | 分离收取与升级目标；收益图标只负责收取，建筑详情只负责升级。保留重复点击冷却。 | 等待产出跨阈值时，升级按钮不变成收款；连点收款不启动升级。 |
| 09 | P1 / 代码确认 | 多资源奖励必须整笔放入背包；其中一种满仓就全部拒收。已有错误提示且不丢奖励，但缺少直接腾空间的操作闭环。 | 先提供库存当前/上限与可消费去向；进一步考虑溢出暂存，必须明确保留位置和领取规则。 | 木料满而零件未满、种子满而食物未满等组合，都有可理解的恢复路径；不静默丢资源。 |

## 需要保留的基础

- 场景成长反馈有效：本次建造完成后木屋明显增加绿植，符合“修建会改变世界”的方向。
- 经济层已处理前置、忙碌、重复执行、容量与交易原子性；满仓失败保留奖励。
- 面板已有明确缺口/来源、状态播报与焦点管理，应简化信息层级而非删除这些帮助。
- 潜水支持自动游近宝箱和随时返回；没有必要为了增加操作量而取消这些便利。
- 场景气质统一，界面优化应继续保持画面留白。

## 建议落地顺序

### 第一批：操作可靠

完成01、02，分离08中的收取/升级行为。补充真实输入回归：左键、右键、拖拽、双击、触控取消、面板遮挡与模式切换。先封住误触消耗，再改变引导与数值。

### 第二批：首局可理解

完成04、05、06及最小库存说明，提供一条可收起的下一步提示。存档03在开放持续试玩前完成。重点是让玩家知道“现在能做什么、为什么不能做、去哪里补条件”。

### 第三批：经营与探索协调

用真实计时试玩调整07、09、10，观察重复跑图与等待。建议初始目标：30秒内完成首次有效交互，2分钟内感知第一次场景成长；完整首局仍以GDD约20分钟为方向。这些是待验证目标，不是本次测得数据。

### 第四批：多设备与体验完善

完成11—15的设备适配、模式教学、后台规则和设置；真机验收后再扩展更多区域或生产链。

## 验证结果与缺口

执行命令：`node --test tests/economy-unit.cjs tests/sail-nav-unit.cjs`（使用应用内置Node绝对路径运行）。结果：33项通过，0失败，退出码0。

这只能证明经济规则和寻路算法的相应断言通过，不能证明玩家可发现入口、真实场景全程不卡住或没有输入误触。现有p0-core-flow会程序化打开指定卡片并加速时间；适合检查闭环，不能作为20分钟自然游玩或新手引导通过的证据。本次没有重新运行浏览器回归全集。

建议补充自然游玩脚本：新玩家从空白状态进入，不调用内部函数、不加速时间，完成取物资、修木屋、播种收获、跨区采集、改船、远海、潜水、返回、刷新续玩。记录首次操作、误触、无效点击、找不到目标、往返次数、停长时间、完成率；至少安排一轮桌面和一轮手机真机测试。不要让测试人员预先知道按钮位置。
