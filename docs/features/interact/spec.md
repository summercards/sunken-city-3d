## 功能目的与边界

正式或规划入口：点击目标自动接近，或靠近按住 E。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-INTERACT-R01 | 交互查询返回可用性、提示和所需时长；缺资源或不满足条件必须解释。 |
| SEA-INTERACT-R02 | 松手、离开范围、切换目标或取消时中止当前进度，不发放完成奖励。 |
| SEA-INTERACT-R03 | 菜单与世界点击隔离，密集地格操作锁定玩家选中的目标。 |
| SEA-INTERACT-R04 | 交互完成/拒绝只通知控制器结束一次；取消清除 hold、preferred 和自动输入，模态阻断自动按住。 |

## 所有者、接口与数据

状态/交付所有者：**Interactor / Interactable / ActorController**。正式代码和资源入口：

- [godot/src/interaction](../../../godot/src/interaction)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。

## 2026-10-29 移除世界里的聚焦环

焦点反馈只保留「焦点文案 + 悬浮图标」，世界里不再画贴地环。
原因：环按视觉包围盒放大（上限 3 倍），多格菜箱的包围盒覆盖整张培养甲板，
环被撑到直径近 4 米；抬高的土箱又把环切成几段，俯视时读成甲板上一道无意义的白弧，
而不是「这个是焦点」。环的尺寸与判定半径本来也不是同一件事，留着只会误导。

焦点状态本身不变：`focused` 仍然置位、`focus_changed` 仍然发信号，
HUD 焦点文案与悬浮卡片照旧工作。

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-INTERACT-R08 | 世界里不得出现常驻的焦点环/光圈：焦点只能通过焦点文案与悬浮图标表达，任何 3D 焦点指示都不得在甲板或海面上留下独立弧线/环带。 |

## 2026-10-29 走不到的地方不给入口

人在这边、走路过不去的目标，**不该出现操作菜单**。这是用户看到第一版修复后的原话：
菜单能弹出来、也写了「需要先坐船靠岸」，但它出现在一个点不动的东西上，
本身就在说「这个能操作」——那是在骗人。

于是规则收敛成三条：

1. **不给入口。** 陆地状态下走不到的目标：不显示悬浮图标、不改指针、点击不弹菜单。
   点击只给一句原因（「那边在别的区域，需要先坐船靠岸」/「那里走不过去，中间没有连通的路」/
   「那里是水面，走不过去」）。有图标就等于许诺可以点。
2. **命中范围就是模型本身。** 从相机发一条射线，打到物体的三角形才算命中
   （用户的说法：「功能热区就按照模型去做吧」）。
   走过两个弯路都记在这里当反例：只认「距图标 30 像素」时物体本体点不中，
   因为图标是命中之后才画的；改成「屏幕包围盒外扩 10 px」后，
   六个并排土箱之间的甲板缝（屏幕上只有十几像素宽）被两侧 AABB 盖满，
   点地面会被判成点土箱，于是走不了路。
3. **可达性按「站到哪操作」判，不按物体中心判。** 有 `approach_points` 就用它
   （培养土把中心从可行走面里挖掉了，按中心判会把自己刚建好的菜箱说成走不过去）。

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-INTERACT-R09 | 陆地状态下走不到的可交互物不得给出操作入口：不显示悬浮图标、不改指针、点击不弹操作菜单，只给一句原因（跨区需先坐船靠岸 / 路径断开 / 水面）。可达性判定优先使用 `approach_points`，没有才退回 `focus_position()`；查询带 350 ms 缓存。任何接近失败都不得静默返回。 |
| SEA-INTERACT-R10 | 点击命中按模型三角形判定（摄像机射线 vs `visual_root()` 下所有 `MeshInstance3D` 的三角形），不得用屏幕包围盒、外扩矩形或固定像素半径去近似物体本体。只允许两处例外：没有几何的纯逻辑交互点用图标 30 px 半径；单个网格超过 1500 面时该网格退回自身 OBB 粗筛。相邻物件之间的真实缝隙必须交给地面（点击即走路），不能被两侧热区盖满。模型命中优先于图标热区。 |

## 2026-11-07 触发式交互：不读条、朝向只仲裁、上下船走热区

用户原话：「有些功能不需要读条，直接走近，进入判定区，出现图标，点击即可触发。比如种植区，不需要读条。大部分的操作反馈都不用压住读条。非常奇怪。」「码头的上船区，应该是在海面的，进入热区后点击即可靠岸上岸，上岸后，在陆地，走进船只，船只出现可上船图标，点击一下就坐上船。」「如果在岸上，同时进入种植区的判定区和上船的判定区，以角色面朝向为优先级判定。」

本节覆盖 R22 的「正面锥是准入门槛」与 R23 的「上船朝向门槛 + 船头方向锥」，把朝向从**门槛**降为**仲裁**；R20 的「必须先松开」在触发式语义下重新定义。业务结算、鼠标模型命中、已选命令的自动接近链路保持不变。

**一处设计修正（已在回复中向用户声明）**：朝向不能当硬门槛。背对船一米上不去，比「误触」更糟，而且玩家会以为坏了。正确做法是「判定区内只有它 → 直接可选；判定区内有多个 → 按面朝向仲裁」。补充项：靠妥容差、单一仲裁源、岸边挡停仍可转脸（SEA-MOVE-R27）。
