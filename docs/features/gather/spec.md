## 功能目的与边界

正式或规划入口：靠近岸边采集点交互。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-GATHER-R01 | 采集点使用稳定 ID，前置建筑等级、资源、数量和冷却来自配置。 |
| SEA-GATHER-R02 | 完成采集后进入冷却，读档恢复相对剩余时间及枯竭表现。 |
| SEA-GATHER-R03 | 背包容量不足有明确反馈，不能无提示丢失奖励。 |
| SEA-GATHER-R04 | 采集前置通过注入的建造服务查询；快照由 GatherField 捕获和恢复，不由 SaveGame 遍历私有节点。 |

## 所有者、接口与数据

状态/交付所有者：**GatherField / GatherSpot**。正式代码和资源入口：

- [godot/src/gathering](../../../godot/src/gathering)
- [godot/assets/data/gather_spots.json](../../../godot/assets/data/gather_spots.json)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。

## 2026-11-06 采集点回到世界里

起因是用户的两句话：「海上的采集，无法靠近使用 E 键采集」「还有很多交互位置没有 E 键可以用的地方，导致没有鼠标就无法操作」。查下来第一个问题不是距离，而是**十个采集点在默认范围里全被藏起来了**。

| 条款 ID | 规则与验收 |
|---|---|
| SEA-GATHER-R05 | 采集点按**所属区块**启停，不跟随「整个采集场」一起藏。只要该区块在当前玩法范围里启用，它的采集点就必须可见、在 `interactable` 组里、能被 Interactor 选中。禁止使用「遍历所有交互物、把不可见的永久移出组」这类单向降级：离组之后读档、切回完整范围都救不回来。未启用区块的点随区块隐藏，但**不得**从组里移除。`build_field` / `salvage_winch` 在该范围里没有入口，仍按原来的方式关闭。 |
| SEA-GATHER-R06 | 装配时以场景回算落点：XZ 取表里的设计摆放，**高度取该点在所属区块可走面上的真实表面**；`gather_spots.json` 的 `y` 从此只是参考值，甲板被手工调整后不需要同步改表。XZ 已不在任何可走面（>3 米）时才吸附到最近可站点，并打一行 `push_warning` 记录原坐标与吸附结果。验收：每个已装配的采集点 `area_at(pos, 0.6) != null`，且与所属区块登陆点之间的步行路线非空。 |
