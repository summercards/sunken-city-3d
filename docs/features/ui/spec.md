## 功能目的与边界

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-UI-R01 | 资源、升级和拒绝操作给出可读反馈，菜单阻断背后的世界点击。 |
| SEA-UI-R02 | UI 发出命令并读取状态，不直接写入业务模块内部状态。 |
| SEA-UI-R03 | 面板随窗口大小可读可操作，触控/手柄支持必须单独验证后登记。 |
| SEA-UI-R04 | HUD 一次一张实物卡：九格主卡420×620，经营详情展开为680×680；海面渔具箱/水下防水日志，3×3分页与详情共用壳，提示胶囊在卡外。 |
| SEA-UI-R05 | 顶部52高只读状态区显示时间/潮汐/水深/氧气；无真实数据显示「—」。首行常驻工具带锁不可出售，下两行收成显示库存，零数量不画角标。 |
| SEA-UI-R06 | 开卡0.22s BACK/OUT（y+64、0.92→1）同步背景去饱和18%/黑12%；翻页0.18s CUBIC/IN_OUT、±366、卡内裁剪且连按不堆叠。 |
| SEA-UI-R07 | 图标hover0.12s到1.06，选中3px描边与1.2s呼吸；数量0.4s滚动并上浮8px，收成0.48s飞入后0.55s高亮衰减。 |
| SEA-UI-R08 | 氧气≤30%橙边，≤15%红边并±2px/10Hz抖动；总开关可关闭，屏幕提示不随卡抖动。 |
| SEA-UI-R09 | 当前已实现界面统一奶油纸张、柔和图标、胶囊按钮和焦点：主卡、种植、建造、仓储、物品、地图、相机、滤镜/水面、订单、打捞、提示与弹窗。外部presenter仅通过UI层装饰，不改业务目录源码。 |
| SEA-UI-R10 | Esc优先关闭弹窗/返回详情上层/关闭当前面板，世界中才开启暂停菜单；暂停停止世界与耗氧，继续恢复此前暂停状态，不隐式上浮。读档与退出提供取消优先确认。 |
| SEA-UI-R11 | 系统菜单提供继续、原保存/读档命令、偏好设置、操作说明和退出。动画/低氧反馈/音量使用独立UI配置，保留游戏存档键；全屏即时应用。 |
| SEA-UI-R12 | 详情可滚动、面板按视口定位；原生验证1600×1000及1280×800、1920×1080。反馈背景与文本同步显隐/淡出；正常、拒绝、等待、成功、失败和取消均单独记录证据。 |

| SEA-UI-R13 | 所有游戏界面使用同一份可分发中文圆体：霞鹜975圆体SC 700W；1600×1000基准标题40px、正文22px、按钮24–26px、对话30px、主卡图标18px。细密工具最低18px；同家族覆盖弹窗、世界标记与临时控件。字体与几何分别抗锯齿，原生逐页及三分辨率验证。 |
| SEA-UI-R14 | 按原始参考区分形态：九格应用保持圆角彩色底；背包为无底物品格、真实堆叠、空位圆点及选中名称胶囊；选项轻薄无厚投影；对话为柔和气泡和姓名标签；保留原有命令与返回链。 |
| SEA-UI-R15 | 纸背板的圆角不得吃进内容框：圆角半径由该面板的内容边距反推得上限（内容边距 + 纸外扩 − 8px），与面板被拉多宽多高无关；纸在四边各外扩24px，面板内控件位置与字号一律不动。任何浮在纸边的装饰标签须同步外扩，纸连同装饰不得越出视口。 |
| SEA-UI-R16 | 浮在3D画面上、无背板托着的纯文字（资源常驻行、潜水状态、视野提示、上岸点名称、水下宝箱名牌）一律：字号不小于26px（基准1600×1000下资源行44px、潜水40px、视野33px、上岸点26px、宝箱29px，均至少为原值的1.5倍）；使用打包圆体并叠加合成加粗以补齐拉丁数字与汉字的字重差；**不得勾边** —— 不用 `font_shadow` 轮廓、不用 `draw_string_outline`，只允许固定偏移的柔和投影。这些判据由 `visual-world-text` 闸门固化。 |
| SEA-UI-R17 | 「被调画的对象」不得被调画界面自身改动：滤镜/水面面板（P 键）打开时仍算模态（世界浮层收起、点击拦住），但不铺 R06 那层去饱和 18% / 压暗 12% 的屏幕遮罩。理由是可测的 —— 该遮罩会把面板下方每一个像素整体改色，取色器读到的不是场景真实像素。遮罩开关集中在一处（`HUD._sync_backdrop`），背包 / 相机 / 订单 / 打捞的遮罩行为保持 R06 不变。 |
| SEA-UI-R18 | HUD 与面板仅通过注入的命令/查询模型调用业务；样式适配器接收明确的面板引用，不沿父节点查找 Main。 |

## 所有者、接口与数据

状态/交付所有者：**HUD / UI presenters**。正式代码和资源入口：

- [godot/src/ui](../../../godot/src/ui)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。

## 当前实现与待完成边界

HUD 已使用程序化单卡与两页九格，经营详情在同一卡内；具体参数、Cozy token复用/绕过和真实数据链见[单卡交付记录](../../development/2026-10-26_ui_ac_single_card.md)。卡片和状态表现不新增业务写入者。

部分旧经营展示仍直接读取业务字段；功能级面板分别由所属功能代码目录管理。即时出售仅调用现有作物出售命令，鱼/贝壳/珍珠保留码头交易入口；不在UI中创造新经济规则。时钟/潮汐未接入，显示「—」。相机、滤镜、订单、打捞和交互提示保留原所有者，通过 `island_presenters.gd` 装饰现有控件；不复制业务规则。系统暂停与UI偏好由 `island_menu.gd` 管理。

主卡仍遵循任务书九格、状态只读和卡外提示；按用户补充的全界面要求，经营详情增加宽度，独立功能面板居中或靠右。实际覆盖范围见交付记录，不据此声称触控/手柄通过。

现有规则继续运行；独立文档、账本和目录归位不代表所有行为已经独立测试，也不代表全部原始目标已实现。阶段事实以本功能账本为准。
