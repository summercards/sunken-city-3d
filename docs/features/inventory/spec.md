## 功能目的与边界

正式或规划入口：背包页和所有资源收支。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-INVENTORY-R01 | 物品定义由 items.json 唯一拥有，货币不占背包格，其余物品按堆叠上限占格。 |
| SEA-INVENTORY-R02 | 不足资源时整笔扣除失败且数量不变，增加时明确返回溢出。 |
| SEA-INVENTORY-R03 | 背包数量由 Inventory 唯一写入；物品 ID、容量和数量有存档契约。 |
| SEA-INVENTORY-R04 | 存储数据必须含容量和计数字典，负容量/负数量/错误类型在进入 Inventory 前拒绝；背包与仓库分别拥有实例。 |

## 5. 资源与数值草案

### 5.1 资源层级

第一版建议分为三层：

1. **海贝：** 通用货币，用于升级和基础交易。
2. **基础物资：** 木料、旧零件、食物等，用于修缮、生产和船只改造。
3. **特殊材料：** 深海材料、旧时代零件或稀有生物资源，用于高阶船只和特殊建筑。

当前工程已实现海贝的可玩闭环，但基础物资、特殊材料、仓储和交易链仍属于后续开发内容。

### 5.2 当前工程已存在的数值基线

下表是根据当前工程代码整理出的可运行数值，不等同于最终平衡方案：

| 项目 | 当前值 |
| --- | ---: |
| 初始海贝 | 80 |
| 建筑产出结算间隔 | 6 秒 |
| 单个建筑储存上限 | 10 枚海贝 |
| 初始木屋等级 | Lv.1 |
| 木屋升级成本 | 20 海贝 |
| 横滨铁道第 1 阶段成本 | 20 海贝 |
| 横滨铁道第 2 阶段成本 | 40 海贝 |
| 横滨铁道第 3 阶段成本 | 65 海贝 |
| 天台种植园第 1 阶段成本 | 25 海贝 |
| 天台种植园第 2 阶段成本 | 50 海贝 |

### 5.3 数值设计原则

- 前 3 分钟内玩家应能完成第一次低成本建造。
- 第一次收获应明确帮助玩家完成下一次升级，而不是只增加无意义余额。
- 船只升级应需要“海贝 + 航海材料”，避免完全依赖单一货币。
- 产出上限和收获操作用于制造轻度节奏，不应迫使玩家频繁上线。
- 数值最终应服务于场景变化和探索解锁，而不是无限增长。
