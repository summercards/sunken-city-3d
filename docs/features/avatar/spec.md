# SEA-AVATAR · 角色档案与外观定制

[主文档中控](../../../GDD_V1.0.md#sea-avatar) · [独立账本](ledger.md)

设计修订 r3，2026-11-02（连续四肢骨骼蒙皮）。目的：让每位玩家以自己的名字和外观开启海上生活，并为后续衣服图案 DIY、配件及内容包保留可维护入口。

## 体验与美术

不设性别限制，所有组合均可混用。角色采用原创圆润几何；比例严格以用户2026-11-02提供截图的轮廓标点为准，替代先前通用2.6头身估计，使用宽头脸、窄肩腰、修长于旧版的腿部和小手脚；不使用其角色、纹理或图标。程序网格是本次正式制作源，保持 sea 现有节点动作契约，不要求外部 Blender 链路。

界面沿用 SEA 的霞鹜圆体、奶油纸张、青绿选中、暖黄确认和胶囊按钮。左侧为真实码头人物，右侧为可滚动的选项纸页。选项显示名称、颜色及选中标志；提供左右旋转、正面复位与随机搭配。先姓名，再外观，再一页旅人证预览，确认后写盘；随时可返回上一步。姓名 1–12 字，首尾空白自动清理，拒绝控制符和界面标记字符。

八类目录：肤色；头发；眼睛；五官；上装；下装；鞋子；配饰。18 个槽位均有稳定字符串 ID，几何与颜色分离。首版 6 肤色、6 发型、8 发色、4 眼形、6 瞳色、3 眉形、3 鼻形、4 嘴形、3 脸颊、4 上装、2 下装、3 鞋、4 帽子、3 眼镜，各服装配色 9 种，共95选项。后续选项不改变已存 ID。

## 接口和扩展

`godot/src/avatar/`：catalog 查询内容；profile 提供 query/commit/to_dict/from_dict/validate_snapshot/changed；visual 接收 appearance，仅拥有生成网格与表现容器；editor 发送保存/取消意图；session 注入 player、camera、profile 与 save Callable，不查 Main/Economy 全局。

持久化：`profile={version:1,name,completed,appearance:{slot_id:option_id},design_refs:{slot_id:design_id},extensions:{}}`。未完成新局 completed=false，可在未完成退出后重新开始创建。草稿不落盘；确认提交后保存失败回滚已提交值，界面仍保留草稿。

新增选项修改 `godot/assets/data/avatar_catalog.json` 并在 visual 的几何解析器增加对应款式；新增槽位必须给默认值与明确迁移。未来 DIY 先新增设计仓库、设计ID与材质解析端口，再开放绘图界面；当前不宣称具备绘图、外部模型导入或联网分享。

## 连续四肢与骨骼蒙皮（r3，用户红框问题）

| 条款 ID | 规则 |
|---|---|
| SEA-AVATAR-R14 | 每条完整手臂（含手）和完整腿（含脚）各是一张闭合、连通、带共享顶点的连续网格；肘/膝处没有分段球体、封口断面或独立几何。由原生Skeleton3D+Skin驱动渐变权重弯曲，21骨骼（根+四组上段/下段/末端控制及上/下段伸长辅助骨），4权重通道，肘膝两骨平滑过渡。换装只改材质/颜色阈值，不重建骨架或写入玩法；保存仍只保存原外观ID，不序列化骨骼姿势。专项须验证闭合/单连通/权重归一化/正常面绕序、0–120°截面不塌陷，以及仅改变骨骼也能改变真实GPU画面，并检查肘膝近景和原动作。 |

`avatar_limb_skinning.gd`唯一拥有四肢网格、绑定及骨骼姿势写入；`avatar_limb.gdshader`拥有袖口/裤脚/鞋底的材质分区，UV同时保留环向与纵向信息供后续DIY。原BodyPivot/肩肘/髋膝节点仅作为不可见动作控制，不再包含旧胶囊或球关节。现有动作采样器→控制姿势→骨骼→GPU蒙皮，避免同时绘制两套四肢。伸长辅助骨不向下一个旋转关节传递非均匀缩放，避免获物伸手时剪切、变粗或手掌错位。

正式骨骼资产为SEA-CHAR-RIG-001；实际骨名、父子和静止位置见[骨架契约](../../../art_source/characters/avatar/v002/rig_contract.json)。本轮仍为可维护Godot程序源，没有声称生成Blender/GLB。用户圈选接缝的[问题截图](../../../art_source/characters/avatar/v002/joint_request.png)仅用于追溯，不进入运行目录。
