# SEA-AVATAR · 角色档案与外观定制

[主文档中控](../../../GDD_V1.0.md#sea-avatar) · [独立账本](ledger.md)

设计修订 r7，2026-11-03（最新肩口红线修订）。目的：让每位玩家以自己的名字和外观开启海上生活，并为后续衣服图案 DIY、配件及内容包保留可维护入口。

## 体验与美术

不设性别限制，所有组合均可混用。角色采用原创圆润几何和粗线条五官；最初基体来自2026-11-02指定图比例，当前默认按2026-11-03最新红线改为饱满躯干/四肢、收拢肩颈、适度展开衣摆和低胯短腿。头大小与横向比例独立可调。参考图仅为风格/轮廓依据，不复制角色、纹理或图标像素。程序网格是正式制作源，保持sea节点动作契约，不要求外部Blender链路。

界面沿用 SEA 的霞鹜圆体、奶油纸张、青绿选中、暖黄确认和胶囊按钮。左侧为真实码头人物，右侧为可滚动的选项纸页。选项显示名称、颜色及选中标志；提供左右旋转、正面复位与随机搭配。先姓名，再外观，再一页旅人证预览，确认后写盘；随时可返回上一步。姓名 1–12 字，首尾空白自动清理，拒绝控制符和界面标记字符。

九类目录：体型、肤色、头发、眼睛、五官、上装、下装、鞋子、配饰。23个稳定字符串槽位、147选项；含4体型、14发型、12眼形、5胡子，9项连续调节参数。款式、配色、刘海与发饰分开，既有ID保持。最新默认体型以2026-11-03红线轮廓为准：肩颈收拢、衣摆适度展开、胯位降低与短腿饱满四肢；头大小/横向比例、臂粗和腿长均可调。原2026-11-02六项比例保留历史追溯。

## 接口和扩展

`godot/src/avatar/`：catalog 查询内容；profile 提供 query/commit/to_dict/from_dict/validate_snapshot/changed；visual接收appearance与morphs，仅拥有生成网格与表现容器；morphology拥有有界尺寸与衣服曲线，face/hair分别拥有曲面五官与发型；editor 发送保存/取消意图；session 注入 player、camera、profile 与 save Callable，不查 Main/Economy 全局。

持久化：`profile={version:1,name,completed,appearance:{slot_id:option_id},morphs:{morph_id:0.5},design_refs:{slot_id:design_id},extensions:{}}`。未完成新局 completed=false，可在未完成退出后重新开始创建。草稿不落盘；确认提交后保存失败回滚已提交值，界面仍保留草稿。

新增选项修改 `godot/assets/data/avatar_catalog.json` 并在 visual 的几何解析器增加对应款式；新增槽位必须给默认值与明确迁移。未来 DIY 先新增设计仓库、设计ID与材质解析端口，再开放绘图界面；当前不宣称具备绘图、外部模型导入或联网分享。

## 指定参考图比例与自行验收（r2，历史冻结）

2026-11-03用户最新轮廓/短腿/饱满体型要求由R22覆盖默认体型；旧六项严格数值不再约束新默认。当前[轮廓契约](../../../art_source/characters/avatar/v005/shape_contract.json)明确记录变更原因、最新红线参考和设计区间，仍以实际顶点投影验收。

用户指定：[原图](../../../art_source/characters/avatar/v001/reference_proportions.png)；[人工标点与比例目标](../../../art_source/characters/avatar/v001/reference_contract.json)。参考为230×350像素，标点有约±3px分辨率误差。头脸含耳、不含头发和帽子，肩不含弯曲前臂，腰不含袖子；配饰从解剖量测中排除，正式创建界面另验全套配饰。画面按相同总高和鞋底线对齐，不拉伸任何坐标轴。

| 条款 ID | 规则 |
|---|---|
| SEA-AVATAR-R13 | 使用用户指定图冻结六项比例：头脸宽高1.5357、肩宽/头宽0.5814、躯干宽/头宽0.4186、腿长/头高0.9048、躯干长/头高0.8214、双脚跨度/头宽0.3798。真实网格顶点经固定近似参考的3/4正交镜头投影后逐项验收，相对偏差每项≤5%；必须同时亲眼检查等高对照、正面和侧面，再回归创建/保存/动作。测试报告保存测量值，不能仅检查配置常量。 |

制作源`avatar_dimensions.gd`拥有基础静止尺寸，`avatar_visual.gd`拥有几何轮廓，`Character`和`item_receive`消费同一尺寸表；不得只在相机或角色根上缩放掩盖比例。礼帽、衬衫马甲、小皮鞋和烟紫色已纳入当前目录，可保存组合。后续部件须服从同一基体比例；头发和帽子允许在基体外扩展。

## 连续四肢与骨骼蒙皮（r3，用户红框问题）

| 条款 ID | 规则 |
|---|---|
| SEA-AVATAR-R14 | 每条完整手臂（含手）和完整腿（含脚）各是一张闭合、连通、带共享顶点的连续网格；肘/膝处没有分段球体、封口断面或独立几何。由原生Skeleton3D+Skin驱动渐变权重弯曲，21骨骼（根+四组上段/下段/末端控制及上/下段伸长辅助骨），4权重通道，肘膝两骨平滑过渡。换装只改材质/颜色阈值，不重建骨架或写入玩法；保存仍只保存原外观ID，不序列化骨骼姿势。专项须验证闭合/单连通/权重归一化/正常面绕序、0–120°截面不塌陷，以及仅改变骨骼也能改变真实GPU画面，并检查肘膝近景和原动作。 |

`avatar_limb_skinning.gd`唯一拥有四肢网格、绑定及骨骼姿势写入；`avatar_limb.gdshader`拥有袖口/裤脚/鞋底的材质分区，UV同时保留环向与纵向信息供后续DIY。原BodyPivot/肩肘/髋膝节点仅作为不可见动作控制，不再包含旧胶囊或球关节。现有动作采样器→控制姿势→骨骼→GPU蒙皮，避免同时绘制两套四肢。伸长辅助骨不向下一个旋转关节传递非均匀缩放，避免获物伸手时剪切、变粗或手掌错位。

正式骨骼资产为SEA-CHAR-RIG-001；实际骨名、父子和静止位置见[骨架契约](../../../art_source/characters/avatar/v002/rig_contract.json)。本轮仍为可维护Godot程序源，没有声称生成Blender/GLB。用户圈选接缝的[问题截图](../../../art_source/characters/avatar/v002/joint_request.png)仅用于追溯，不进入运行目录。
