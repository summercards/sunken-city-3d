# 3–5分钟水下体验主方案

[SEA-DIVE 功能文档](spec.md) · [SEA-DIVE 独立账本](ledger.md) · [SEA-CAMERA 规划](../camera/spec.md#2026-11-14-水下体验镜头与轻潜水镜设计规划planned) · [SEA-MOVE 规划](../move/spec.md#2026-11-14-潜水角色动画3c承接设计规划planned) · [SEA-SAVE 规划](../save/spec.md#2026-11-14-潜水远征照片与采集存读设计规划planned) · [本轮开发记录](../../development/2026-11-14_underwater_experience_plan.md)

## 1. 交付边界

本轮交付为**可进入开发的详细设计**，更新主方案、GDD、四功能 spec/ledger 和开发记录；不改游戏代码、场景/TSCN、资产、root v4 或玩家存档。目标是在现有 `DiveSession`、Shared DiveRuntimeController、Map 适配、圆幕过场、Inventory、WorldClock 和 SaveGame 框架上，设计一次可重复的 **3–5 分钟潜水短体验**：电影化入水 → 选择一项主活动并顺路探索 → 打捞／拍照／抄网捕鱼 → 电影化出水 → 收获与观察记录按既有保存意愿持久化。不是每次必须完成三项活动。

首版产品选择由本方案给出默认决策，仍允许体验测试后调整；“已确定设计”不等于“用户已试玩认可”或“代码已完成”。3A是连续动作、镜头舒适、视听反馈和交互可靠性的参考标准，不是已经达到的质量评级。

所有本节与 SEA-DIVE-R52–R75、SEA-CAMERA-R18/R19、SEA-MOVE-R32、SEA-SAVE-R20/R21 均为 `planned`；运行状态为 `pending`。既有历史 PASS 只能作为接口背景，不能替代本轮真实验收。

## 2. 玩家体验节奏

| 阶段 | 目标体验 | 约束 |
|---|---|---|
| 电影入水 | 无文字圆幕遮挡加载，展开后看到角色从水面进入水下 | 复用既有 curtain、switching、transition_frozen；到swim才解除过场门禁并允许输入/Air，active存档禁写仍保持 |
| 观察与移动 | 以第三人称探索一小段水下路径，角色有踢蹼滑行、悬停、倒游、侧移、刹停和转身 | 移动由碰撞后实际速度驱动；不假踢蹼、不拉伸肢体、不用陆地步频；镜头由 Shared DiveRuntimeController 唯一拥有 |
| 打捞 | 发现并完成少量可交互目标，获得可堆叠或唯一资源 | 目标稳定 ID、奖励原子事务、满包/重复/过期 token 不消耗目标；Inventory 是唯一物品写者 |
| 拍照 | 在目标或环境构图中保存一次观察记录，可选引用本地图片 | `photo_id` 稳定；最佳构图、首次日期和可选相对图片引用入 `dive.expedition.photos`；JSON 不写二进制或绝对路径 |
| 抄网捕鱼 | 对鱼群执行短时、可取消的抄网动作，按日配额收取物品 | 玩法状态由潜水控制器/内容适配器交接，奖励仍由 Inventory 统一提交；不能在忙状态或写盘失败时重复发奖 |
| 电影出水 | 结束后沿现有返回事务恢复同一 Main、角色、船、相机、环境和 UI | 不重建 Main、不重读存档、不遗留第二套相机/WorldClock/输入所有者 |

目标不是强制玩家在每次潜水完成全部活动。3–5 分钟是完整体验的参考窗口；玩家可提前上浮，未完成目标不被伪造为完成，已得内存资源按现有保存意愿处理。

## 3. 所有权与接口关系

- **DiveSession**：持有跨地图的潜水会话、共享 Air 生命周期、稳定进度与 `dive.expedition` durable owner；不持有 Map 几何、不写 Inventory。
- **Shared DiveRuntimeController**：唯一解释潜水输入、四态生命周期、实际运动、潜水相机姿态、潜水角色表现、电影进出水释放点和 Air 消耗；不新增 Splash FSM 或第二相机 owner。
- **Map 适配器**：只提供入口、路线、碰撞、安全 `camera_clip`、环境、目标内容和鱼群查询/执行端口；不独立 tick 输入、氧气、相机或奖励。
- **Inventory**：唯一物品写者；打捞、捕鱼和日配额奖励都经原子提交端口。
- **WorldClock**：海面唯一日历真值；07:00 epoch 注入潜水资源刷新和全局日配额。潜水期间海面钟停，重入不刷新。
- **SaveGame / SnapshotRegistry**：沿既有 busy/capture/write/restore 门禁执行；返回同一 Main 且所有 busy 解锁后，最多请求既有 `SaveGame.write` 一次。
- **照片服务**：异步产出图片后才允许写 `photo_id` 的本地相对引用；失败不删除观察记录，不宣称图片与 JSON 跨文件原子。

## 5. 实施顺序

1. P0先验证耗气、回程安全路径与Controller出水释放点，维持现行唯一owner；家园浅层做一条可玩的验证路线，不动手摆建筑。
2. P1接入稳定ID、活动事务和存档迁移，让一处打捞、一处捕鱼、一个照片目标形成完整可回归闭环，再铺内容。
3. P2完成潜水装备/脚蹼、动作层、远广角与镜片效果及声音交接，避免先做特效后发现活动无法安全结算。
4. P3按第16节做路线、真实输入、多体型/帧率/宽高比及双渲染后端验收；真实结果分别回填spec/ledger，不把算例当引擎测试。

本文件是主方案，不是实现承诺；`planned`、`pending` 和历史未签边界在实现与运行报告完成前保持不变。

## 6. 现有海底内容基线与新增边界

本方案先按正式工程当前真实内容设计，不把装饰资产或调试能力写成已存在的玩法：

- 家园海底 `dive_home_seabed` 当前没有宝箱、海底资源奖励或可捕捉鱼；鱼群是观赏组件。阳光房场景当前为 10 群、共 178 条鱼的视觉内容，数量和位置以现行 TSCN 为准。
- 旧九张独立潜水图当前共有 23 个一次性宝箱，稳定全局 ID 为 `0..4`、`100..101`、`200/203`、`302/304`、`404`、`501/502`、`600/602/603`、`701..703`、`800..802`。宝箱奖励只复用当前物品与瓶盖：合计 `wood×34`、`parts×28`、`coins×120`、`pearl×13`、`fish×8`；这些奖励仍由旧宝箱链路负责，不与新增潜水远征配额混账。
- 当前海底鱼群全部是视觉组件，不能直接把鱼群数量当作捕鱼产量；海面鱼群收取也仍归 SEA-PICKUP。水下捕鱼必须新增稳定的 `dive_fish_target` 内容端口，复用 `fish` 物品，不复用装饰鱼节点作为物品写入者。
- 正式工程尚未有玩家摄影收集系统；本轮的 `photo_id`、构图摘要、相册观察记录和可选图片引用均为 planned，不能以 CameraPanel、工程截图或自由观察相机替代。
- 家园新增资源目标首版只允许复用 `wood`、`parts`、`glass`、`rope`、`pearl` 等已登记物品 ID；不新增“海底专属材料”，具体收益与现有用途见第12节。新增节点、奖励、日配额和图片链路在开发阶段登记为 pending，未完成前不宣称家园已经可打捞/捕鱼。

## 7. 三条首发体验路线与奖励预算

3–5 分钟指 **`swim` 解锁后至玩家主动请求上浮的有效水下窗口**；圆幕、加载、准备、恢复和图片异步不计入窗口。路线不是强制任务，玩家可以只拍照、只打捞或提前返回。

| 路线 | 推荐地图/深度层 | 3–5 分钟内的主目标 | 首版真实奖励边界 | 体验重点 |
|---|---|---|---|---|
| 浅层观察 | 家园海底，浅层与中层鱼群 | 观察 1 个鱼群、拍 1 张环境照、完成 1 个近岸小打捞（planned） | 0–2 个已登记材料；拍照首版只记观察，不发瓶盖 | 学会悬停、绕行、调镜头和安全返程；家园当前无奖励，目标需先实现 |
| 中层寻箱 | `dive_zone1/2` 等已有宝箱图 | 完成 1 个旧宝箱，余时拍照或尝试 1 次抄网 | 直接使用该宝箱既有奖励；新增捕鱼每日上限建议 `fish×2` | 旧内容真实可玩，打捞读条与氧气余量形成取舍，不叠加完成奖金 |
| 深层遗迹 | 旧城/深谷宝箱区域 | 1 个深层宝箱 + 1 张深度/遗迹照片，低氧前沿返程 | 直接使用既有宝箱奖励；深层不额外掉落瓶盖 | 以返程余量和能见度为压力，不用强制死亡或扣已有资源 |

**首版取消“每次最多2箱/2鱼/3照片”的硬性活动次数限制。** 这会打断探索，也会让重入绕过限制。单潜1–2个主目标只是内容密度建议，不是奖励门禁。旧宝箱只受一次性 `opened` 规则限制；照片可反复拍并更新最佳记录；新增打捞与捕鱼由第12节的稳定目标、全图共享日配额和真实背包容量约束。配额用 `resource_epoch + consumed + daily_yield` 持久化，不能按下水次数重生。

### 7.1 单次节奏

- **计时前：入水**。圆幕、加载和可见下沉都不计有效水下时间；到swim立即可控，0.3–0.6秒中性悬停仅在无输入时播放，不额外锁操作。
- **0–30秒：辨认环境**。呼吸稳定、看清一个入口地标和一条候选路线，不铺满任务图标。
- **30–80秒：接近首个兴趣点**。目标用轮廓、散落物、鱼群运动引导；沿用宝箱11m发现/头灯锥规则，不开全图透视。
- **80–180秒：一次主活动+观察**。大部分时间用于找角度、绕障碍和看环境；单次打捞仅2.5–3.5秒、收网1.2–1.8秒，不能用长读条凑时长。
- **180–240秒：继续或返回**。主动游回浅层仍属swim并耗气；超过建议返程余量提前提示，但允许随时结束，不要求做完所有目标。
- **结束请求后：**浅层播安全出水末段；深处、出口不可达或救援走短表现+遮黑压缩返程。退出表演不计有效时间，不能让玩家锁输入等待跨越120m深沟。

## 8. 氧气与返程预算（调优候选，尚未实现）

当前 `DiveAir` 的 `MAX=100`、`BASE_RATE=0.85`、`DEPTH_RATE=0.009`、开灯 `+0.30/s` 在 30–120m 常规游动下只能支撑约几十秒，不能满足本方案的有效窗口；不能只把 HUD 倒计时拉长而保留旧消耗公式。

复审后统一为**候选A**，取代前稿0.27/s且灯额外耗气的候选。UI可沿用氧气图标，但提示称“余气”，解释为游戏化呼吸气量而非真实潜水生理模型。灯是电器，首版不再烧气，也不额外增加电池条。

```text
A_max = 100
D = clamp(depth / 120, 0, 1)
M = 1.00 (悬停/观察), 1.08 (普通游动), 1.35 (实际冲刺)
T = 0.02/s (实际打捞/收网执行中), 0 (其余)
rate = (1/3) * (1 + 0.15 * D) * M + T
lamp_cost = 0
```

深度压缩只是游戏调平；不模拟减压、氮醉或真实120m潜水规范，不作现实潜水教学。呼吸的快慢由运动负荷平滑驱动，不要求玩家按键呼吸；不增加憋气省气漏洞。

### 8.1 可复算预算（数学算例，不是引擎实测）

每段记为 `(秒数,平均深度m,M,T)`，含返程主动游动、不含冻结的出入水表演；深度是分段平均值，路径最终须从实际运动日志积分。灯可全程打开。

### 8.2 返程与补气

- 保留35%/15%双告警，同时优先判断路径余量：沿Map可达路径以正常游速积分返程耗气，另加 `max(10点,估算耗气×20%)` 安全缓冲。当前位置到水面的垂直距离不能当无障碍路线；HUD只显示近似区间与“足够／建议返回／建议救援”，不伪装精确倒计时。
- 首版**不在水下换气**，返回同Main才补足；避免贴水面无限续航。旧九图最浅约5.92m却用5m阈值、家园上界0.82m却用0.5m阈值均不可达；不通过让角色穿破胶囊上界补气来修它。地图适配仍须提供合法浅层出口，位置来自TSCN/碰撞，不写死世界坐标。
- 0%取消未提交活动并触发救援，不扣已得物品、不弹惊悚溺水画面；返回后保留现有6秒恢复冷却。正常返回无额外惩罚；过场和暂停不减冷却。
- Air模型只由共享Controller推进；WorldClock在潜水中不走，Air用运行时delta，与海面日期倍率无关。工具耗气取实际执行状态、冲刺取实际移动速度，挡墙不以按键意图持续扣冲刺气。
- 正常完整上浮是swim中的玩家选择，吃余气预算；已经请求结束后不再扣气，也不能途中重新收物品，否则产生免费探索返程。

## 9. 3A品质取向、镜头与电影化进出水

“参考 3A”在本项目中落成可验收的体验目标，而不是堆叠高成本特效：角色有重量和惯性、镜头稳定、动画与实际速度一致、入出水有明确光线/声音/泡沫节奏、交互结果可靠。优先级为 **可控性 > 读得清 > 电影感 > 特效密度**。

- **潜水镜头：**采用 SEA-CAMERA-R18 的 9.5m 候选默认距离、vFOV74°/冲刺80°、KEEP_HEIGHT 和 0.32m 双 clip；滚轮 5–16m 只改变观察距离。轻潜水镜中心55%不扭，边缘默认短边1.5%以内并可关闭；HUD、标签和圆幕不被扭曲。

- **性能：**泡沫、呼气、焦散和轻潜水镜均采用池化/质量档；远景建筑和鱼群按距离降级，不用新增大规模高模作为 3–5 分钟内容的前置条件。

## 13. 三种活动与轻量潜水模拟

### 13.1 打捞不是“靠近等读条”

先观察可拆部位、绕到无遮挡的一侧，再确认取物。候选目标默认有效半径1.8m；工具动作前速度≤0.6m/s、射线无遮挡、返程余气不足时提示而非强制拦截。普通拾取约0.8秒；解绳2.5秒、拆零件/取玻璃3.5秒；旧箱沿现开启规则，未来只替换动画/手部落点，不改奖励池。每类只做一个明确动作，不加连续QTE。

按住与点击切换两种可访问性方式共用同一命令；手动移动/取消/离开有效距离/遮挡/转场立即终止未完成令牌。进度仅当前会话有效，取消不耗材料或目标。完成时重新校验距离、LOS、epoch、配额和整份容量，不能用开始时的校验代替。

### 13.2 捕鱼：先观察，再轻靠近，最后抄网

与海面靠船收取区分：鱼群附近约6m进入观察圈，冲刺到约4m内会使可捕目标散开6–8秒；平稳游动或悬停2秒恢复靠近机会。首版不做实时逐鱼刚体AI；独立内容代理沿鱼群可达轨迹给出一个网捕体积，视觉鱼依旧由原组件绘制。

候选抄网距离1.4m、前方70°总锥角、收网1.5秒；开始和收网接触时都要有有效目标/无遮挡。快按连点不会提高命中率，不需要亚秒级反应；成功一次fish×1，失败只让鱼暂避、不扣资源。满包不耗目标、不扣日配额；配额已满可继续观察拍照但明确“今日已收获2条”，不再播放会误导成功的捕获动画。抄网、工具挂点和专用接触动作均待制作；不在没有资产时假称已有装备。

### 13.3 摄影：画面就是奖励

首发拟6个photo_id：`home_photo_entry_light`、`home_photo_ruin_window`、`home_photo_fish_school`、`home_photo_seabed_arch`、`zone1_photo_chest_context`、`zone2_photo_ruin_silhouette`。名字仅语义候选，内容制作时确认实际地标存在；不存在就选择同图可读地标并正式登记，不能生成虚构对象提示。

第一次观察登记不需完美构图：目标在画面内、无遮挡可见采样≥60%、距离处于内容配置2–25m、主体屏占比8%–60%，稳定0.4秒即给“可记录”提示。快门永远可按；不达观察条件也可保存风景照，不消耗道具。有效照片候选质量 `Q=100×(0.4V+0.3S+0.3C)`：V为可见采样比例；S是屏占比接近25%的梯形评分；C取中心/三分构图位置最佳值。首版只分“已记录/构图清晰/佳作”，不用真实摄影技术术语惩罚玩家，评分须可解释。

相册展示拍摄区域、首次游戏日期、最佳构图和可选缩略图；不发钱、不占背包格。重复同photo_id仅改善最佳，不反复发观察奖励；已获观察即使图片写失败仍保留。水下取景保持实时，暂停菜单才停耗气；防止打开相册获得无限安全探索。保存图片排除HUD/圆幕但保留环境雾、光线及玩家选择的镜片效果，照片低画质不能成为后处理门禁的旁路。

### 13.4 轻量模拟与方向感

模拟感来自中性浮力、踢蹼后滑行、阻尼转向、呼气气泡随深度/节奏变化、距离雾和顶部光线，不靠复杂惩罚。松手趋向悬停不自动沉底；呼吸起伏主要由胸肩/气泡表现，角色根和镜头不周期大幅上下抖。无随机强水流、无脱离输入的持续roll。可选弱环境流只影响粒子与软植物，首版不推走打捞中的角色。

HUD常驻只留余气、深度和简短方向提示；互动时给一个主提示。返程地标用入口光/水面亮区及可关闭方向标，失去安全路径显示“建议结束潜水”，不画一条穿墙直线。低气双通道图标+文字，避免红闪全屏或刺耳持续警报。

### 14.2 动画清单与同步

- 巡航建议1.0–1.4Hz踢蹼、蹬水后0.25–0.45秒舒展滑行；冲刺1.5–1.9Hz但不缩骨长；悬停用小幅手臂/踝部调整，不做持续推进踢腿。
- 倒游、侧移、刹停转身各有姿态；头眼先于肩髋0.08–0.15秒、混合0.15–0.25秒，输入变化不清动画相位。墙前实际速度归零停止推进腿和冲刺镜头，保留小幅呼吸/悬停动作。
- 打捞上身工具层、摄影持机层、抄网前伸/收回层与下身悬停分开；IK只在可达目标内使用，手臂不过伸、不把身体吸到目标上。蹼、相机、抄网是待制装备/挂点，须另按既有资产分账本登记后使用。
- 入水姿态、出水抬头、海面呼吸恢复与游泳共用原骨架和独立潜水Character；表现不驱动物理根位置、不直接扣Air或发奖励。五体型均验证工具穿身和脚蹼穿地。

### 14.3 镜片与电影段

中心55%指按画面半短边归一化的径向区域；边缘平滑增加桶形位移，默认≤短边1.5%、最大3%。投影标签锚点随世界正向映射，文字本身保持清晰；点击反解回未扭曲相机射线，镜片关闭必须严格等价。舒适档关闭畸变/heave/冲刺FOV和镜头震动，不关闭必要的目标可读性。

入水保留既有真实黑帧和可见下沉。新候选曲线从7.8m/vFOV78°连续过渡到用户距离/74°；若用户滚轮已有值必须以其为终点，不能硬跳9.5m。向上俯仰偏移和heave默认减半至0.04m级，不强行旋转用户朝向；黑幕揭开后角色、气泡、相机运动顺序有可见起点。

出水顺序必须显式改原冻结释放点，不能仅调用已有 `dive_exit_tick()` 后声称有电影感：

1. Session接受结束→令牌失效/取消活动→switching+frozen，存读、奖励、Air、玩家输入仍锁；保留当前视角。
2. 给同一Controller本次exit专用表现许可（不是解除全局冻结）；Map提供碰撞合法末段，沿 `dive_move` 运动并用实际位移更新动画/双clip相机。
3. 有浅层末段：1.2–1.8秒上浮、气泡向后、光区扩展；无末段/深处/救援：原位短抬头后遮黑，不直接lerp深层Y到水面。玩家可跳表演，底层事务不可跳。
4. cover→确认全黑post-draw→卸载水下Runtime→恢复同Main/原船/人物/相机/环境→uncover→解除busy。海面0.6–0.9秒呼吸/衣物水滴仅表现实例层，不改恢复的业务姿态；已可控时玩家输入优先。
5. 失败/重复请求走既有回滚；阻塞超时不得一直黑屏。离水声按低通退去→吸气→海面环境交接，缺音效时静音降级，不能加载不存在资源导致返回失败。

## 15. 事务、照片异步与存档落点

`active`是潜水会话存在，不是活动busy；稳定swim必须可以领奖。只允许一次活动token，包含session代次、target_id、epoch和action序号，取消/切换使其失效。提交前再次验证整份容量、可达性和额度。Inventory只负责物品，DiveSession只负责耗尽/配额/观察；当前库存内部原子不代表两者原子，需要现事务扩展延后信号与补偿回滚。不能先广播背包成功再发现额度提交失败。

root v4不变，可选 `dive.expedition` version1。仅缺整个模块才按旧档迁移为空；模块存在却缺consumed/daily_yield等必填字段必须拒绝，避免坏档刷资源。未知字符串内容ID和原未知整数宝箱ID保留。资源晨次不能来自壁钟，不能读取未来晨次。序列化不存当前Air、动作、位置或图片二进制；照片引用只允许受控相对路径。

异步照片采用session代次+photo_id+记录修订号回调，不能对已卸载Map写节点。观察先提交内存，图片成功且仍匹配记录才挂引用；失败/取消保留观察，临时图片未被引用不等于保存成功。返回全busy解除后最多请求一次既有SaveGame.write；图片较晚到达只挂内存待下次普通保存，不为每张照片额外强写。图片和JSON跨文件不承诺原子：缺图展示观察占位，无权限/磁盘满明确“图片未保存”。平台不支持受控本地图片时降级观察记录，不能把Web下载成功等同存档引用可恢复。
