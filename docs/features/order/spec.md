# SEA-ORDER · 交易与订单

[主文档中控](../../../GDD_V1.0.md#sea-order) · [本功能账本](ledger.md)

设计修订：r1（2026-10-23 工程拆分，未更改玩法数值）。所属系统：经营。
范围来源：主文档保留的全局设计、拆分前文档与当前代码核对；下面明确区分目标与实现边界。

## 功能目的与边界

正式或规划入口：码头订单板打开，交付或免费换单。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-ORDER-R01 | 当前最小版本采用商店买种与出货箱次晨销售；三张长期订单仅保留为锁定的后续功能，开发档可回归。 |
| SEA-ORDER-R02 | 只扣背包货物，先模拟扣货后奖励容量，容量不足不扣货、不消耗订单。 |
| SEA-ORDER-R03 | 成功订单不可重复领取；档位通过进度查询端口获得，存档保留补位剩余时间。 |
| SEA-ORDER-R04 | 旧文档的到期换单设计保留历史身份，2026-10-22 经营循环说明为当前实现依据。 |
| SEA-ORDER-R05 | 订单节点和面板不访问全局 Economy；支付、奖励和库存检查通过公开端口完成。 |
| SEA-ORDER-R06 | 面板和订单牌通过 offers/offer_at 查询副本；不得取得内部槽位和奖励字典的写引用。 |
| SEA-ORDER-R07 | DailyShipping独立拥有48格出货箱、最后结算晨次与收据；鱼/蔬菜/番茄/南瓜可放入或取回，07:00按ItemDB售价清货入账，重复通知及读档不得重复销售。 |
| SEA-ORDER-R08 | 商店调用 Farm.buy_seed；背包不足或瓶盖不足不扣钱。保管仓库与出货箱相互独立，玩家显式取出后出货。 |

| SEA-ORDER-R09 | 太阳房现有白盖蓝箱固定移至码头左侧，实体点击打开出货箱；收货员每天07:00按登记售价自动清货并支付瓶盖，无需即时出售。结算前可取回，保管仓库不参与。 |

## 所有者、接口与数据

状态/交付所有者：**OrderBoard / 注入式交易展示**。正式代码和资源入口：

- [godot/src/orders](../../../godot/src/orders)
- [godot/assets/data/orders.json](../../../godot/assets/data/orders.json)
- [godot/assets/data/trade_board.json](../../../godot/assets/data/trade_board.json)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。

## 当前实现与待完成边界

订单规则保持纯端口注入；TradeBoard 注入 Orders，OrderPanel 注入 Inventory。额外交易品类和商人实体尚未扩展。

2026-10-27 接口：configure / fulfill / reroll / tick / to_dict / from_dict；changed、fulfilled；orders.slots 保留订单和补位剩余时间。

详细所有权、状态转换与扩展方法见 [模块接口约定](../../architecture/module_contracts.md)；实测范围见 [框架交付记录](../../development/2026-10-27_modular_framework.md)。原目标中尚未实现的内容保持登记，不因架构拆分自动升级完成度。
