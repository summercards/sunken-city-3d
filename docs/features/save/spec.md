# SEA-SAVE · 存档与恢复

[主文档中控](../../../GDD_V1.0.md#sea-save) · [本功能账本](ledger.md)

设计修订：r1（2026-10-23 工程拆分，未更改玩法数值）。所属系统：基础。
范围来源：主文档保留的全局设计、拆分前文档与当前代码核对；下面明确区分目标与实现边界。

## 功能目的与边界

正式或规划入口：F5、F9、自动存档及启动读档。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-SAVE-R01 | 写入采用临时文件校验后替换；新版本档拒绝，旧档按版本迁移。 |
| SEA-SAVE-R02 | 冷却保存相对剩余时间；模块恢复应全量复位，未知内容 ID 容错。 |
| SEA-SAVE-R03 | 潜水或收线中拒绝不完整快照；测试在 Autoload 前隔离存档目录。 |
| SEA-SAVE-R04 | 恢复不能长期依赖 UI 或主场景的私有字段，应通过各功能恢复接口交接。 |

## 所有者、接口与数据

状态/交付所有者：**SaveGame 协调 / 各功能状态所有者**。正式代码和资源入口：

- [godot/src/save](../../../godot/src/save)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。

## 当前实现与待完成边界

当前 SaveGame 仍访问 Main/HUD 内部状态；该条明确为待解耦，现有格式不变。

现有规则继续运行；独立文档、账本和目录归位不代表所有行为已经独立测试，也不代表全部原始目标已实现。阶段事实以本功能账本为准。

## 验收入口

通过主文档定位本功能后执行账本列出的检查。正常、拒绝、取消/重复、存档恢复均按适用范围记录；真实渲染、听验和设备项单列。本次使用统一 runner 的隔离存档项目，不能直接拿玩家存档做测试。
