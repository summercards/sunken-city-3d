## 功能目的与边界

正式或规划入口：点击海面漂流物或鱼群，驶近后收取。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-PICKUP-R01 | 目标先展示名称和产出，再通过合法航路接近，不隔岛远程拾取。 |
| SEA-PICKUP-R02 | 完成收取后进入对应冷却或移除，重复点击不能重复结算。 |
| SEA-PICKUP-R03 | 收取反馈与库存变化一致，航行取消时旧目标不再执行。 |
| SEA-PICKUP-R04 | 鱼群外观直接采用网页版 `web/fish-schools.js` 的模型与游动：扁胖椭球身体、三角尾鳍、深色眼珠，每条鱼绕自家小轨道做椭圆巡游、朝向取切线、尾鳍按 9 rad/s 摆动。**整条鱼沉在浪面之下**（按最高点算沉深 0.25–0.90 m，随同一套波浪采样取高度），不再浮在水面上；鱼沉下去之后点击锚点同步下移到鱼身。单群 3–6 条，个体按黄金角铺开、各有地盘，不允许共心排成一圈。配色取网页版薄荷青系（同色相提纯，不得落入土黄/橄榄的脏色）。以网页版已烘焙位置为首批参考，仅在可航行且距可行走地面至少 2.6 米的水域刷新。鱼群涟漪为**单圈开环 + 一道**动态外扩脉冲弧线，透明度不高于 0.35 且圈色不得为近白高亮（不得压过鱼本身），随真实水波起伏。 |
| SEA-PICKUP-R05 | 被收取目标不允许重复结算；存档保留实体、随机流及相对计时，恢复清空旧计时与目标，不遗留 SceneTree 定时回调。 |
| SEA-PICKUP-R06 | 快照实体ID唯一，next_id大于已有ID，随机流字符串可无错误解析；旧版缺失用显式reset命令迁移，当前空记录拒绝。 |
| SEA-PICKUP-R07 | 最小版本4个本地鱼群，不生成漂流材料；注入spawn_area和can_receive。满包时不移除鱼群、不奖励；读档将范围外鱼群迁回本地并保留已收取的补货计时。 |

## 2026-10-29 拾取流程：停下才打捞

一次海上拾取分三个阶段，**这是玩法状态机，不是表现层的修饰**：

| 阶段 | 条件 | 结果 |
|---|---|---|
| IDLE 空闲 | 没有拾取 | — |
| SAILING 航行 | 点击浮木/鱼群后，船正朝它划过去 | **没有任何进度**。赶路不是打捞。 |
| GATHERING 打捞 | 船**已停稳**（`starts_sailing() == false`）且目标在打捞范围内 | 进度条从 0 出现，计时走满才结算 |

| 条款 ID | 规则 |
|---|---|
| SEA-PICKUP-R09 | 拾取是「停下来做的动作」，顺序固定为**停船 → 开始打捞 → 计时 → 结算**。航行阶段无论还剩多远都**不得出现任何进度**（`PICK_REVEAL_SECONDS` 那种"按剩余航程折算进度"的写法已废弃：它让船还在划、人还没碰到东西时条就在走）。停稳后先校验目标是否真的在范围内（浮木 2.2 米 / 鱼群 `FISH_PICKUP_RADIUS` 3.2 米）：够得着才进入打捞，够不着（例如半路被岸线挡住）直接作废待拾取，不允许在原地对空气打捞。打捞时长 `PICK_GATHER_CRATE = 1.2` 秒 / `PICK_GATHER_FISH = 1.6` 秒，进度条在此期间按时间从 0 走到 1；**走满那一刻才真正结算**（`collect_crate` / `collect_fish`），打捞途中不进账。结算成功条停满格 0.5 秒再收；背包满等失败情况立即收条，不闪假满格。取消、改道、靠岸、读档、入睡等取消路径立即清阶段并收条。没有点击、船自己停在浮木旁时走同一条路径（停稳 → 打捞），不再瞬收。 |
| SEA-PICKUP-R10 | 拾取进度条挂在**角色头顶**（`ANCHOR_LIFT = 1.35` 米 + `SCREEN_GAP = 16` px 屏幕偏移），76×6 px，与建造条共用 `res://src/ui/thin_progress_bar.gd`。挂点必须是角色而不是目标：镜头跟着角色走，目标很容易偏出取景框，挂在目标上的条会随之整条消失。 |

R09 新增了 1.2 / 1.6 秒的打捞时长（原先是到站瞬收）。这是本轮唯一的玩法数值改动，只影响「停下之后捞多久」，不改航速、奖励数量、补货计时与存档结构。
