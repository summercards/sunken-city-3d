## 功能目的与边界

正式或规划入口：主场景 World/Zones。

本功能以这一玩家行为或工程交付闭环为管理粒度，内部操作作为设计条款逐项承接；不按脚本数量拆功能。跨功能前置和关系由主文档本行统一维护。

## 设计条款与验收标准

| 条款 ID | 目标规则 / 应验证的行为 |
|---|---|
| SEA-WORLD-R01 | 五个海面区块各有独立 TSCN，稳定 zone ID 关联布局、可行走区域和上岸点。 |
| SEA-WORLD-R02 | 跨区块复用的组件与区块专属实例分开管理，正式场景可以手工编辑。 |
| SEA-WORLD-R03 | 正式场景更新不得由旧烘焙脚本静默覆盖；初始化或候选生成有独立出口。 |
| SEA-WORLD-R04 | 已由动态功能接管的历史烘焙对象，使用场景内显式几何排除清单退役；不得重生成覆盖整份正式场景或让旧对象重复参与岸线。 |
| SEA-WORLD-R05 | 水面阻挡归属组件：每个区块组件自带 BlockerSet，由自身可见几何派生（只取水线到船高这一段的三角形），替换/移动模型即同步替换阻挡。禁止用一份与场景脱钩的离线岸线表充当正式阻挡，也禁止用隐藏单元或临时排除清单绕开空阻挡。远景水街区（只有烘焙几何、没有组件场景）单独登记在 `assets/baked/shore_environment.json`。 |
| SEA-WORLD-R06 | 区域资格经 far_sea_query 注入；导航障碍形状由装配接口提供，区域服务不访问全局 GameState。 |

## 所有者、接口与数据

状态/交付所有者：**Zones / ZoneScene**。正式代码和资源入口：

- [godot/src/world](../../../godot/src/world)
- [godot/scenes/zones](../../../godot/scenes/zones)

读取上述所有者的公开查询，修改通过其命令或交互入口；事件由拥有该状态的对象发出。具体公开方法、信号和持久化字段见本账本的接口清单。原有稳定 ContentID、场景 ID 和存档键保持不变，重命名须另做迁移。

共享资源的所有权以被依赖功能为准。本功能引用它们，不复制背包数值、资产记录或其他功能规则。规划中的接口尚无实现时必须先补契约再编码。
