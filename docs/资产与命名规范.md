# 资产与命名规范

> 适用工程：`sea/godot`（sea Godot 移植版）
> 版本：v1.7 · 2026-10-19（主场景可编辑化 + 滤镜面板 / 环境与水面资源文件）
> 本文是**强制规范**。改资产结构、加区块、加植物之前先读这一页。

---

## 1. 总原则

1. **场景负责装配，代码只负责接线。** 世界内容写在 `.tscn` 里，`main.gd` 不 new 几何。
2. **一个区块 = 一个场景文件。** 区块内的一切（静态几何、可行动区域、植物、上岸点）都归它自己的 tscn。
3. **能烘焙的不要手写。** 建筑几何来自网页版烘焙，保证 1:1；坐标来自 `zones.json`，不在代码里写死。
4. **资产按「谁拥有」分层。** 跨区块复用的放 `common/`，绑死区块的放 `zones/<zone>/`。
5. **命名用 ASCII。** 文件夹、文件名、节点名一律小写蛇形或大驼峰；中文只用于 `zone_label` 这类展示字段。

## 3. 命名规范

### 3.1 区块

| 层级 | 规则 | 示例 |
| --- | --- | --- |
| 逻辑 id | `zone<N>`，与 `zones.json` 一致 | `zone1` |
| 文件夹 / 文件名 | `<id>_<英文短名>`，小写蛇形 | `zone1_home_harbor` |
| 场景节点名 | `<Id><EnglishName>`，大驼峰 | `Zone1HomeHarbor` |
| 中文名 | 只进 `zone_label` 字段，不进文件名 | `sea` |

现行对照表（改这里必须同步 `tools/naming.py` 与本文）：

| id | 文件夹 / 文件名 | 场景节点 | 中文名 |
| --- | --- | --- | --- |
| zone1 | `zone1_home_harbor` | `Zone1HomeHarbor` | sea |
| zone2 | `zone2_yokohama_station` | `Zone2YokohamaStation` | 横滨铁道 |
| zone3 | `zone3_arc_farm` | `Zone3ArcFarm` | 圆弧农场 |
| zone4 | `zone4_far_shore` | `Zone4FarShore` | 远海街町 |
| zone5 | `zone5_aqua_platform` | `Zone5AquaPlatform` | 浅水养殖台 |

### 3.2 区块场景内部节点（固定五块，名字不可改）

```
<ZoneNode>                  zone_scene.gd，字段 zone_id / zone_label / geometry_source
├─ StaticBatch              zone_batch.gd，字段 bake_dir（实例批次，回退路径）
│  └─ BatchNNN              MultiMeshInstance3D（由脚本生成）
├─ Models                   建筑几何（tscn 里的真实 glb 实例，可直接编辑）
│  └─ <unit_id>             实例根（glb：root/<mesh>）
│     └─ surface_material_override/N  共享材质 assets/materials/models/*.tres
├─ WalkAreas                Node3D（纯容器）
│  └─ Walk_<area_id>        walk_area.gd
├─ Plants                   plant_field.gd，字段 zone_id / placement_path
└─ Landings                 （预留）上岸点，当前由 main 的 LandingMarkers 统一绘制
```

`geometry_source` 决定静态几何走哪条路，两条路的画面必须一致：

| 值 | 几何来源 | 用途 |
| --- | --- | --- |
| `scene` | `Models` 下的 glb 实例节点 | 默认。编辑器里可选中/移动/替换 |
| `baked` | `assets/zones/<zone>/instances.bin` | 回退。字面量高保真，但不可编辑 |

切换只重建被选中的那条，另一条在 `_enter_tree` 里被关掉，不会双份几何。
临时对比：`Godot --path godot -- --source=baked`。

`Models` 段由 `tools/build_zone_scenes.gd` 生成（区间 `; >>> models` / `; <<< models` 之间会被整体覆盖）：
它读 `manifest.json`，把每个 unit 的 glb 作为实例节点写进 tscn，并按 `slots` 给每张面挂
`assets/materials/models/baked_t*.tres`（与 `BakeStore.material()` 参数逐项相同）。
改了资产后跑一次 `build_zones.py` → `build_zone_scenes.gd` → `verify_zone_scenes.gd`。

`Walk_<area_id>` 的 `area_id` 必须等于 `zones.json` 里 `walk[].id`。

### 3.2.1 编辑器里能看到什么（@tool 约定）

打开 `main.tscn` 时，下面这些也会在编辑器里出现，不按 F5 就能摆位：

| 内容 | 谁生成 | 说明 |
| --- | --- | --- |
| 建筑 `Models/*` | tscn 实体节点 | 本来就在场景里，可直接选中 |
| 外围环境 249k 实例 | `zone_batch.gd`（@tool） | `World/Environment` 的 StaticBatch，一次性 build |
| 植物 205 株 | `plant_field.gd` + `plant.gd`（@tool） | 按**建成态**（满级）摆放，不跑生长/摆动 |
| 采集点 / 施工牌 / 菜箱 | `gather_field` / `build_field` / `farm_field`（@tool） | 只摆造型，不读玩法状态 |

这些 @tool 节点用 `add_child` 生成、**不设 owner**，所以保存场景时不会写进 tscn，
运行时仍由原逻辑生成，两份不会打架。

坑：编辑器里 autoload 是 **占位实例**（脚本不是 @tool 就不执行），调它的方法会报
`Attempt to call a method on a placeholder instance`。所以 `build_site.gd` / `farm_plot.gd`
在编辑器分支里只建几何，`Economy` 相关的刷新全部跳过。

打开场景后视口相机停在原点很常见：在 3D 视口里按 **F**（框选全部），或选中 `Camera`
再点菜单「视图 → 对齐视图到相机」，就能得到和游戏一致的构图。画面偏灰/没光时，
打开视口右上角的「预览太阳与环境」。

### 3.3 可行动区域字段

| 字段 | 含义 |
| --- | --- |

## 4. 坐标约定

1. **区块内坐标相对区块原点**：`local = (world.x - origin.x, world.y, world.z - origin.z)`。
   **y 永远是绝对高度**，不减 `origin.y`（对齐网页版 `zones.js`）。
2. 区块节点自身的 `transform` 就是 `(origin.x, 0, origin.z)`；搬区块只改这一个数。
3. `zones.json` 里 `walk[].rects`、`landings`、`boatPark` 都是**世界坐标**；
   写进区块场景时由 `build_zones.py` 自动转成相对坐标。
4. 环境（`assets/world/environment`）保持世界坐标，因为它不属于任何区块。
5. 水面高度 `WATER_LEVEL = 1.12`，只允许在 `bake_store.gd` / `main.gd` / 着色器默认值里出现。
6. **三角形绕序原样写，不要翻**。glTF 与 Godot 的正面约定一致（都是逆时针），
   Godot 的 glTF 导入器会自己转成内部的顺时针约定，导出时 `add_indices(idx)` 传默认参数即可。
   `tools/winding_probe.gd` 用两块已知绕序的四边面实测过：翻过来只会让所有墙面变成背面，
   单面材质下整栋楼只剩内部可见（=「建筑碎了」）。
   真正要管的是**单面 / 双面**：manifest 每个材质槽的 `double_side` 决定用哪个着色器变体
   （`uw_materials.gd`），双面会把内壳外壳同时画出来抢深度 —— 那才是「一直在闪」的来源。
   海底有 `--selftest` 的绕序断言兜底（注意方向：运行时 `(b-a)×(c-a)` 与顶点法线**反向**
   才对，因为导入器翻过了）。

### 5.2 三条硬规则

1. **烘焙必须取「建成态」**：`living-harbor.js` 的爬藤/花丛/屋顶花园按建造等级控制 `visible`，
   导出前要把 `buildSites[].level` 拉满，否则绿植全丢。
2. **植物要先抽、区块后切**：`build_plants.py` 产出 `plant_claim.json`，
   `build_zones.py` 据此把叶片从静态几何里排除，避免画两遍。
3. **不要手工改 `assets/` 下的二进制与 JSON**，下一次构建会被覆盖；要改就改 `tools/` 再重跑。
   唯一例外是 `assets/models/zones/<zone>/units.json`（单元划分表），它本来就是给人改的。

### 5.3 模型层：反向烘焙成 glb

网页版是运行时程序化建场景，没有可编辑的模型文件；烘焙只留下「几何原型 + 实例矩阵」。
`tools/build_models.py` 把实例矩阵**烘进顶点**，再按语义单元切成独立 glb，供 DCC 直接打开。

```
assets/baked/                     几何原型 + 实例矩阵
   │  tools/build_models.py
   ▼
assets/models/zones/<zone_key>/
   ├─ <zone_key>.glb              整区总装（所有实例合并，按材质分 primitive）
   ├─ units/<unit_id>.glb         语义单元（单栋建筑 / 构件 / 零散件）
   ├─ manifest.json               单元清单：摆放、包围盒、材质槽、顶点数、实例数
   └─ units.json                  划分表（锚点 + 半径），可手改后重跑
```

**拆分规则**（`build_models.py` 顶部常量）：

| 概念 | 规则 |
| --- | --- |
| 种子 | 水平尺寸 ≥ `SEED_MIN_FOOTPRINT`(2.8m) 且高 ≥ `SEED_MIN_HEIGHT`(1.2m) 的实例，按体积降序、间距 ≥ `SEED_GAP`(4m) 取点 |
| 归属 | 每个实例归到**最近种子**；水平距离 ≤ `UNIT_RADIUS`(7m) 入该单元 |
| 零散件 | 不落在任何种子半径内 → 合并成一个 `detail` 单元（超过 `DETAIL_MAX_VERTS` 才按 12m 网格再切） |
| 无种子区块 | 全区一个 `unit_01`（例如浅水养殖台） |

自动划分只是初稿。要按建筑设计意图重划，直接改 `units.json`（删掉某个 anchor 就会并回 `detail`），
再跑一次脚本；`manifest.json` 会跟着更新，场景不用改。

**坐标与枢轴（替换时必须遵守）**：

- `Y-up`、单位米、与 Godot / 网页版一致，**不做轴转换**。
- 单元枢轴 = **单元 AABB 水平中心 + 世界 y=0**（水面基准），不是包围盒底部。
  用水下基座做底部会把枢轴压到 -30m，DCC 里没法编辑。
- 顶点色 `COLOR_0` 存的是 Three.js 的 `material.color`（线性空间），GIMP/Blender 里显示会偏暗，正常。
- 每个 primitive 对应一个材质槽；`manifest.slots` 的顺序与 glb primitive 顺序严格一致。

**`manifest.json` 字段**：

| 字段 | 含义 |
| --- | --- |
| `name` | 区块 key，与文件名一致 |
| `origin` | 整区总装枢轴（世界坐标） |
| `bounds` | `min/max/size`，世界坐标 |
| `instance_count` | 该组包含的烘焙实例数（= 各单元之和） |
| `whole` | 整区 glb 的体量统计 |
| `units[].id / file / label` | 单元 id、相对路径、可读名（最近地标 + 距离） |
| `units[].origin / bounds` | 摆放位置与包围盒 |
| `units[].slots[]` | `tex / tint / unlit / alpha / double_side / instances / vertices / triangles` |

**替换流程**：

1. Blender 打开 `assets/models/zones/<zone>/units/<unit>.glb`，改模型（枢轴别动）。
2. 导出覆盖同一个文件（glTF Binary，Y-up，米）。
3. `Godot --headless --editor --quit --path .` 重建导入缓存。
4. `./verify.sh` —— 画面与自检都要过。

只换一个单元时，其余单元不受影响；`manifest.json` 里的顶点数/包围盒会与 glb 不符，
自检会报 `顶点数与清单一致` 失败——这时重跑 `build_models.py` 会覆盖你的模型，
所以**改完模型要手改 manifest 的对应字段，或把该单元从自动构建里排除**。
需要长期迭代的单元，建议在 `units.json` 里固定 id 后把 glb 纳入版本库并停止重跑脚本。

**注意**：`build_models.py` 是全量重建，会覆盖 `units/` 下同名 glb。
在 glb 上做的手工修改要么换文件名、要么先备份。

**外围环境不纳入模型层**：`environment` 有 900 万顶点（整块 400MB+），
它是背景而非可替换区域，继续走 `StaticBatch`。需要时用 `--env` 临时导出分块（约 420MB），
默认不生成、不入库。

### 5.4 海底世界：四个独立区块

海底是**一张独立地图**（不是把相机压到水面下）。为了好维护，它不写成一个大场景，
而是按内容拆成四块，每块一个 `tscn` + 一套 glb 资产，可以单独关掉、单独替换：

| region | 中文名 | 内容 | 单元 | 整区 |
| --- | --- | --- | --- | --- |
| `basin` | 礁盆与台地 | 连续岩盆、岩层、沙堆、8 座珊瑚台地 | 2 | 3.2 MB |
| `neighborhood` | 沉没街区 | 12 栋民宅、断桥、8 盏路灯、4 台车 | 15 | 6.3 MB |
| `reef` | 珊瑚礁与海草 | 246 丛珊瑚、55 株海草 | 10 | 29 MB |
| `trench` | 北境海沟 | 海床、断崖、阶梯、32m 海盗船、巨型珊瑚 | 3 | 12.5 MB |

```
scenes/underwater/
├─ underwater_world.tscn        UnderwaterWorld
│  ├─ Regions                  UnderwaterBasin / …Neighborhood / …Reef / …Trench
│  ├─ Deco                     uw_deco.gd（鱼群/气泡/光柱/微粒/水膜/灯光）
│  ├─ Chests                   5 个宝箱（运行时生成）
│  └─ DiveCamera               fov 55 / near 0.12 / far 420
└─ region_<region>.tscn        region 字段 + manifest_path
```

**坐标**：与海面同一世界坐标系，但两边互斥显示。海底区块场景的节点 transform 是 identity，
单元按 `manifest.origin` 摆位（枢轴 = 单元 AABB 中心，三轴都取中心 —— 海沟里的东西不适合用 y=0）。
区块内不做二次偏移。

**烘焙与拆分**（`tools/export_underwater.cjs` → `tools/build_underwater.py`）：

1. 导出时**先关掉网页版的自动合批**（把 `underwater-art.js` 里的
   `batch(root);swaying.forEach(...)` 替换成注释）。合批会把同几何同材质的网格跨区块
   合并成一个 InstancedMesh 挂到 root 上，"这属于哪栋楼 / 哪片珊瑚"的信息就丢了，
   没法再按区块切。关掉之后按「最近的具名祖先」判区块、按组名判单元。
2. 珊瑚和海草的组名不带序号（都叫 `reef-coral` / `ribbon-kelp`），按**遇到顺序**每 32 丛 / 28 株
   分一个桶；生成是确定性的，桶号可复现。
3. 批次键 = `几何 + 材质 + region + unit`，Python 侧按 unit 合并成世界坐标网格直接写 glb。
4. 平面着色（`flatShading`）在烘成静态网格时必须**自己拆三角形算法线** ——
   three 是渲染期用导数算面法线，顶点法线本身是平滑的。

**动态内容不进 glb**：鱼群、气泡、光柱、浮游微粒、水面顶盖、宝箱、以及所有灯光，
都由 `uw_deco.gd` / `underwater_world.gd` 运行时重建（位置与参数对齐网页版）。
`swim.json` 提供碰撞盒（43 个）、台地（8 个）、宝箱（5 个）、鱼群（7 群）、海沟剖面（9 段）。

**材质**：`uw_materials.gd` 按槽位去重，`underwater.gdshader` 做焦散网纹 + 自发光 + 深度衰减。
水雾不是 Environment 雾，而是**屏幕空间上下渐变 + 视深度**（和网页版一样），
因为 Godot 的环境雾只有单一颜色，做不出"上亮下暗"的水柱。两个坑：

- 水雾色 / 天空色是网页版**色调映射之后**的 sRGB 值，必须先转线性再混，否则整屏发白。
- `albedo_color` / `emissive_color` **不能加 `source_color`**：manifest 里的颜色已经是线性值
  （three 的 `material.color`），再加一次 sRGB→线性会把奶油色帆布压成墨绿。

**调试**：

```sh
Godot --path . -- --dive                            # 直接潜到入口
Godot --path . -- --dive --uwat=-2,-200,-120        # 潜到海沟（x,y,z）
Godot --path . -- --dive --uwat=-14,-6,20           # 潜到民宅前
```

**坑**：海底世界整棵树常驻在场景里，**不当潜水时 `visible` 必须为 false**。
它自带平行光和点光，忘了关会让海面白天整体过曝（实测亮度从 121 涨到 174）。

## 6. 植物体系

### 6.1 两级划分

| 级别 | 位置 | 归属 | 用途 |
| --- | --- | --- | --- |
| 通用植物 | `scenes/plants/common/` | 无 | 跨区块复用。同一原型被 ≥2 个区块引用时自动归入这一类 |
| 区块专用植物 | `scenes/plants/zones/<zone_key>/` | 绑死该区块 | 只在该区块出现，带该区块专属的摆动参数与效果 |

构建脚本的判定很简单：**原型的挂载点出现在两个及以上区块 → 通用；只出现在一个区块 → 专用。**
新增内容时不要手工改变归属，改摆放表或重跑构建。

### 6.2 生长

- 生长 = 整株 `scale` 从 0 到 1，和网页版 `layer` 的 `g.scale.setScalar(a)` 一致。
- 触发源是建造等级：`plant_field.set_zone_level(level)`，
  `growth = 0.22 + 0.78 * level / max_level`。
- 每株有错峰起点（摆放表 `g` 字段，0.10~0.38），落地后依次"长出来"。

### 6.3 动画

| 动画 | 实现 | 参数来源 |
| --- | --- | --- |
| 叶片摆动 | `plant.gd::_process` 对 `rotation.z/x` 做正弦 | `sway_amplitude` × `wind_strength` |
| 区块风力 | 专有植物场景里的 `wind_strength` | sea 0.9 / 铁道 0.7 / 农场 1.5 / 远海 1.2 / 养殖 0.5 |
| 生长缓动 | `plant.gd` 每帧向目标插值，窗口 0.38s | 固定 |

### 6.4 效果

区域效果由**该区块的专用植物登记**，每区块只挂一个发射器（`plant_effect.gd`），
所以几百株植物也只有一份粒子开销。

| 区块 | effect | 表现 |
| --- | --- | --- |
| zone1 | `petals` | 花瓣飘落 |
| zone2 | `pollen` | 花粉尘埃 |
| zone3 | `wind` | 强风（只加强摆动，不发射粒子） |
| zone4 | `sea_breeze` | 海风细沫 |
| zone5 | `ripple` | 水面气泡 |

### 6.5 让通用植物「互用」

任意区块的 `Plants` 节点都可以在运行时种一株通用植物：

```gdscript
# zone.plants 是 plant_field 实例
zone.plants.spawn("plant_03_7l", "common", Vector3(2.0, 2.15, -1.0))
```

专用植物只能从自己的区块场景里引用（`spawn(..., "zones/zone1_home_harbor", ...)`），
这样"绑死区块"就体现在路径上，而不是靠约定。

`scenes/main.tscn` 只允许包含：

```

└─ World
   ├─ Environment         instance scenes/world/environment.tscn
```

（它们是会动的单例，放场景里反而难管）。**新的静态内容一律进区块场景或环境场景。**

`--selftest` 里除玩法外还检查：区块五件套齐全、几何来源只启用一条、每个模型的

出现 FAIL 等同于构建失败。

模型路径与烘焙路径的画面比对：同分辨率各截一张，
`mean abs diff` 应在 0.03 左右、>80% 像素几乎一致（差值集中在植被摆动与抗锯齿边缘）。
