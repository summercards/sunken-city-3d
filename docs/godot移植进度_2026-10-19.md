## 这一轮踩到的坑（都已在代码里注释）

1. **水面以上被刷成纯白**：手绘材质里 `depth = max(0, water - y)`，出水物体
   depth 恒为 0，正好命中"贴水线泡沫"分支。原 JS 版整段包在
   `if (y < uWaterLevel)` 里。必须保留这个判断。
2. **Godot 4.7 把 `var x := <Variant>` 当错误**（`inference_on_variant` 警告升级为
   error）。从 Dictionary 取出来的值要么显式标 `: float/: Vector2`，要么用 `=`。
3. **`--script` 模式下 `class_name` 解析不到**（没有编辑器生成的全局类缓存）。
   测试与场景脚本一律 `preload` 具体路径。
4. **射线拾取分三层**：上岸桩 → 采集图标 → 海面物件 → 地面/水面。
   顺序错了会出现"点图标变成走过去"。
5. **船壳推出每轮只处理最深的一处**，单步 ≤0.45m、≤12 轮；按每排各推一次
   会把同一个长平台推几十遍，一帧把船弹飞（原工程已踩过，照搬结论）。
6. **停泊位贴着平台边缘**，所以"航迹不穿建筑"的断言必须跳过首尾 2.6m，
   这一小段交给运行时推出兜住。

实例分布：environment 249,136 / zone1 1,434 / zone3 1,224 / zone2 211 / zone5 52 / zone4 40。

### 植物两级库

- 抽取：叶片几何 `{1020,1024,111}` → 以「种子叶」1.15m 半径聚类（**不做链式传递**，
  否则整面墙的藤会连成一株）→ 少于 3 片叶子或跨度 >2.6m 的碎株留给静态几何。
- 212 株候选 → 205 株成形，985 片叶接管。
- 原型 42 个，其中 6 个跨区块复用 → `common/`，36 个只出现在单区块 → `zones/<zone>/`。
- 生长 = 整株 scale（与网页版 `g.scale.setScalar(a)` 一致），错峰起点来自摆放表 `g`。
- 摆动 = `rotation.z/x` 正弦，专有植物自带 `wind_strength`。
- 效果 = 每区块一个发射器（花瓣/花粉/海风/气泡），由该区块的专用植物登记。

### 踩到的坑

1. **实例矩阵按列存**：`bx3, ox, by3, oy, bz3, oz`。按「3x3 基 + 原点」切会把原点当基向量，
   整批植物飞出画面（第一版就飞了）。
2. **MultiMesh 的 `buffer` 存不进 `.res`**（保存回来 `buffer_size=0`）。所以几何靠共享的
   `geoms.bin`，区块只存自己的 `instances.bin`，运行时建 MultiMesh。
3. **`zones.json` 里的 rects 已经是世界坐标**（导出时展开过一次），再减 origin 会算错区块归属。
4. **macOS 大小写不敏感**：`rm scenes/Main.tscn` 会把 `scenes/main.tscn` 一起删掉。
5. 页面上的悬空白色描边是烘焙进来的水线 `lines`，不是新问题（原始网页版也有）。

## 19:30 模型层：反向烘焙成 glb 资产

目标：每个区块的建筑与场景内容都能在 DCC 里单独替换，不再依赖运行时实例矩阵。

### 做法

`tools/build_models.py` 把烘焙的「几何原型 + 实例矩阵」反推成标准 glTF 2.0：
实例变换**烘进顶点**（法线按 `(M⁻¹)ᵀ`），再按语义单元切开，枢轴落到「单元水平中心 + 世界 y=0」。

拆分是确定性的，不靠连通聚类（试过，墙面/甲板会把整岛连成一坨）：

| 概念 | 规则 |
| --- | --- |
| 种子 | 水平 ≥2.8m 且高 ≥1.2m 的实例，按体积降序、间距 ≥4m 取点 |
| 归属 | 归到最近种子，水平距离 ≤7m 入该单元 |
| 零散件 | 合并为一个 `detail` 单元（>18 万顶点才按 12m 网格再切） |
| 无种子 | 整区一个 `unit_01` |

产出（`assets/models/zones/<zone>/`）：整区 glb + `units/*.glb` + `manifest.json` + `units.json`（可手改）。

| 区块 | 单元 | 整区 glb |
| --- | --- | --- |
| zone1 sea | 3 建筑 + detail | 12.4 MB |
| zone2 横滨铁道 | 3 + detail | 1.9 MB |
| zone3 圆弧农场 | 1（整岛一个温室群）+ detail | 15.2 MB |
| zone4 远海街町 | 4 + detail | 0.2 MB |
| zone5 浅水养殖台 | 1 | 0.1 MB |

### Godot 装配

`ModelRoot` 节点（`model_zone.gd`）读 manifest 摆 glb，按 `slots` 逐 surface 套项目原有的
toon/unlit 材质（复用 `BakeStore.material`）。与 `StaticBatch` 二选一，由区块的
`geometry_source` 决定，`_enter_tree` 里先把另一条置 `enabled=false`，不会双份几何。

### 验收

- `test_core` 422 条全绿；`--selftest` 100 项全绿（新增模型清单/顶点数/包围盒/实例数对账）
- 画面：`--source=baked` 与默认 models 同分辨率对比，平均差 0.0285、81.8% 像素几乎一致，
  差异集中在植被摆动与抗锯齿边缘（两次运行时间不同）
- 逐区块截图 zone1..5 均正常

### 坑

1. **枢轴不能用 AABB 底部**：烘焙里有 30m 深的水下基座，枢轴会被压到 -30m。
   统一用「水平中心 + y=0」。
2. **一个单元按材质拆多个 primitive**：Godot 导入后是一个 MeshInstance3D + N 个 surface，
   顶点数/包围盒必须合计所有 surface 再和 manifest 比。
3. **GDScript 的 `:=` 从 Variant 推断会编译失败**：`var path := root + "/" + str(...)` 直接 parse error，
   而 main 里 `add_child(null)` 会让进程被 SIGKILL（表现为 exit 137、stdout 全空，很难查）。
   以后遇到「137 且无输出」，先用 `--check-only --script` 查语法。
4. **外围环境不纳入模型层**：900 万顶点、分块后 420MB，它是背景不是可替换区域，
   继续走 `StaticBatch`；`--env` 可临时导出。

## 10-20 潜水场景：闪动与「建筑破碎」

现象：下潜后整片海底的物件一直在抖，建筑像被拆开成一堆漂浮的楼板。

### 真因：四个区块一律双面，内外壳抢深度

海底的四个区块（basin / neighborhood / reef / trench）此前**所有材质都是 `cull_disabled`**。
沉没街区本身就是「一层层空心盒壳」——外墙、内墙、窗框、挑檐叠在一起，
双面绘制时同一像素上有两个深度几乎相同、法线相反的面在争，
**相机一动就交替胜出**：远看是「墙面发虚」，近看是「物件一直在闪、建筑是碎的」。

修法是把「单面/双面」交还给数据：manifest 里每个材质槽自带 `double_side`，
`uw_materials.gd` 据此选 `underwater(_culled).gdshader` 变体。
实测下来 554 个 surface 里 543 个单面、11 个双面、只有 1 个透明（岩盆外壳 0.38），
也就是街区全部走 `cull_back` —— 填充率和深度冲突一起消失。

`uw_common.gdshaderinc` 同时补了 `uw_face_normal(FRONT_FACING)`：双面材质在背面取反法线，
与 three 的 `DoubleSide` 行为一致（否则岩盆内侧的焦散高光整片失效，岩壁变成灰板）。

### 顺手关掉海底实时阴影

`uw_deco._build_lights` 的方向光原本 `shadow_enabled = true`。街区是几百个半嵌进墙里的
薄盒子，**贴合面的阴影贴图深度几乎相同**，自阴影会在整面墙上长出随相机爬动的细纹，
这也是「闪」的一部分。网页版水下本来就不开阴影，关掉还省掉 40 万三角形的阴影 pass。

### 我在这里走过一次弯路（结论比过程值钱，留着）

看到「建筑只剩楼板、墙不见了」，第一反应是「glTF 逆时针正面、Godot 顺时针正面」，
于是在导出时给每个三角形对调后两个索引（`add_indices(..., flip=True)`）并重烘四个区块。
**结果是全错**：所有墙面变成背面，`cull_back` 下整栋楼只剩内部可见，比改之前更像废墟。

`tools/winding_probe.gd` 用两块已知绕序的四边面（左 = glTF 逆时针，右 = 索引对调）
一次性把这件事钉死：

| 画法 | 左块（逆时针） | 右块（顺时针） |
| --- | --- | --- |
| `cull_back` | 可见 | 消失 |
| `uw_facing_debug` | 绿（正面） | 红（背面） |

结论：**glTF 的逆时针在 Godot 里就是正面**，Godot 的 glTF 导入器会把数据转成它内部的
顺时针约定，导出时**不需要、也不能**翻。`build_underwater.py` 已改回原样并留注释。

### 怎么证明（可复用的工具）

| 工具 | 作用 |
| --- | --- |
| `tools/winding_probe.gd` | 已知绕序的四边面 + 两种画法，**绕序问题的唯一裁判** |
| `tools/unit_cull_probe.gd` | 把单栋 glb 单独摆出来，正面绿/红 + 单面/双面各截一张，**判断某个模型在 cull_back 下是不是完整** |
| `shaders/uw_facing_debug.gdshader` + `--uwfacing` | 正面绿 / 背面红，用来给现场画面定性 |
| `--flicker` + `tools/compare_flicker.py` | 同机位连拍两帧求差，输出差异率与连通块统计 |
| `--uwfreeze` | 冻住焦散相位，把「时间动画」和「深度竞争」分开 |

改后同机位连拍：平均 |Δ| 0.0032，硬跳变像素 0.21%，且**全部落在会动的物体上**
（光柱、气泡、珊瑚摆），楼体表面已经没有成片跳变。

> 注意这套帧差的**局限**：相机静止时两次快门之间深度排序不变，所以它**测不到**
> 相机移动时才发生的深度竞争。相机移动中连拍会把整幅画面的一像素位移算成差异
> （3.7% 起步），也读不出来。判 z-fighting 只能靠几何证据 + 眼睛：
> `house_00` 单个单元里就有 6184 对共面重叠三角形、合计 3102 m² —— 双面绘制时
> 这些必然成对抢深度。

`tools/unit_cull_probe.gd` 给出的关键证据：`house_00.glb` 在 `cull_back` 下**是完整的**，
墙、窗框、窗台、挑檐都在，没有「只剩楼板」。所以「建筑碎了」不是几何缺失，
是双面绘制把内壳也画出来、和外壳在同一个深度上打架。

`--selftest` 新增 8 条绕序断言。注意断言的方向是**反的**：Godot 导入器翻过绕序，
所以运行时网格里 `(b-a)×(c-a)` 与顶点法线**反向**才是对的（见 `tests/integration/selftest.gd`
里那段注释，改之前先跑 `winding_probe`）。现在 **500 项全绿**。

### 还试过、但没用的（省下次的时间）

往海底加一盏「底光」方向光去模拟网页版 `HemisphereLight` 的 ground 色（#30538b, 1.9）。
实测画面平均只变 0.39%，楼板底面亮度一点没动 —— 因为水下着色器根本不吃引擎灯光，
`ALBEDO` 里的明暗是 `0.88 + uw_light() * 1.1` 自己算的。要压底面颜色只能改 shader，别加灯。
已撤销。

### 还没解决：窗洞是「透视」的，墙面偏白

单面剔除之后，窗洞后面没有任何面 —— 视线会穿过空腔看到水色，所以窗户读起来
像一块亮斑而不是暗洞；再加上水下不开实时阴影，挑檐、窗台底下没有接触暗角，
整个立面和水色的对比太弱，远看仍然有点「飘」。

   （用 `n_w.y` 与顶点高度做，不需要额外 pass）；
2. 或者把朝下的面单独乘一个暗系数，替代半球灯 —— 水下着色器不吃引擎灯光，

### 顺带发现（未做，记下来）

## 10-20 潜水重做（F8）：氧气、头灯、发现式宝箱

旧版潜水没有代价：想潜多久潜多久，五个宝箱一进水就在屏幕上列成清单，
点一下自动游过去、等 3 秒、到账。这一版把两件事改回游戏。

### 规则（`src/diving/dive_air.gd`，纯状态机）

100 点氧气，三件事同时烧：

| 消耗项 | 规则 | 取舍 |
| --- | --- | --- |
| 深度 | `0.85 × (1 + 深度 × 0.009)`，75m 处约 1.7 倍 | 深沟只能快进快出 |
| 动作 | 游动 ×1.35，Shift 冲刺 ×1.9 | 赶路还是省气 |
| 头灯 | 每秒 +0.30 | 看得见 vs 待得久 |

35% 报「余气不多」、15% 报「氧气见底」并让仪表呼吸闪烁；
**归零不扣资源，强制上浮 + 6 秒恢复**；5m 以内快速换气（约 3 秒回满）。

### 头灯只能写在 shader 里

水下材质的明暗是 `ALBEDO = base * (0.88 + uw_light() * 1.1)` 自己算的，
引擎灯光几乎不参与（上一轮加补光实测只变 0.39%）。所以头灯是 uniform，不是 SpotLight3D：

```glsl
uw_lamp(n_w) = smoothstep(outer, inner, dot(dir, to_lamp))   // 锥形
             * pow(1 - dist/range, 1.5)                      // 距离
             * (0.18 + 0.82 * max(dot(n, -dir), 0))          // 朝向，留背光散射
```

头灯**不吃深度衰减**，反而在深处更亮。冻结焦散后对比开关灯：
街区机位 +0.5/255（`>20` 占 1.1%），深沟 -121m 机位 **+12.3/255**（`>20` 占 24.6%）。
浅水几乎看不出、深水一眼就亮 —— 「越深越依赖灯」成立了。

踩过的坑：`uw_lamp()` 一开始写在 `varying vec3 v_world;` 之前，编译器报
`Unknown identifier: v_world`。shader 的函数不向前引用，**用 varying 的 helper 必须放在声明之后**。

### 宝箱改成「发现式」

没发现的宝箱不画标签、也不能点（`_visit_chest` 会拒绝并提示）。
发现条件：游到 11m 内，或头灯扫到 26m 内的椎形区域（`dot >= 0.55`，约 55°）。

`to_dict()` / `from_dict()` 只存「发现 / 打开过哪些 id」，不存氧气（读档一律回船、满气）。
**`from_dict` 必须是全量复位**：只做「加上」不做「清掉」的话，读旧档会把当前进度叠上去，
自检里 `清空后已发现归零` 就是这么抓出来的。
