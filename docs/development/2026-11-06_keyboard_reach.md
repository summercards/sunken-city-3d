# 靠岸后的键位与 E 键可达性（2026-11-06）

[主文档](../../GDD_V1.0.md#feature-control) · 承接 SEA-GATHER-R05/R06、SEA-MOVE-R24、SEA-INTERACT-R15/R16/R17/R18、SEA-UI-R52

## 用户反馈

> 靠岸后操作很不舒服，往下没办法自动往下挪，还有很多交互位置没有 E 键可以用的地方。导致没有鼠标就无法操作。
> 比如海上的采集，无法靠近使用 E 键采集。

截图里船停在泊位旁、胶囊提示是「前方靠岸过近，请重新选择航路」。查下来是**三个独立缺口**，不是一个。

## 缺口一：十个采集点在默认范围里全被藏起来了（最严重）

`main._apply_play_scope()` 在最小范围里这样做：

```gdscript
for field in [gather, build_field, salvage_winch]:
    field.hide()                                   # ← 整个采集场被藏
    field.process_mode = Node.PROCESS_MODE_DISABLED
for node in get_tree().get_nodes_in_group("interactable"):
    if not node.is_visible_in_tree():
        node.remove_from_group("interactable")     # ← 不可见就永久离组
```

探针实测（`probe-control-gaps`）：

```
[gap] gather 节点=GatherField  spots=10
[gap] spot Spot_zone1_shell in_group=false vis=false
...（10 个全部 in_group=false、vis=false）
[gap] 交互物统计 { zone1/选择种子:1, zone1/放入/取回:1, zone1/进入房间:1, ... }   ← 一条「采集」都没有
```

所以岸边的贝壳、缆绳、木料在默认范围里根本不存在：看不见、选不中、按 E 没反应。
这不是距离问题，是**它们根本没在世界里**。而且离组是单向的 —— 读档、切回完整范围都救不回来。

**修法**：采集点按**所属区块**启停，并把「不可见即离组」整段删掉
（`Interactor` 与 `HoverCard` 本来就会跳过不可见节点，不需要离组）。
未启用区块（zone3/zone4）的点随区块隐藏，但保留分组，切回来立刻可用。

同时修了落点数据：`gather_spots.json` 的 `y` 来自 `zones.json` 的行走矩形，
而那座甲板后来被手工下调（2.15 → 1.38），表没跟上 —— 两个点悬空 0.77 米、
`area_at` 判不出脚下地面。现在 `GatherField._snap_to_ground()` 在装配时**按场景回算高度**
（XZ 保留设计摆放），表里 `y` 降级为参考值。另外 `zone1_rope` 压在渔场板上（相距 1.72 米，
自检要求 ≥2.4），挪到 `(-15.6, 1.33, 10.6)`。

改后：

```
[gap] 交互物统计 { ..., "/采集": 10, "/交付材料": 3, "/打捞": 1, "/建造渔场": 1 }
[gr] Spot_zone1_shell on=true 建议=(5.887, 1.380, 10.657) 步行=7m
[gr] Spot_zone1_wood  on=true 建议=(3.817, 1.380, 7.466)  步行=9m
[gr] Spot_zone5_fish  on=true 建议=(24.650, 1.480, 18.000) 步行=4m
```

## 缺口二：泊位里朝岸按方向键 = 把船顶到岸上，然后连 E 都不认了

上一轮加手动划船时，泊位里按方向键没有特判：按住 ↓，船用 30% 最低推进顶着岸线往前挤
（实测 0.7 米），抛「前方靠岸过近」，同时**离开泊位** —— 于是 `_landing_is_docked()` 变假，
按 E 也不认，玩家得先把船划回来才能上岸。这正是「往下没办法自动往下挪」。

**修法**：`_key_intent_is_toward_shore(dir)`，两条判据取或 ——

1. 与「泊位站立点 - 船位」夹角 ≤76°（玩家心里的「往岸那边」）；
2. 前方 1.4 米探针撞岸（兜住登陆点在别处的结构物泊位）。

命中就执行上岸，并进 0.35 s 冷却；**沿岸平划**（锥外方向）与朝开阔水面按方向键，
行为一字未改 —— 这一条在测试里各有断言。

只看向碰撞不行：泊位到岸线常有 2–3 米水面，0.5 米探针探不到，于是「朝岸按」被当成划船。
只看朝向也不行：沿岸平划的意图必须仍然能划。

改后探针：`船上朝岸按方向键 30帧: boat_moved=0.0 mode=0 toast='上岸了 · 方向键走路，E 上船'`。

顺带把撞岸提示改成有泊位时提示动作：`前方是岸了 · 按 E 靠岸`（原来只会说「请重新选择航路」）。

## 缺口三：交互提示条被整体关掉了，海面打捞与靠岸没有键盘入口

`_setup_prompt()` 里写着 `prompt.enabled = false`（「服务口袋」那次改版关的，理由是菜箱改成点击冒泡菜单）。
但采集点、出货箱、房门、订单板、绞盘都没有冒泡菜单 —— 于是「站在东西前面该按什么」在画面上**完全没有提示**。
玩家原话「还有很多交互位置没有 E 键可以用的地方」。

同时船上的漂流物/鱼群不是 `Interactable`（它们要「开船靠过去 → 停稳 → 计时」），
一直只有鼠标点得到。键盘玩家在海上等于没有手。

**四处补齐，全部复用既有链路，没有第二条实现**：

| 入口 | 做法 |
|---|---|
| 海面打捞（R15） | `_sea_pick_candidate()` 只读查询挑 12 米内最近目标 → `_handle_prop_click()`（航线→停稳→计时→结算原样） |
| 键盘靠岸（R16） | `_near_landing_key()` 8 米内按最近泊位 → `_select_landing()`（靠泊与上岸仍只有一条链路） |
| 世界菜单键盘化（R17） | 气泡打开后 `1…9` 选项、`E` 选第一个**可用**项、`ESC` 关闭，每项画键位角标 |
| 提示条恢复（R18） | `prompt.enabled = true`；徽标写 `E`（原来写 `spot.verb`，画面上是「采集  采集 · 贝壳」）；空进度槽不画；上移 14 px 让开「视野 %」 |

E 的优先级固定为「贴到跟前先捞 → 上下船 → 8 米内有泊位就靠岸 → 划过去捞」，
提示条文案与 `_press_boat_key()` **共用同一个判定函数** —— 不允许出现「写着上岸、按下去在捞」。

菜单分支必须**先于**上下船分支返回：否则按 E 会同时「确认菜单」和「上岸」。

## 实测

新增专项 `interaction-reach`（**34 项 0 失败**，exit 0），逐条锁住上面每一条：

```
采集点       装配 10 个 → 全部在 interactable 组、全部 area_at != null
岸边采集     站到旁边 → 焦点锁到 Spot_zone1_shell → 按住 E 采到（点进冷却）
泊位朝岸     _key_intent_is_toward_shore(朝岸)=true，沿岸=false
             按住 40 帧 → mode=0（下船）、人在岸上可走面、船没被开走
朝水面       同一组键 → 船划出 0.3 米以上、mode=2（没被下船规则吃掉）
离泊 2.2 米  不算靠妥，但 _near_landing_key 仍认得出泊位；E 靠回去并上岸
船边漂流物   候选= crate、提示=「打捞」、E 进入并**跑完整条打捞链**
```

## 边界与未完成

- 船上 E 靠岸只挑「离船最近的泊位」，没有「选择去哪个岛」的键盘 UI —— 远距离旅行仍需点登陆标记，
  或先手动划到岛边再按 E。
- 打捞的 12 米候选半径是手感值，未做「同时有鱼群和漂流物时的玩家偏好」；当前按距离取近。
- 气泡菜单键盘化只覆盖 `1…9`，没有方向键在气泡间移动焦点；超过 9 项的菜单仅鼠标可点（现有一处最多 6 项）。
- 菜箱冒泡菜单的**真实渲染**截图未出（抓图脚本里那条前置依赖未满足就跳过了），逻辑层已由专项覆盖。
