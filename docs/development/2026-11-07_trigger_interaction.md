# 2026-11-07 触发式交互：取消读条、朝向降为仲裁、上下船改热区

本轮回应四条手感反馈，并把「交互」从「按住读条」整体改成「按一次就做完」。

## 用户原话与拆解

> 部分交互还有细调整：例如有些功能不需要读条，直接走近，进入判定区，出现图标，点击即可触发。比如种植区，不需要读条。大部分的操作反馈都不用压住读条。非常奇怪。
>
> 然后是上船下船的判定。经常容易体验不好。码头的上船区，应该是在海面的，进入热区后点击即可靠岸上岸，上岸后，在陆地，走进船只，船只出现可上船图标，点击一下就坐上船。这样比较简单。
>
> 如果在岸上，同时进入种植区的判定区和上船的判定区，以角色面朝向为优先级判定。这些细节如果我说的不对，你需要帮我纠正，还有没有想到的你也要帮我进行补充。

拆成四条：① 取消读条；② 上下船热区化；③ 同区冲突按面朝向仲裁；④ 允许我纠正与补充。

## 我做的纠正

**朝向不能当硬门槛。** 用户说的是「以角色面朝向为优先级判定」——这是**仲裁**语义，不是准入门槛。上一轮（SEA-INTERACT-R22/R23）恰恰把它做成了门槛：dot ≥ 0.55 才可用、上船要 dot ≥ 0.60。后果是「背对船一米也上不去」，比误触更糟，玩家会以为程序坏了。

改成：判定区里只有一个目标 → 直接可选，完全不看朝向；有多个 → 按朝向排序，差量 ≤ 0.08（≈5°）视为同档，同档内比距离与优先级。显式选择（Q 锁定、点击落下）仍然压过一切。

## 补充项（用户没想到，我补上的）

1. **靠妥容差过大/过小**：旧值 1.0 m 太紧，自动靠泊在余速下常停在 1.1–1.4 m，玩家看到船贴着码头却被告知「船不在泊位」。统一到 1.6 m。
2. **单一仲裁源**：提示文案、近距图标、点击、E 键分派必须是同一个函数的结果。以前散落四处、各判一次，必然出现「写着上岸、按下去在打捞」。
3. **岸边挡停仍能转脸**：朝向从门槛降为仲裁后，玩家可以在原地面朝不同方向切换目标，不需要先挪位置（与 SEA-MOVE-R27 一致）。
4. **码头标记让位**：岸上船停泊位时，常驻锚标记会被挂到船上；新的上船图标也贴在那里 —— 两个同款圆圈叠在一起，读起来像渲染重影。让常驻标记在上船档让位。
5. **热区外的漂流物**：不出图标（图标含义是「你已进判定区」），但 E 仍保留「划过去捞」。必须给提示文案补同源兜底，否则「提示为空、按 E 船却跑了」。

## 实现要点

### `godot/src/interaction/interactor.gd`

`hold_time` 的语义从「要按多久」改成「动作本身多长」，`0` = 瞬发。

| 字段/常量 | 作用 |
|---|---|
| `acting` | 动作正在执行，由一次按下发起，之后自动走完 |
| `_acted_once` | 这一轮按住已经用掉，松开才清 |
| `_wait_release` | 上层显式要求等松手（过场、出门） |
| `FACING_TIE = 0.08` | 朝向分档带宽，同档内比距离 |
| `CENTER_REACH = 0.35` | 脚下近中心豁免，避免零向量抖动 |

删掉了 `FACING_DOT = 0.55`（朝向门槛）与 `_holding_last`（读条时代的状态位）。

三个必须记住的顺序/清理约束（都是本轮真踩到的）：

1. `if acting: _tick_action(delta); return` 必须在去重闸门**之前**，否则按下当帧动作就被冻住。
2. `queue_command()` 必须清 `_acted_once`。命令式交互的 holding 来自 `auto_hold`，永远看不到「松开」；不清就一条命令都不执行，角色卡在 `interacting`（键盘播种全线卡死，只剩一句「背包里没有种子」）。
3. `cancel()` 只能设「手还按着就等松开」，**不能**打开整个闸门。菜单自己会 `actor_controller.cancel()`，闸门全开就会「发起动作 → 发 options → 取消自己 → 再发起」，一个按住的 E 把菜单连开两遍。

### `godot/src/bootstrap/main.gd`

- 新增 `_near_action() -> Dictionary`：唯一仲裁源，`kind ∈ {boat_board, boat_leave, dock, spot, pick}`。
- 新增 `_activate_near_action()` 替代原匿名 lambda。原写法里 `"leave"` 会掉进 else 分支误触打捞。
- 新增 `_actor_in_boarding_zone()`：站立点 2.4 m 内**或**船体 3.0 m 内。两个半径取「或」，因为各区块泊位到站立点距离差别很大（实测 3.6–8.0 m）。
- `_near_landing_key()` 删掉船头 0.20 方向锥，改为热区 + 0.4 s 可航缓存（`plan_route_to` 不便宜，热区每帧三次调用）。
- `DOCK_SETTLE_TOLERANCE = 1.6`，四处统一（`_landing_is_docked` / `_click_boat` / `_landing_icon_world` / `_select_landing`）。
- `_near_action()` 里先 `interactor.refresh_now()`：焦点每 0.12 s 才扫一次，落在两次扫描之间时 `target` 是 null，会把「站在菜箱前」判成「想上船」。

## 顺带修掉的两处「不是本轮引入」的失败

诚实记录，避免误记成本轮回归：

1. `keyboard-panels`：作物表被前序改动从 3 种扩到 6 种（新增蓝星花/晨光花/珊瑚花），笔记条目 6+7=13 条翻成 3 页，而断言把「两页」和「第二页首卡是 platform_plot:2」写死了。已改为按条目数算页数、按内容找地格页。
2. `minimum-loop`：`shop` 命令已改为独立商店面板（`shop_panel.open_shop`），不再开 HUD 页签。断言已按新事实拆分。
3. `selftest` 的「走动打断采集」：读条时代的写法是「连按看 hold 涨」，触发式下不再成立。改为「按下发起动作 → 位移 → 动作中止」。

`selftest` 剩余 24 项失败与 2026-11-07 基线逐条比对，只差三项浮动项（打捞冷却读数、航路长度数值、泊位两两可达条数），属既有历史失败。

## 一个环境事故

中途 Bash 工具开始报 `ENOSPC`，C 盘 0 字节。查明根因是**本仓自己的验证脚本在漏空间**：`run_verification.py` 每跑一轮就用 `custom_user_dir_name="sea-verification/<run>"` 建一个隔离用户目录，Godot 在里面重铺 `shader_cache`，而脚本跑完从不清理。从 10-26 累积到 **1921 个目录 / 20.5 GB**。

已修：新增 `release_user_data()`，跑完把 `logs/*.log` 复制进证据目录再删除整个用户目录（`SEA_KEEP_USER_DATA=1` 可保留）。验证后跑一整轮，用户目录归零。

清理过程本身也踩了一个坑，值得记下：直接删会触发工作区的「修改前备份」钩子，删 20 GB 反而又写回 20 GB，净释放为零；而且 C 盘满时安全删除钩子连自己的临时目录都建不出来，形成死锁。最终解法是把目录整体改名移进备份排除区（`~/.cache`）再删 —— 同一卷改名不动数据。
