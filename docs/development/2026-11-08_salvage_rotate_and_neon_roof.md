# 绞盘打捞台朝向调整与霓虹花园屋顶可活动区（2026-11-08）

关联条款：SEA-WORLD-R31、SEA-WORLD-R32。关联既有条款：SEA-WORLD-R01/R05（行走面与阻挡归属）、SEA-MOVE-R01（WalkArea 作为稳定声明）、SEA-WORLD-R22（可上岸性跟随实际摆放标高）。

用户诉求三项：

1. 绞盘打捞台「角度按养殖平台调整」，只调平台、不调电线杆，捕渔区同步。
2. 检查屋顶草地那栋（`rooftop_ranch`）的可移动区域与模型是否一致，不一致则修。
3. 霓虹花园左楼「可活动区改到屋顶」，有一个 NPC 挪过来（指定：船老大）。

## 1. 从截图反解世界角度

用户截图中的红框经像素测量为**屏幕正对齐矩形**（236,213–458,390，四边严格水平/垂直），不是随手涂的斜框。因此目标是「甲板边缘与画面水平/垂直对齐」。

默认相机 `orbit_dir = (-54, 76.37, 54)`，反解得：

- 视线方向 `(0.5, -0.7071, -0.5)`
- 屏幕右方向 `(0.7071, 0, 0.7071)`

要让甲板局部 X 轴映射到屏幕右方向，需 `Basis(UP, -45°)`。

**踩到的坑（记为工程注意事项）**：`Transform3D` 的九个数字在 TSCN 里按**基矩阵的行**读取。首次按列写入，实测转成了 +45°（方向正好相反），且 `rot_y` 读回 −45° 但实际表现相反——必须用 `to_global()` 验证世界位置而不是只看角度数值。

## 2. 绞盘打捞台（SEA-WORLD-R31）

甲板几何中心 `(-13.456, 12.664)`（GLB 顶点自带 `(-6.9, 8.7)` 偏移，节点原点不是几何中心）。以 `pivot = (-13.45, 11.955)` 绕 Y 轴转 −45°：

| 节点 | 处理 | 实测结果 |
|---|---|---|
| `Models/绞盘打捞台` | 绕 pivot 转 −45° | 甲板世界中心 `(-13.456, 12.664)`，与转前一致 |
| `salvage_station/PoleAndFlowers` | **反向补偿**，世界位姿不变 | 世界位置 `(-2.8, 0, 6.55)` 精确保持 |
| `Models/WildFishery` | 同步转 −45° | 11 个 `Land`/`Flora` 部件全部落在甲板局部 ±4.47/±3.54 内 |
| `Objects/FisheryHarvest` | 位置同步转 | `(-12.8808, 1.33, 11.7393)` |
| `WalkAreas/Walk_zone1_salvage` | 节点自身绕同轴心转 | 行走矩形随甲板走，`Landing_salvage` 派生落点同步 |

电气杆补偿的算法：`new_local = parent_new⁻¹ · (parent_old · old_local)`，即保持世界位姿，只换父空间表达。

## 3. 屋顶牧场（`rooftop_ranch`）：结论是**一致，不改**

新增只读探针 `godot/tools/probe_walk_vs_model.gd`（可见网格临时建三角碰撞 + 逐格射线比对声明面），另用 `godot/tools/probe_roof_profile.gd` 打中线剖面。

结论：

- 楼顶站立面声明 `surface_y = 4.13`（本地 60.05），实测草皮 4.08~4.34，偏差 1~5 cm，可接受。
- 可走范围 x ±23.50 与实测一致；z ∓15.50 是「±16.90 草皮外沿再收女儿墙」的正确结果——z ±16.5 处实测高度 5.20，是 1.07 m 高的女儿墙顶面，**不是可站草皮**。
- ASCII 差异地图显示：主体 `#` 与模型一致，大块缺口正好对应 `ROOF_CUTS` 的五处占地（凉台/棚屋/鸡舍/温室/水塔），位置正确；残差只有 1~2 格零星缺口与草皮起伏。

**过程记录**：中途曾按草皮外沿把 `ROOF_MIN_Z/MAX_Z` 放宽到 ∓16.75，探针随即报出 902 格「声明可走但模型高出 1.07 m」，证明放宽是错的，已回退并在常量上方写清理由。

## 4. 霓虹花园屋顶可活动区（SEA-WORLD-R32）

楼根在 `main.tscn` 实测 `(106.555, -15.870, 88.884)`，`rotY=-107.8°`。据此换算（此处必须用主场景实测值，独立加载场景根在原点会得出错误的 y=31.10）：

| 面 | 局部 Y | 世界 Y | 相对水面 1.12 |
|---|---|---|---|
| 街口铺地 | 1.42 | −14.45 | 水下 15.6 m |
| 左楼屋顶 | 15.20（局部 31.10） | 15.20 | 水上 14.08 m |

改动：

- `WalkLeftRoof` 增 `Landing_main`：站立点在屋顶（局部 y 31.10 → 世界 15.20），`BoatPark` 在实际水面（局部 y −14.11 → 世界 1.12），垂直差 14.08 m。**这是用户确认的选择**：「直接上岸到屋顶」，不做水面→屋顶的爬升通道。
- 撤销 `WalkStreetLanding` 的 `Landing_main`：铺地在水下，泊位本来不可用，且与屋顶泊位同名 `main` 会冲突。
- 新增 `RoofNpcStations`（`walk_path = WalkAreas/WalkLeftRoof`），船老大 `npc_luo_yan` 迁入；`rooftop_npc_stations.tscn` 移除原站点，避免同一 `npc_id` 双处登记。
- `main.gd` 的 `NpcAnchorHub.configure()` 追加 `RoofNpcStations`。

**落点踩坑**：派生屋顶的 `rects` 是**断开的 14 块**，中间 x −15.5…−12.5 有一大片空缺。首次选的 `(-14, 3.5)` 正好落在空缺里，`surface_point()` 返回 INF，锚点直接缺失。改到 `(-16.5, 1)`（x −18…−15.5 × z −2…7.5 那块 2.5×9.5 的连续大块）后正常。

**坐标踩坑**：`surface_y` 存的是**世界高度**，而 Marker 的 `position` 是**局部坐标**。混用会把落点算到楼外（实测站立点 y 变成 1.42，船位掉到 −14.75）。
