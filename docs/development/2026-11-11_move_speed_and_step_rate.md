# 2026-11-11 行走提速与步频翻倍

[主文档](../../GDD_V1.0.md#sea-move) · [功能设计](../features/move/spec.md) · [功能账本](../features/move/ledger.md)

对应 SEA-MOVE-R29。用户原话两句：「角色移动动画加快一倍，移动速度加快0.5」。本轮把它落成两个数，不改其他任何东西。

## 改了什么

| 项 | 旧 | 新 | 落点 |
|---|---|---|---|
| 岸上行走地速 | 2.3 m/s | **2.8 m/s** | `free_walk_action.SPEED`（键盘）、`walk_action.SPEED`（点击）、`main.WALK_SPEED`（参考值） |
| Shift 轻跑 | 2.576 m/s | **3.136 m/s** | 仍为 `SPEED × 1.12`，没有第二套倍率 |
| 玩家步行相位倍率 | — | **×2.0** | `ActorController.PLAYER_WALK_PHASE_SCALE` → `Character.walk_phase_scale` |
| 满速步频 | 6.4 rad/s | **12.8 rad/s** | 同上，由 `WALK_PHASE_RATE × walk_phase_scale` 得出 |
| 半速步频 | 3.2 rad/s | **6.4 rad/s** | 随速度比线性缩放，不变式保留 |
| 轻跑步频 | 7.36 rad/s | **14.72 rad/s** | `12.8 × 1.15/1.12`，仍不重复乘 15% |
| 每步位移 | 1.129 m | **0.687 m** | 每步占 π 相位（左右腿各一次 = 2π），故 `速度 ÷ (步频/π)`：`2.3÷(6.4/π)` vs `2.8÷(12.8/π)` |

倍率放在 `Character` 上而不是硬乘进 `WALK_PHASE_RATE`，理由是 NPC 共用同一个 `Character`：`npc_world_presenter` 按 2.0 m/s 走，若步频跟着翻倍会变成 4 步/秒的碎步，比原来更滑。所以 `ActorController.configure` 只给玩家写 2.0，NPC 保持默认 1.0。

动画快了但地速只加快 21.7%，两者不是同一个比例 —— 这是用户要的效果：「动画加快一倍」和「速度加快 0.5」是两个独立指令。代价是每米腿摆次数由 `6.4/2.3 = 2.78` 升到 `12.8/2.8 = 4.57 rad/m`，脚底相对地面会有轻微滑移（约 +64% 步频密度）。要完全贴地只有两条路：步频倍率回调，或地速继续加。这条已记在 spec 与账本里，不藏。

## 没动的东西

胶囊 0.22 m / 1.30 m、+Z 朝向契约、加减速时间常数 `τ_accel 0.085 / τ_decel 0.055`、反向折减 `0.35 + 0.65(cosθ+1)/2`、地面与净空判定、导航烘焙、上下船与存档字段、轻跑折减比 12%。`walk_speed_ratio` 仍按 `speed_actual / SPEED` 算，所以半速、起步、被挡的值全部自动跟着新基准走，不需要第二处改数。

## 测试侧的两处修正（不是放水）

1. `test_control_feel` 第 5 段原来用「首尾相位差再 wrap 到 ±π」测步频。步频 12.8 rad/s 时 0.5 秒刚好转过一整圈，wrap 后读成 0.23 rad/s 的假值。改成 `measure_walk_rate()` 逐帧累加 `fposmod(delta, TAU)` 再平均 —— 这是循环量的正确测法，旧写法只是因为 6.4×0.5 = 3.2 < π 才碰巧成立。
2. `test_shift_jog` 的「切走路不重置相位」原来断言单帧增量 < 0.15 rad。单帧增量现在本身就是 0.245 rad，改成断言「落在 (0.02, 0.30) 区间」—— 真重置会给出 0 或接近一整圈，仍然能抓到，只是阈值跟着步频走。

## 第二轮：再快 10%（同日，SEA-MOVE-R30）

用户追加「角色走路播放速度再加快50%」，随后两次收敛口径：「不要到50% 改成20%」→「改成10%」，最终取 10%。只动倍率一个数：`PLAYER_WALK_PHASE_SCALE` `2.0 → 2.2`（2.0×1.1）。地速、轻跑折减比、加减速时间常数、胶囊与朝向一律不动。

中途试过 ×1.5（50%）与 ×1.2（20%）两档，均已被 ×1.1 覆盖，代码里不留旧值。

| 项 | 第一轮 | 第二轮（最终） | 原始 |
|---|---|---|---|
| 相位倍率 | ×2.0 | **×2.2** | ×1.0 |
| 满速步频 | 12.8 rad/s | **14.08 rad/s** | 6.4 |
| 半速步频 | 6.4 | **7.04** | 3.2 |
| 轻跑步频 | 14.72 | **16.192** | 7.36 |
| 步频（步/秒） | 4.074 | **4.482** | 2.037 |
| 每步位移 | 0.687 m | **0.625 m** | 1.129 m |
| 每米腿摆 | 4.571 rad/m | **5.029 rad/m** | 2.783 rad/m |
| 单帧相位（60 FPS） | 0.213 rad | **0.235 rad**（轻跑 0.270） | 0.107 |

口径变更全过程：50%（×3.0）→ 20%（×2.4）→ **10%（×2.2，最终）**。前两档均已被覆盖，代码里只留 2.2。

记步换算口径：一个完整 `sin` 周期（2π 相位）是左右腿各迈一次，所以 `步/秒 = rad/s ÷ π`，`每步位移 = 地速 ÷ 步/秒`。按此 4.482 步/秒、每步 0.625 m、每步 0.223 秒。

4.482 步/秒仍在慢跑频率之上（正常人快走约 2 步/秒、慢跑约 3 步/秒），步幅 0.625 m（0.33 倍身高；正常走路约 0.4 倍，角色身高 1.87 m）—— 画面读作**步幅收窄的小跑节奏**，不是大跨步快走。三档横向对比：×1.5 是 6.112 步/秒 / 0.458 m（明显碎步），×1.2 是 4.889 / 0.573 m，本轮 ×1.1 是 4.482 / 0.625 m，原始 ×1.0 是 2.037 / 1.129 m。这是「地速 +21.7%、步频 +120%」的算术后果，不是实现缺陷。要真正读作快走，须同时放大 `walking_action.gd` 的 `stride` / `arm_swing`，本轮没做。脚底滑移密度 5.029 rad/m，是原始的 1.81 倍，同样不据此判失败。

## 第三轮：Shift 快跑再快 30%（SEA-MOVE-R31）

用户：「压住shift快跑的速度要再快一点 30%把」。走路不动，只提速快跑。

### 一个数改不动，必须同时改三个

如果只把 `SPRINT_MULTIPLIER` 从 1.12 改成 1.456，会立刻坏两处：

1. **`walk_speed_ratio` 被 clamp 截断**。`free_walk_action.gd` 原本是 `clampf(speed_actual / SPEED, 0.0, 1.35)`。轻跑实际比值 1.456 > 1.35 → 被压到 1.35，步频比地速慢 `1.456/1.35 = 7.9%`。表现是跑起来脚在地上往后拖。上界提到 **1.50**（留 3% 余量容斜坡/推挤的瞬时超速）。
2. **`JOG_PHASE_MULTIPLIER` 的除数过期**。它是 `1.15 / 1.12`，语义是「地速倍率已经带来 12% 步频，再补足到 15%」，即 `总步频倍率 = ratio × JOG = 1.15`。若沿用旧式而 ratio 变成 1.456：`1.456 × 1.027 = 1.495`，轻跑步频 `14.08 × 1.495 = 21.05 rad/s = 6.70 步/秒` —— 比用户上一轮砍掉的 ×1.5 档（6.11 步/秒）还碎。改成 `1.15 / 1.456` 后总倍率回到 1.15，轻跑步频 16.192 rad/s = 5.15 步/秒。
3. **腿摆幅度失配**。步频只涨 15%、地速涨 45.6%，步幅必然从 0.625 m 放大到 0.791 m（+26.6%）。`walking_action.gd` 的 `stride` 原本 `0.54 × 1.12 / 1.15 = 0.526`（略短步），继续用就会「腿只摆 31° 而身体每步跨 0.79 m」= 腿没迈开、人滑出去。改为 `0.54 × 1.456 / 1.15 = 0.684 rad`（39.2°）。

手臂仍由 0.66 收到 0.55，抬膝 0.48→0.86、屈肘 −0.18→−0.82、前倾 0.045→0.12 全部不动 —— 跑与走靠姿势和步幅区分，不靠整体放大。
