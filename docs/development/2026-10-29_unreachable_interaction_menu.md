# 到不了的地方也要能点出菜单（2026-10-29）

对应条款：[SEA-INTERACT-R09](../features/interact/spec.md)。证据：`unreachable-menu`。

## 现象

站在木屋码头，看左边台阶旁的菜箱、看右边水上的六格种植平台：
**点可交互物没有子菜单**。截图里红框标出的那颗「浇水」图标也一样 ——
看得见、点不着；点远处的箱子，菜单干脆什么都不弹。

## 根因：三处叠在一起，任何一处都足以让「点了没反应」

### 1. 命中只认那颗 38px 的圆，物体本体点不中

`HoverCard._pick()` 的距离口径是「鼠标到图标中心的像素距离 < 30」：

```gdscript
var sp := camera.unproject_position(anchor)   # 图标位置
if sp.distance_to(screen) > HOVER_RADIUS: continue
```

而 `_show()` 只在那之后才把图标画出来。也就是说——**你得先点中它，才看得见它**。
物体越高、离得越远，图标抬得越高（`Vector3.UP * 0.75`），屏幕上离本体越远。
实测 zone1 出货箱：箱体屏幕包围盒 240×275 px，图标在包围盒右下角外 192 px，
箱体中心到图标 775 px。玩家凭直觉点箱子，永远落在 30 px 之外。

### 2. 气泡锚点出屏就立刻关

`_bubble_anchor()` 在投影落到视口外时返回 `null`：

```gdscript
if not get_viewport().get_visible_rect().grow(24).has_point(screen): return null
```

`WorldActionBubbles._place()` 拿到非 Vector2 就 `close(true)`。
隔水看对面平台时锚点投影在 (2063, -7) —— 菜单开一帧就没了，
视觉上等价于「没弹出来」。

同一处还有第二个毛病：锚点用 `spot.global_position`（节点原点），
而判定用 `focus_position()`（视觉包围盒中心）。出货箱两者差 2 米，
菜单会开在箱子旁边的空地上。

### 3. 走不过去是静默失败

即使菜单弹出来，选完也什么都不发生：

```gdscript
func execute(c, target) -> bool:
    ...
    if area == null: return false          # 无提示
    if not c.start_walk(...): return false # 其中的通知是别的分支才有的
```

气泡已关、角色不动、没有 toast —— 玩家的唯一解释只能是「这游戏坏了」。

## 修法

### 1. 命中改成「落在物体身上」

`_screen_bounds()` 取世界 AABB 八个角投影求并集，`_pick()` 的距离取两套口径的小值：

| 口径 | 用途 |
|---|---|
| 到屏幕包围盒的距离（外扩 10 px） | 主路径：点在箱子/牌子上就算 |
| 到图标中心的距离（30 px） | 没有几何的纯逻辑点（睡眠位）只有这一套 |

`_usable_bounds()` 加了一道闸：包围盒面积超过视口 12% 就不参与身体命中。
原因是菜箱的视觉根可能是整张培养床，包围盒把整个木甲板包进去
（zone5 半宽 2 米）。照单全收的话，玩家点甲板任何一处都判成「点在菜箱上」，
**再也走不了路** —— 那是一次修复换一次更糟的回归。这类物件退回图标口径，
它的锚点本来就在甲板中间，凑近照样能操作。

### 2. 贴边图标 + 点击点兜底

`_clamp_to_viewport()`：视口内的点原样返回（正常距离下图标不能因靠边被吸走），
只有整块投影出屏时才夹到边内（内缩 28 px），并给右上/右下两颗 72px 常驻圆按钮
让出 112 px 的角。

`WorldActionBubbles.open()` 新增 `screen_fallback`：锚点查不到时退回到
「玩家点下去的那一点」，菜单钉住不动。连点击点都没有（不是玩家点开的）才收起。

### 3. 走不过去要说出原因，并且菜单照弹

`main._land_reach_reason(spot)` 按三类返回不同的话：

| 情况 | 文案 |
|---|---|
| 目标不在任何可行走面上 | 这里没有能走过去的地面 |
| 目标在另一个 zone | 那边在别的区域，需要先坐船靠岸 |
| 同 zone 但路径断开 | 那里走不过去，中间没有连通的路 |

这句话直接进两个地方：

- 菜单标题（和「选择种子」同一个奶油胶囊）：三颗全灰的圆不说一句话，
  玩家只会以为界面坏了；
- 每个可执行项的灰态 `blocked`：点下去 toast 同一句。

`approach_action.execute()` 补齐所有静默分支的 `notify`：目标失效、潜水态、
没有地面、跨区、路径不通，各说各的话。

## 副作用修掉的两个观感问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 长句标题糊成一团、像重影 | `Cozy.world_text()` 带 `variation_embolden = 1.0`（给 44px HUD 数字补粗细）+ 3px 偏移投影，落到 23px 长句上就糊 | 标题换回不加粗圆体、24px、1px 投影 |
| 菜单压住右上角菜单按钮 | 锚点被夹到右上角，弧形气泡和标题正好盖住那颗 72px 圆 | `_place()` 加右上/右下 118 px 保护区，相交就整体下推/上提；推不动就保持原样（宁可压角，也不能把菜单推出屏幕） |

## 验证

`python3 scripts/run_verification.py unreachable-menu`（25 项断言，0 失败）

| 断言组 | 覆盖 |
|---|---|
| 点物体本体 | 取包围盒里离图标最远的角（实测 192 px），旧规则必然落空，新规则命中 |
| 巨型包围盒 | 24×24 米平面盖满屏幕 → 不参与身体命中 |
| 菜单钉住 | 点击后 40 帧仍然打开，标题整段在视口内，不压右上角 |
| 二级菜单 | 菜箱 → 种植 → 选种子，有层级标题 |
| 跨区目标 | 菜单照弹、不消失、每项都写原因、标题就是那句原因 |
| 灰项 | 点下去 toast 出原因 |
| 接近失败 | 海面中央的交互点：不开始行走，且给出提示 |
