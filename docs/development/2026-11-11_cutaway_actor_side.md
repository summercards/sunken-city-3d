# 2026-11-11 剖切必须看角色站在墙的哪一侧

[返回主文档](../../GDD_V1.0.md#sea-room) · [功能文档](../features/room/spec.md) · [独立账本](../features/room/ledger.md)

对应条款：SEA-ROOM-R17。

## 用户报的问题

一张室内截图（角色站在玻璃前厅外的木台上），原话：
**「房屋内的这面墙，还没走进屋子的时候就看不见，会导致感觉被空气墙挡住」**。

## 根因

剖切（`room_cutaway.gd`）原来只按**相机**判：相机越过某面墙的外表面，这面墙就收。
这条规则在「人已经在屋里」时是对的 —— 相机和人在同一侧，收掉的是挡视线的墙。

但进屋的落点在 `ENTRY_LOCAL = (0, 0, 3.25)`，也就是**玻璃前厅里**，人还没进屋。
这一刻：

| 量 | 值 | 结果 |
|---|---|---|
| 相机局部 z | ≈ +6.9（俯角 46°、距离 14.4） | 越过前墙外表面 2.5 |
| 角色局部 z | 3.25 | **也还在前墙外侧**（2.5 以外） |
| 前墙 `WallDoor` | 按相机判 → 收起 | 人眼前本该是一堵带门洞的实体墙 |

于是画面里是「一间没有前墙的房子」，人自然走过去 —— 然后撞在门洞边框上。
不是碰撞错了，是**视觉把实体墙拿掉了**。这就是空气墙的来源。

## 改了什么

收墙判据从「相机越过这面墙」改成「相机越过这面墙 **且** 角色已经在这面墙内侧」：

```
visible = cam·n < face + margin                       # 原有的相机判据
        AND NOT (actor_known AND actor·n > face + 0.25)  # 新增的角色闸门
```

- `face = 2.5`（墙到中心），`ACTOR_WALL_MARGIN = 0.25` → 阈值 **2.75**。
  门槛外沿在 2.74，所以「跨过门槛进屋」就是「墙让开」的那一步，误差 1 cm。
- 只对**墙**生效。玻璃前厅那排构件（正面玻璃、门框立框、裙墙、圈梁、立柱）
  不吃这条闸门 —— 它们遮的是「镜头与地板之间」，相机在前厅前上方时照旧整排收。
  实测过一次「一起保留」的写法：画面下方是一个大白框，把角色下半身挡住。
- 角色不在屋内时闸门整体跳过（局部包围盒 `|x|<6`、`-6<z<8`、`|y|<4`）。
  这一条是必需的：`_begin_inside` 里 `set_active(true)` 在 `restore_pose` 之前，
  那一帧角色还在海面，房间局部坐标几百米开外，「人在墙外侧」会被算成真，
  本来该收的墙会闪一帧。

接线：`room_scene.set_actor_query(query)` → `_cutaway.actor_query`；
`main._setup_room` 注入 `func() -> Node3D: return player`。

## 实测

| 套件 | 结果 |
|---|---|
| `room` | **125 项 0 失败**（+6 条 R17 断言） |
| `visual-room` | 8 机位 0 失败 |
| `sleep-cycle` | 通过 |
| `keyboard-farm-loop` | 通过 |

新增断言：进屋时角色局部 z > 2.6 / 此时前墙必须可见 / 此时前厅构件照旧整排收 /
进屋后局部 z < 2.5 / 之后前墙收起 / 之后前厅整排收起。

## 代价（必须说清）

`visual-room` 的 `inside` 机位（进屋默认构图）现在会看到一堵带门洞的前墙，
室内近处三分之一被它遮住。这是**刻意的取舍**：

| 方案 | 空气墙感 | 进屋瞬间视野 |
|---|---|---|
| 只按相机收（旧） | 有 —— 墙看不见但走不过去 | 好 |
| 按相机 ∧ 角色（现在） | 没有 | 差一点，人一进门就恢复 |

选后者的理由：主人报的就是「看不见墙」；而遮住近处只是几秒的事 ——
角色落点在门槛外，走一步（0.34 米门槛）就进室内，墙随即收。
如果以后想让默认构图也开阔，正确做法是**把落点挪到门内**（`INNER_LOCAL`），
而不是把墙重新藏起来。
