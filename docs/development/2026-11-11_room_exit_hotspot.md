# 2026-11-11 屋里门口的出门热区

[返回主文档](../../GDD_V1.0.md#sea-room) · [功能文档](../features/room/spec.md) · [独立账本](../features/room/ledger.md)

对应条款：SEA-ROOM-R16。

## 用户报的问题

一张室内截图，角色站在玻璃前厅外面的木台上，原话：
**「在屋子里这里没有出去的操作热区，键盘操作出不去」**。

先查了实现，屋子里当时只有两条出门通道：

| 通道 | 位置 | 玩家能不能发现 |
|---|---|---|
| 右下角橙色圆钮（门 + 箭头） | 屏幕右下，体图纸上面积约 72×72 px | 能看见，但和体力条挤在一起，**没有文字**；提示「离开房间 · X」只在鼠标悬停时出现 |
| `X` 键 | 无 | 纯靠记 —— 屋里没有任何一处写着 X |

而**门口本身没有热区**。屋外那颗「进入房间」是 `Objects/RoomDoor` 交互点，
走进去按 E 就能进屋；屋里那扇门只是一块几何，靠近没有任何焦点、
`[E]` 提示也不出现。所以在门边站着按 E 什么都不会发生 —— 键盘玩家被卡在屋里，
只能去发现那个小圆钮。这是「进出不对称」，不是「按钮藏得深」。

顺带确认了圆钮与 X 键本身没坏：真实点击圆钮 → 过场开始、`inside` 变 false；
真实 X 键 → 同样正常（探针实测）。所以不是事件没接上，是**少了一个入口**。

## 改了什么

1. 新增 `godot/src/room/room_exit_point.gd`：纯逻辑交互点，和 `room_door.gd` 对偶。
   - `id = "room_exit"`、`label = "门口"`、`verb = "离开房间"`、`priority = 6`；
   - `focus_radius = 1.6`、`auto_radius = false`、`focus_anchor = "node"`
     —— 没有视觉包围盒，半径必须手写，否则 `auto_radius` 会算出 0；
   - `interact()` 只发 `exit_requested`，返回 `{"event": "room_exit_requested"}`。
2. `godot/scenes/rooms/bedroom.tscn` 根下加 `ExitPoint`，局部 `(0, 0, 4.25)`。
   前厅可走面到 `z=4.32`，所以它压在**房间最外沿**：玩家走到「已经想出去」的那一步，
   就正好在半径里（截图里那个位置就是这里）。半径 1.6 米同时覆盖「刚进屋站在前厅」。
3. `main._setup_room` 接线：`exit_point.exit_requested → _on_click_command("room_exit")`。
   **没有新通道** —— 圆幕过场、世界显隐、背景切黑、存档语义全用既有那条。
4. 图标读作「离开」：`hover_card.show_near_focus`（近距图标）与
   `main._open_spot_bubbles`（点击气泡）都按 `id == "room_exit"` 取 `back` 图，
   而不是默认的 `hand`。气泡标题是「门口」，按钮文案是「离开房间」。
5. 进屋/出门的显隐沿用 `room_scene.set_active` 已经维护的 `_interactables`：
   屋外时该点退出 `interactable` 组 —— 否则站在太阳房甲板上会点得到 200 米高处的门。

## 实测

统一 runner，隔离用户数据：

| 套件 | 结果 |
|---|---|
| `room` | **119 项 0 失败**（原 112 + 本轮 7 条） |
| `visual-room` | 8 机位 0 失败，新增 `room-exit.png` |
| `keyboard-farm-loop` | 通过（X 键与 E 键互不误触的既有断言未被破坏） |

新增断言：屋里门口有独立出门交互点 / 屋外时不在交互组 / 屋里时进组且可见 /
站在前厅门洞选中「离开房间」/ 动作文案 / 按交互键触发出门过场 / 出门后退组。

`visual-room` 的 `exit` 机位（真渲染）里，人物头顶出现橙色圆形「返回」图标 ——
这就是玩家在门边能看见的那个入口。

## 边界

- 没有给门口加第二个可见几何（门牌、地贴）。热区本身就是「走近才出现」的语言，
  和屋里其它可交互物（床、床头柜）一致；加实体标记会和剖切、玻璃前厅的构图打架。
- X 键保留。它现在只是快捷键，不再是唯一出路。
- 这次没动 `tv/` 那份播放画面，也没有新增失败状态。
