# 2026-11-02 建造模块深度审计

关联：SEA-BUILDING-R01–R26；跨功能读取 SEA-MOVE / SEA-SAVE / SEA-UI。主入口为 [GDD 功能导航](../../GDD_V1.0.md#sea-building)，规则以 [建造规格](../features/building/spec.md) 为准。

## 结论

**基础建造闭环和25项内容具备，但尚不满足“各种组合都可靠、操作顺手、每条功能完整通过”。本轮确认6项功能缺陷，其中3项优先处理；另有相机操作限制和两处测试覆盖偏差。**

当前支持：三种平台贴边组合、四向旋转、跨板摆件、施工扣费、种植与带作物搬移、安全退款、独立海上平台、动态登陆、二层楼梯/楼板、共享仓库、补水和照明。正向样板通过，不代表所有排列、删除和二层布置都安全。功能账本改为 `partial`，不再把相关条款一律标成已实现无缺口。

本轮为审计，提交范围是证据与功能状态。产品代码、正式场景和玩家槽位没有由本轮修改。所有运行通过 `scripts/run_verification.py`；新反例使用工程外 Python 包装器扩充 TESTS、把探针复制进 runner 创建的隔离工程，不改仓库 runner。

### BUILD-AUDIT-01：混合新摆件与旧培养土，放置和存档规则不一致

以建造局部坐标为例，在中心 `(100,100)` 的4×4浮台上：

1. 先建桌面油灯 `(100.2,100)`。
2. 再建标准培养土 `(99,100)`，此时两件相距足够远，布局合法。
3. 用默认0.1米吸附把油灯搬到 `(100.1,100)`，不需要Shift。
4. 搬移命令成功，但 `BuildingService.validate_snapshot` 返回 `Invalid building support or overlap`。

此时实体之间仍有约1.3厘米空隙。新套件用 `shape.grow(-0.008)` 检查重叠，旧培养土用 `other.grow(0.02)`；相同几何从两边检查得到不同答案。先土后灯可以成立，先灯后土被拒；反转保存记录顺序也能改变校验结论，违反顺序无关要求。

`save_schema.gd:70` 会把该错误上交，`SaveGame.write` 在实际写盘前拒绝布局。本轮使用正式 Boundary / World 的候选空间检查，以及 Controller 生成的默认吸附请求复现；另有小培养土+Shift的独立反例。未冒充完整GUI拖放全过程。

修复应统一旧培养土和新组件的同层间距、空间分离与快照校验规则，并验证两种创建顺序、搬移后保存、反转记录顺序都得到相同结果。

### BUILD-AUDIT-02：家具切口把相邻二层板的导航边拆坏

合法布局有三块由柱独立支撑的二层板 A→B→C，楼梯连接A。在B放一个木储物箱：

- 放置允许，施工完成。
- B上还保留 **0.955米** 宽的净通道，超过角色直径0.44米。
- 同一B板内部沿通道可以求路，C到B通道却没有路径。
- 无箱时C→A有路径；反转所有存档记录后，有箱仍断路。

实际 NavigationServer 证据：原拼缝 `x=103,z=99..101` 在双方各有同长边；家具切割后，B变为 `99..100.045` 与 `100.045..101`，C仍为 `99..101`。`AssemblySurfaces.faces` 只同步楼板占地边端点，没有同步家具切口顶点；三角网格形成不匹配接缝。

结论限定为**点击导航通路失败**。本反例没有直接驱动真实胶囊跨越该家具接缝，不能把这一条扩写成已确认物理碰撞封死。

### BUILD-AUDIT-03：二层连通性没有进入安全修改门禁

同样A→B→C布局，角色站C，拆中间B：`can_remove` 返回空原因，`remove` 成功并正常退款，随后C到A楼梯口的实际导航路径为空。拆后布局仍通过快照校验。

Boundary仅保护角色正在站的那块楼板；后续 `world.walk_rects` / `Space.connection_reason` 检查基础层二维地面，不包含二层通路。把楼板换成摆件堵住二层桥也存在同类保护遗漏。

修复应对候选布局的三维可达关系统一检查，至少保护角色→楼梯→地面、现有交互点及返船路径，避免只检查脚下有无地面。

### BUILD-AUDIT-04：搬移阶段缺少目的地虚影

新建培养土正对照有1个虚影；选中既有培养土进入搬移后，目标请求合法、提示明确写“点击放到新位置”，但可见虚影为0，选中轮廓也隐藏。`_refresh_ghosts` 根据 `recipe` 创建虚影，`recipe="move"` 不匹配平台或摆件；选中后 `update_preview` 又隐藏轮廓。

本轮真实渲染 `diy-move-preview.png` 也显示只有文字，原物仍在旧位置，目的地没有预览。玩家难以判断跨缝占地、旋转及细调，容易反复试点。应按被搬物件种类生成目标虚影，保留原物直到成功提交；非法原因与红绿状态同步。

### BUILD-AUDIT-05：培养土的U选层是虚假的

合法浮台+四柱+二层楼板上，按U显示楼层2，投射射线世界高度约4.28米。`planter_small` 请求却没有 `py`，支撑选到底层浮台，实际成功提交高度约1.48米。油灯正对照有 `py=2.8` 且支撑指向二层楼板。

不是单独补UI高度即可：旧培养土的服务、记录与Farm投影也没有完整的二层承载协议。若目标仍是R20的二层摆件，需把种植区纳入一致协议；若产品决定暂不支持二层种植，应明确禁选并告知原因，不能楼层2点击成功却建到楼层1。

### BUILD-AUDIT-06：用完整包围盒点选，门洞被当成实心

26.6°合法视角中，射线从门洞中间通过，高出甲板1米、水平偏门中线0米；可见目标为后方花盆，但 `_item_under_cursor` 返回门框。模型门洞是真空，管理射线却检测整块AABB。

应以模型/明确分段选择体检测空洞，或提供楼层/遮挡过滤和可循环选择。屋顶/楼板的完整AABB遮挡也需要一起回归，不能为了让高灯可选把所有空洞变成不可穿透的选择面。

合计：3平台＋10框架＋2种植区＋10生活摆件＝25配方。首批22件新套件中的“12种结构”包括两种浮台，不能再次把平台重复计入框架数量。

**可以做开放式水上平台和一层建筑框架，附带二层露台；目前不能自由搭完整两层房屋、二层护栏、任意角度或桌面堆叠。** 墙/栏杆限制与第三层未开放是现有规格边界，不作为本轮新增回归；如果用户期待完整多层建房，需要显式扩充设计和能力。

另一个 FeatureID `SEA-BUILD` 是固定建筑修缮升级，当前最小可玩范围锁定大部分固定升级，原设计的绞盘站三级场景成长仍在其账本标记partial；不能用本模块25配方的正向检查代替固定升级验收。

## 测试自身的覆盖缺口

1. `test_building_perf.gd:27–34` 没检查每次begin是否成功；夹具从原点起板，与固定平台重叠部分被拒。所谓45板门禁本轮实际测的是21板（另外两档为5、12）。本轮独立探针对每块创建结果做断言，补测实际9/25/45/100块，未发现吸附性能回归。**测试标签错误与产品性能差是两回事。**
2. `test_building_ocean.gd:45` 的独立海面请求没有 `origin="boat"`。R22后纯规则默认按岸上处理，两个开工断言失败，后续探针没有及时中止而超时124。真实 `BuildingController._deck_request` 已写入boat来源；只在隔离副本修正这一条夹具请求后，原海上施工→登陆→返船→存读与退款流程通过。原仓库测试仍需更新，不能把修正夹具的结果写成原测试PASS。
