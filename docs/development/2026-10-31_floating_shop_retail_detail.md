# 海上悬浮商铺 v003 · 零售细修（摆件 / 广告牌 / 玻璃 / 店内装饰灯）

承接 SEA-ASSET-R37，复审 R35 的材质口径。用户的需求很明确：**要上一版的美术感觉，用这一版的方形规格**，只调摆件、广告牌、玻璃和店内装饰灯，其它不要动。

## 为什么这版粗糙

v003 把「不要商店门窗」实现成了整片实墙：32 个组件里没有玻璃、没有招牌、没有陈列品，客厅里也空着。造型换对了，但零售的建筑语义被一起删掉了 —— 站在甲板上看，就是一栋没有内容的方盒子。

上一版（v002）的内容其实都在，逐件列出来对照：

| 类别 | v002 | v003 修正前 |
|---|---|---|
| 玻璃 | 14 个弧形橱窗单元 | 0 |
| 广告牌 | GIFTS / POSTCARDS / COLD DRINKS 三块 | 只有一块 SEA SUPPLY |
| 外部摆件 | 明信片架、红邮筒、ICE 冷藏箱、黄色售货机 | 0 |
| 店内 | 8 组陈列架 + 饮料瓶 + 礼盒玩偶 | 0 |
| 店内灯 | — | 0 |

不改的东西也逐条钉住了：甲板、屋顶、墙脚、角柱、遮棚、栏杆、轮胎、救生圈、爬梯、主控机箱、射灯、屋面管线、电气箱、信号灯、推进器、浮舱、配重、花盆植物、铭牌、长凳、货箱、系泊柱。

## 做了什么

**玻璃。** 正面 4 块实墙板换成 2 米橱窗单元（`shop_window`），窗带 0.56–4.30 米：上面留奶油横缝墙板，下面青绿窗裙，中间内凹玻璃 + 青绿竖框横档。玻璃用 `SEA_Gloss`，材质槽恢复透明（`transparency=1`、`alpha=0.13`、`roughness=0.05`）。

**关键约束：玻璃是陈列面，不是入口。** 门仍然是 0，主体内部仍然不可走 —— 这条由 `sea-supply` 的「enclosed body is not walkable」断言盯着，而不是靠注释。

**广告牌。** `sign_gifts`（GIFTS + 红礼盒）与 `sign_drinks`（COLD DRINKS + 饮料杯）做成直线牌，与既有 SEA SUPPLY 同高同带（z=7.38），落在 12 米墙两侧各 3.2 米的空档里。第一次放在 5.55 高度，被遮棚完全挡住 —— 招牌必须和 SEA SUPPLY 同一带，否则等于没挂。

**摆件。** 环廊外侧放明信片架、红邮筒、ICE 冷藏箱、黄色售货机，全部避开前侧 3.2 米栏杆开口（走位检查带 x∈[-1.2, 1.2] 保持 2.4 米净宽）。店内 4 组货架 + 每组一瓶组 + 一盒礼盒玩偶，位置在玻璃内侧，站在甲板上透过玻璃能看见。

**店内装饰灯。** 4 盏吊灯（垂杆 + 黄铜灯座 + 奶油灯罩 + 暖光灯泡）+ 1 串橱窗灯（悬垂电线 + 13 颗发光小球），全用 `SEA_Emission`。

灯的第一次摆放全错：`part()` 会把组件重心归到最低点 z=0，我按世界高度写坐标，结果整盏灯被压到货架后面，窗外只看到格栅。改成从灯罩往上写，实例高度按「灯罩世界高度」给（5.16 米），灯泡落在窗带内才看得见。

## 一个连带问题

Gloss 槽恢复透明后，货箱盖跟着变透了 —— 它原本也挂在 Gloss 上。把 `cargo_crate` 的箱盖移到 `SEA_Metal`，Gloss 从此只承载玻璃。这条写进了 R37，避免以后再加一件 Gloss 件时又踩一次。

## 顺手修掉的两处测量问题

**浮店距阳光房的断言会随导入状态飘。** `floating-shop` 原来现场量阳光房 AABB 求中心，再要求浮店在其正南 50 米。但阳光房是 MultiMesh 装配，`MultiMeshInstance3D.get_aabb()` 在这个引擎版本里会随 multimesh 是否已重算过包围盒返回两种结果：同场景同帧数，一次得到中心 z=1.813（union 14.2×11.15），另一次 z=2.474（union 14.3×10.68），差 0.66 米刚好越过容差。带 `--import-assets` 就红、不带就绿。

改成锚在冻结基准 `(6.158222, 4.806684, 1.813078)` 上（这是 R35 定「正南 50 米」时的实测值），现场另留一条 ±3 米的实时冗余检查 —— 世界真位移照样会红，测量口径不再左右结果。

**`main.tscn` 里浮店实例的位移被改过。** 跑导入时发现实例 transform 从 `(6.158, -1.134, 51.813)` 变成了 `(0, -0.976, 57.983)`，同时一处 `ArrayMesh` 的 sub-resource id 被重命名。这不是本次改动，已 `git checkout` 还原并复验通过。编辑器打开场景时会重写 uid/sub-resource id，提交前必须看 diff。

**`dock-seed` 在 `--visual` 下会被判未通过。** 21 项断言全过（`[dock-seed] 21 checks, 0 failures`），
但退出时有 3 行引擎噪声：`10 RID allocations ... EnvironmentE were leaked at exit` 加两条
`Pages in use exist at exit in PagedAllocator`。在 HEAD 副本上跑同一检查（`--visual`）出现同样三行，
所以是引擎关机顺序的既有问题，不是本轮引入。不带 `--visual` 时是干净的 `PASS`。
