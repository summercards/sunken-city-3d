# 2026-11-09 90 秒玩法宣传片：实机录制 + 现做配乐

[主文档](../../GDD_V1.0.md#feature-control) · [分镜脚本](../../promo/分镜脚本_v4_实机90秒.md)

用户要求：以导演、测试员、玩家、摄影指导、剪辑师的身份接管游戏，**真实操作录制**，
按「强开场 → 核心体验 → 特色玩法 → 组合成长 → 高潮收尾」的叙事结构做一支 90 秒左右的
玩法展示片。重点是**玩法演示**，不是风景混剪，也不是操作录像。本文记录做法与实测，
不改任何玩法条款。

## 产物

| 文件 | 参数 |
|---|---|
| `promo/renders/sea_90s_1080p60.mp4` | 1920×1080 · **60 fps** · **90.017 s** · H.264 CRF19 + AAC 192k · 102 MB |
| `promo/renders/sea_90s_1080p60_share.mp4` | 同上，CRF25 + AAC 128k，约 40 MB |

母版帧数 5401（5400 帧时间轴 + 1 帧收尾），`--fixed-fps 60` 保证 5400 帧严格等于
90.000 秒，与机器性能无关。

## 没有外部录屏，也没有生成画面

沿用 v3 的通道，用 Godot 自带 Movie Maker 逐帧出图：

```
python scripts/build_promo_project.py --run-dir <工程外目录> --width 1920 --height 1080
godot --path <run>/project --resolution 1920x1080 --fixed-fps 60 \
      --write-movie out.avi --script res://tools/record_promo_90s.gd
```

`scripts/build_promo_project.py` 复用 `scripts/run_verification.py` 的隔离口径：
`custom_user_dir_name` 在 Autoload 构造前改写，`assets` / `terrain` / `.godot/imported`
用目录联接只读挂载，仓库 `project.godot` 不动。录完的用户数据目录留在 AppData，不递归删除。

`godot/tools/record_promo_90s.gd`（本次入库）是真实驱动，全部走玩家点得到的那条链路：

| 玩法 | 驱动入口 |
|---|---|
| 上/下船 | `_select_landing` → `_step_ashore` / _depart |
| 走到菜箱 | `_approach` → `actor_controller` 自动寻路 |
| 播种/浇水/收获 | `FarmPlot.perform("plant"/"water"/"harvest")` |
| 建造 | `building.begin` + `building.tick`（30 余帧施工条） |
| 打捞浮木 | `_press_sea_pick` → SAILING → GATHERING 三阶段状态机 |
| 下潜 | `_on_dive` → `dive.request_dive`，圆幕过场 |
| 珊瑚园探索 | `_visit_chest`（真实导航 A* + 3 秒搜索计时）→ `_open_chest` 发货 |
| 进屋 | `room_controller.enter` |
| 睡觉 | `_rest_for_day` |

没有瞬移角色，没有伪造奖励。幕与幕之间的船位是在**切镜内**摆的（观众看到的是「换了个地方」），
不是角色在画面里瞬移。

## 三处只为这段素材做的会话内调整

写在录制脚本里，不进正式代码：

- **船速 ×2.6**：`boat.speed_multiplier` 回调注入，只影响本进程。原速 2.6 m/s。
- **界面收敛**：「视野 x%」浮标（逐帧调机位会刷成常驻）与底部操作大卡片逐帧隐藏；
  建造段额外隐藏左上角 toast（每块板建成都会弹一次「拼接木板建造完成」，会连弹四次）。
  用 `RenderingServer.frame_pre_draw`，必须在节点 `_process` 之后、渲染之前改。
- **相机锁**：每帧重申一次目标/距离/方位，否则会被跟随逻辑、模态面板和过场 tween 抢回去。

另外两处用的是既有预览命令：`farm.debug_set_growth` 推生长（16 步）、
`building.tick` 推施工。

## 潜水段为什么去浅湾珊瑚园

用户要求「潜水拍浅水区、颜色好看」「要有操作和游历，不要进去就出来」。
实测后按以下三点定案：

1. **家园海底没有珊瑚。** 家园海底（`home_seabed`）是与海面同坐标的旧城，
   珊瑚与生态集中在 120 米深的街道面上；在用户指定的 **10–20 米**深度带里，
   只有远处楼体轮廓和几尾小鱼，画面偏暗。垂直扫掠 4/7/10/13/16/20/24 米
   八个机位逐张目视确认过（`sea-work/promo90/project/shots_hs2/`）。
2. **浅湾珊瑚园（`zone2`）才是彩色的那片。** 水深 11 米、紫粉珊瑚、水面光束、
   鱼群、两个宝箱，是唯一在浅水就有内容的潜图。
3. **它是真实可达的。** 家园锚点 60 米内的下水点一律归 `home_seabed`；
   开到锚点 60 米外、离横滨最近的水面，`_dive_source_at` 才命中 `zone2`。
   所以那一段是**真的开船出去再下水**，不是切图作弊。

潜水段的操作链：游动（`swim_to` 走真实路径）→ 从 11 米下潜到 17 米 →
自动导航游向「珊瑚花园宝箱」→ 搜索计时 3 秒走满 → 开箱 →
拿到「旧零件 +2 木料 +2」。中途珊瑚、光束、鱼群全程在画面里。

## 字幕

10 句，只在画面说不清的地方出现。**改用 ASS + libass 烧入**，不用 drawtext 链：
v3 那套 `drawtext` 链式转义在本次内容里直接报
`Invalid argument`（滤镜图解析失败），而 ASS 的 `\fad` 一个标签就解决淡入淡出，
字体走 `fontsdir` 指向工程内 `assets/fonts/`，与 HUD 同一套 Noto Sans SC。

## 配乐

工程里没有任何音频资产（`assets/` 下无 wav/ogg/mp3），配乐是现做的合成音轨
（`sea-work/promo90/make_score90.py`，无版权风险）：

- 粉噪低通成海，17 s / 6.3 s 两条正弦叠极慢起伏；
- C–Am–F–G 和弦垫，长起音、微失谐，按段落给 0.55–1.0 增益；
- 五声音阶拨弦 8 s 进入、40 s 上八度；
- **潜水段（56.5–68 s）拨弦跳到两个八度外、撤掉低音**，让水下安静下来，
  与珊瑚园的明亮画面错开；
- 78 s 起回暖，88 s 起淡出。

峰值 −1.0 dB、均值约 −14.6 dB。

## 已知取舍

- **没有音频素材，所以没有保留真实游戏音效。** SEA-SFX / SEA-MUSIC 两个功能都还是
  「规划中」，工程内没有任何音源，只能整条换成合成配乐。这不是剪辑选择，是资产缺口。
- **潜水只展示了一张图**（浅湾珊瑚园）。环礁深庭、北境裂谷、霓虹沉街花园的画面
  在浅水区都不如珊瑚园，且这次用户明确了「浅水、颜色好看」。
- **`zone3` / `sea_supply` / `rooftop_ranch` 的潜图加载失败**（`request_dive` 返回
  false），未进片；这是现有实现状态，不是本次改动引入。
- **霓虹花园、顶层牧场没进片**：主场景里它们的标高很低（Y=-21.7 / -55.9），
  在默认机位下要么只见水面要么只见墙。它们属于「存在但当前取景拍不出内容」。
- **建造段只有四块木板**，没有做完整的墙/屋顶/楼梯组合：一片 4 格的平台是
  90 秒里能讲清的体量，做整栋会把其他玩法挤掉。
- **UI 全部保留**：这是玩法演示片，HUD、面板、气泡都是内容。

## 复核清单

按用户给的自查项逐条核对：

| 检查项 | 结果 |
|---|---|
| 前 5 秒是否吸引人 | 低机位贴水面划向水上之家，第一秒就有动作和方向 |
| 15 秒内能否理解基本玩法 | 8.8 s 起走位 → 12.2 s 播种 → 15.6 s 浇水，15 秒时观众已看到「种地」 |
| 至少三个明确特色 | 海上自由扩建、水上下潜珊瑚园、昼夜窗光 + 室内房间 |
| 每个玩法是否展示真实交互与结果 | 是（见上表，全部走真实入口；打捞有进度条与 +7 木料，宝箱有掉落文字） |
| 是否有无意义重复镜头 | 无；同一动作不重复出现 |
| 是否体现成长与反馈 | 作物四阶段延时、木板逐块成形、宝箱掉落 |
| 看完是否想自己上手 | 收尾拉到大远景展示整座家，留「还会再扩建」的余量 |
