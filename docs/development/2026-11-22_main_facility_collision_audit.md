# 正式 Main 设施碰撞与组件归属复核

按 SEA-WORLD-R50–R52、SEA-MOVE-R44 和阳光房当前场景核对正式入口。对照项包括模型与碰撞的父子关系、角色场景碰撞、船壳碰撞、泊位及设施热区的归属。保留当前摆位。本轮交付为复核记录。

## 已确认的差异

| 设施 | 正式运行结果 |
|---|---|
| 霓虹花园 | 检修浮台有实体支撑，直梯两端通过落脚净空查询，折返楼梯抽查 22/22 有支撑。三个屋顶和花园桥的导航面仍启用，三座屋顶分别只有 2/28、2/18、4/38，花园桥 0/36 抽样点在导航高度上下 0.4 米内命中可站物理表面。对每处再取三个有可见表面的点，在导航高度上下 1.25 米做物理射线，12 个点均无碰撞。街口原走域已停用。 |
| 打捞台、升级渔场 | 角色和船都使用当前阶段启用的网格碰撞。打捞台模型和碰撞同挂在打捞台实例下，渔场碰撞挂在渔场实例下。共用泊位、船位和船壳触发区仍属 zone1 的 `WalkAreas`，收鱼热区在 zone1 的 `Objects`，绞盘与升级牌由 Main 装配。单独移动任一模型实例时，这些触发区域不会随之移动。 |
| 横滨铁道 | 站台和检修跳板都有实体碰撞。横滨整个区块跟随摆放，泊位仍挂区块，站台模型合并碰撞挂在 `Models`，调整单个站台模型实例不会使合并碰撞和泊位一起更新。东站台抽样 33/34 命中可站物理表面，剩余点待实走确认。 |
| 浅水养殖台 | 平台和培养木甲板有实体，六格菜箱有自己的交互节点，泊位仍是区块级。移动整个区块时跟随，单独移动主要平台模型时，区块泊位、菜箱和聚合网格碰撞由各自节点持有。 |
| 浮店 | 甲板、墙体、船体阻挡、泊位和补给柜台都在同一设施根内。浮动更新同步移动模型、碰撞、泊位触发区和柜台，停船点高度单独贴水。甲板抽样 44/44 命中实体。 |
| 顶层牧场 | 牧场根内有泊位、末段楼梯、屋面、护栏和家具阻挡。登岸、屋面及楼梯抽样结果 48/48 命中，未逐条实走。 |
| 屋顶街机铺 | 西侧甲板和底座承担角色与船的碰撞，泊位随设施。覆盖西侧甲板的声明范围，室内和阁楼未纳入玩法开放范围。 |
| 阳光房卧室 | 进门和返回入口分别随室外阳光房与室内实例；房间启用后地板抽查 6/6 命中实体，退出时禁用碰撞。 |
| 旧驿站、普通建筑 001 和 002 | 景观职责，三处均用随模型摆位的船体网格碰撞，无角色承重和泊位。船壳扫掠通过。 |
| 工坊摆放样例 | Main 内仍有标为候选的海风公寓实例，碰撞仅在 256 层，正式岸上玩家和船的掩码均不读取。无正式泊位。 |

区块散布的绳索、零件、玻璃以及养殖台采集点采用自身 Area3D，运行时仍挂在全局 `GatherField`。它们的逻辑与统一交互一致，摆放归属仍用区块坐标。相较阳光房手工碰撞盒，其他设施较多使用随场景装配的离线网格碰撞，正式角色和船同样由 Godot 物理处理。已登记的固定设施区块在当前运行态均未发现 GroundSpace 派生的地板或边界物理体，既有 WalkArea 和 BlockerSet 仍为导航与布置等查询提供数据。
