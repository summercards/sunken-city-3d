# 2026-11-09 填充率归因：不改画面还能拿回多少帧

[主文档](../../GDD_V1.0.md) · [本机帧预算诊断](2026-11-09_frame_budget_m1.md) · [上一轮帧诊断](2026-11-07_frame_diagnosis.md)

## 1. 先更正上一轮的结论

`2026-11-09_frame_budget_m1.md` 用 `--script` 探针测得 8.6 FPS，并判断瓶颈在绘制批次。**这个判断不成立**，原因有二：

- `--script` 模式下测到的帧时偏高。同一台机器、同一个隔离工程，用正常游戏循环（`--print-fps`）测得 **16 FPS**，是脚本探针的两倍。脚本探针的绝对值和排序都不适合当画质决策依据。
- 把三块「散件大户」整块隐藏（`rooftop_ranch/Models` 760 件、`floating_shop/Models` 381 件、`sunken_city/Models` 388 件）后，帧率**一点没变**（16 → 15/16）。它们多半在 31° 视锥之外，本来就被剔除。

因此绘制批次不是瓶颈。下面全部改用正常游戏循环测量，1600×1000 逻辑分辨率（Retina 2× → 3200×2000 framebuffer）、Metal 3.2、Forward+、Godot 4.7.2、Apple M1。

## 2. 边界数据

同一工程，只改窗口分辨率（`--resolution`，200 帧后取稳定中位）：

| 逻辑分辨率 | 实际 framebuffer | FPS |
|---|---|---:|
| 640×400 | 1280×800 | 35 |
| 800×500 | 1600×1000 | 31 |
| 1280×800（当前） | 2560×1600 | 16 |
| 2560×1600 | 5120×3200 | 9 |

帧率与像素数近似反比：像素翻四倍，帧时翻两倍多。**这是填充率/带宽瓶颈的典型指纹**。

## 3. 逐项归因（基线 16 FPS / 66 ms）

| 改动 | FPS | 变化 | 说明 |
|---|---:|---:|---|
| 基线 | 16 | — | 3200×2000、4× MSAA、SSAO、glow、8192 阴影 |
| **隐藏水面 `World/Water`** | **27** | **+69%** | 单项最大，约省 25 ms |
| **关 4× MSAA** | **20** | **+25%** | 约省 14 ms |
| 隐藏 `rooftop_ranch` 植被 MultiMesh | 16 | 0 | 植被不是瓶颈 |
| 隐藏三块散件 Models | 15–16 | 0 | 视锥外，白测 |
| 阴影 8192 → 4096 且距离 220 → 90 m | 17 | +6% | 只降 size 无效 |
| 关 SSAO | 16 | 0 | 已半分辨率 |
| 关 glow | 16 | 0 | — |
| 关去色带 | 8.4（脚本模式） | 0 | 无影响 |
| 每帧天空 / 水面 / 环境材质写入全部停掉 | 16 | 0 | 属性 setter 有值比较 |
| Vulkan（MoltenVK）后端 | 13 | −19% | 比原生 Metal 慢，不用换 |
| 3D 缩放 0.85（bilinear / FSR1） | 18 | +13% | 两者一致 |
| 3D 缩放 0.70（bilinear / FSR1） | 23 / 22 | +44% | 画面开始变柔 |
| 隐藏水面 + 关 MSAA | 33 | +106% | 上限参照，不可用于正式版 |

水面和 MSAA 两项相加就解释了 66 ms 里的 39 ms：**全屏透明混合 + 屏幕纹理折射 + 深度纹理采样，叠在 3200×2000 的 4× MSAA 上**。

`shaders/water.gdshader` 的 `render_mode blend_mix, depth_draw_never, cull_disabled`，并同时读 `hint_screen_texture`（折射）与 `hint_depth_texture`（吸收/泡沫水线）。这三点决定了它必须全屏混合、无法 early-z、且每帧要复制一次屏幕。

## 4. 「不改画面」能拿到的组合

按实测单项收益排序，从"几乎看不出"到"看得出"：

| 档 | 做法 | 预计 FPS | 画面代价 |
|---|---|---:|---|
| A | 关 4× MSAA，改 FXAA（`screen_space_aa=1`） | ~20 | Retina 下 2× 密度，边缘略软，几乎不可辨 |
| B | + 3D 缩放 0.85 + FSR1 | ~22 | 2240×1400 上采样，仍然高于逻辑分辨率 |
| C | + 阴影 4096 / 90 m | ~23 | 远处阴影略软 |
| D | 3D 缩放 0.70 | ~30 | 明显柔化，属于"降画质" |
| E | 水面拆「不透明主体 + 透明泡沫层」 | 未实测，估计 +8–12 ms | 理论上零差异，需要改 shader 架构 |

A+B+C 是唯一能既不破坏观感、又把 16 拉到 22 左右的组合。要到 30+ 必须进 D 档或做 E 的重构。

## 5. 结论

**没有既完全不动画面、又能让这台 M1 跑顺的开关。** 现在的 16 FPS 里，水面与 MSAA 是硬成本：

- 水面是设计上就要全屏透明 + 折射的，除了重构分层没有零代价解法；
- 4× MSAA 在 Retina 3200×2000 上是纯带宽税，换 FXAA 能拿回 14 ms 且几乎看不出。

真要做 E（水面分层）值得单独开一轮：不透明主体进 opaque 队列后可以 early-z、可以省掉屏幕复制，是唯一有希望把帧时压到 40 ms 以内的零画质路线。

