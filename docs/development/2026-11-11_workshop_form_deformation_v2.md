| 问题 | 上一轮状态 | 这次 |

| 幅度太小，开了像没开 | 12m 三层楼 4° 上限只有 2.1%，SF-C 也只有 1.87% | 倾角上限可调（默认 8°），默认幅度 3–6%，SF-C 到 9.4% |

## 上限为什么有两个

结构收分写进 `taper` 字段，而 `taper` 的合法范围是 0–0.10（`recipe.validate` 的硬约束）。所以：

```
可用收分 = min( tan(θ)·H_total / max(W,D) ,  0.10 )
             └── 墙倾角限制 ──┘   └ 字段硬上限 ┘
```

12×9m、3 层、层高 3.6m（总高 10.8m）实测：

| 倾角 θ | 倾角允许 | 实际可用 | 谁在拦 |
|---|---:|---:|---|
| 4° | 0.0629 | 0.0629 | 倾角 |
| 8° | 0.1265 | 0.1000 | taper 字段 |

**这个必须分开报。** 上一版只报"上限 0.0629，可调大 max_tilt_deg"，用户把倾角从 4° 调到 8° 后仍被拒（因为撞上 0.10 字段上限），会以为倾角参数没生效。

拒绝文案现在分两路：

- 被倾角拦：「结构收分上限 0.0629（墙宽 12.0m、总高 10.80m、墙倾角上限 4.0°），structure.max 须不大于该值或调大 max_tilt_deg」
- 被字段拦：「结构收分上限 0.10（taper 字段合法范围 0..0.10 为硬上限，当前倾角 8.0° 还能放到 0.1265），structure.max 须不大于该值」

编辑器读数也同步：倾角允许值超过 0.10 时标注「；taper 上限 0.10」。

## 窗洞逐列取号

```gdscript
static func opening_rho(recipe: Dictionary, column_key: String) -> float:
    var magnitude: float = ...  # 区间 + seed 落值，和 rho 同一条逻辑
    var sign_mode: String = str(entry.get("sign", "positive"))
    if sign_mode == "mixed":
        sign_mode = "negative" if unit_noise(seed, "opening_sign|" + column_key) < 0.5 else "positive"
    return -magnitude if sign_mode == "negative" else magnitude
```

`column_key` 是 `立面_序号`，**不含楼层**。这一点不是细节——如果按「立面_层_序号」取号，同一竖列的上下窗会各掷一次骰子，立面读成随机噪点；按列取号，一列上下同向，才是手作感。

实测（12×9m、3 层、seed 11010）：18 列上窄、24 列上宽；真实玻璃上窄 8 片、上宽 15 片；同列上下同向核对 15 对全通过。

## 上宽下窄的几何坑

`pull` 之前是 `maxf(0.0, rho) * w * 0.5`，永远非负。改成允许负值后，三处会破：

**1) 网格挖空范围。** `_face_grid` 用 `_hole_rect` 建挖空矩形（下沿矩形）。上沿外扩时，扩出去的部分落在挖空矩形之外，网格会把它重新补成墙——洞口上沿被墙盖住，看起来像窗被切顶。

修法：新增 `_hole_bounds()`，取「下沿矩形 ∪ 上沿梯形」的并集，挖空和墙垛/开间校验都用它。

**2) 墙面补角方向。** `pull > 0` 时补的是洞口肩部上方的两块三角（矩形洞比梯形洞宽出来的部分）。`pull < 0` 时宽出来的是下沿，得补下方两块，顶点完全不同。

```gdscript
if pull > 0.0:
    _tri(左下, 左上, 左下+pull@上)      # 上部左侧
    _tri(右下, 右下-pull@上, 右下)      # 上部右侧
else:
    _tri(左外, 左外@上, 左下)           # 下部左侧
    _tri(右外, 右外@上, 右下)           # 下部右侧
```

**3) 墙垛与开间校验。** 用 `hole.x0/x1`（下沿）校验时，上沿扩出去的部分可能越过墙角或与相邻窗相撞。新增 `reach = max(half, half - pull)`，校验一律按 `cx ± reach`。

`validate_bay` 同步按 `-pull` 外扩。

## 一个被误判成 bug 的现象

近景特写里，中间有一个「宽窗」，玻璃分成两半、中间一条细木档。第一眼像两个洞口被挤到一起。

查了：那是同一洞口的**活动扇**（`shell_window_geometry._sash_hole`），窗类型不是 `fixed` 时会额外生成一扇。关形体时同样存在，与本次改动无关。

相邻窗实际间距：`cx = -4.46 / -1.49 / 1.49 / 4.46`，净宽 1.5m + 框，窗间墙约 1.2m，没有相撞。

## 还没做的

- **宽扁低层楼仍拿不满幅度。** 8° 下 12m 三层楼可用 0.126，但 taper 字段封顶 0.10；更宽扁的（如 20m 宽两层）倾角限制会低于 0.01 的语法下限，此时开形体也不会有可见变化。当前只拒绝超上限，**没有主动提示「下限不可达」**。
- `accessory` 只接了雨棚柱变径和雨棚板自由边收窄；花池、水塔、招牌尚未生成，无从接入。
- 窗只做梯形，不做歪斜/旋转（skill 明确禁止结构件倾斜）。
- 不签建筑承载、受力计算、土木结构安全。
