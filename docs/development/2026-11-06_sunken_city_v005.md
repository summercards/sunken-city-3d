# 沉没旧城 v005：连续海床、鱼群与海鸥

[主文档](../../GDD_V1.0.md) · [世界规范](../features/world/spec.md) · [资产规范](../features/asset/spec.md) · [环境表现规范](../features/ambient/spec.md)

## 用户修订

用户明确否定 v005 第一版在城市外围追加道路/坡块的方案。原 40 个 `edge_ramp_*` 实例已撤下；v004 仍保留，v005 恢复为原城市 **388 个实例**，不改变原有道路、建筑、桥梁、电车、用户手动摆位和 `World/SunkenCity` 根 Y=`43.487442`。

本轮改为使用 Terrain3D 在城市模型下方铺连续海床：中心托住现有地坪底部，城市边缘外保留 12m 平台，再用 96m 连续缓坡下降到世界 Y=`-62m`。海床是独立 `World/SunkenSeabed`，纯视觉、无碰撞、无水面阻挡、无导航和交互职责。

## 制作与数据

- 官方 Terrain3D v1.1.0，下载包 SHA-256：`51b78bc758f5759cbc8eaaab14e5cf4e8661717e265fdd760f5abf945f15b243`。
- Godot 4.7.2 Forward+，插件通过 GDExtension 加载；验证所需 `.godot/extension_list.cfg` 已纳入隔离 runner。
- 海床水平采样：`STEP = 2m`，4 个 256×256 region，覆盖 `[-512,512)`；全部 262144 像素写入，0 个未写入 0 高度像素。
- 真实地坪采样来自 `SunkenCity` 100 个 `aligned_ground_domain` 的三角网格；不从旧 JSON 反推用户摆位。
- `collision_mode = 0`；海床场景 metadata 标记 `visual_only=true`、`water_layer=submerged`、`water_layer_role=none`、`blocks_water=false`。
- 海床材质为 Terrain3D 自定义无纹理着色器，不改全局海水材质、海面高度或吸收参数。

## 鱼群与海鸥

阳光房周边新增 3 个纯装饰鱼群变体：6 条近群、10 条中群、14 条外扩群。鱼群使用现有鱼体和水面采样，只消费水面，不注册捕捞、库存、经济或存档状态。

在确实突出水面的建筑上增加两组海鸥：阳光房、屋顶牧场。海鸥只在 06:00–18:00 运行，使用同一 `WorldClock`，夜间关闭根节点和鸟的 process；不接建筑玩法状态。

## 生活循环边界

本轮完整集成 runner 中，收获/仓储链的 `minimum-loop` 曾出现 10 项失败。随后执行了视觉节点因果对照：移除 `SunkenSeabed`、鱼群和两组海鸥后，失败标签、141 项检查数和 10 项失败完全一致。因果报告：

`D:/projects/sea-work/sunken_city/v005/import/minimum_loop_baseline.json`

根因是工作树另一事务对 `farm_plot.gd` 的改动：成熟作物也被 `use_action_menu` 截断为 `options`，没有进入 `harvest()`。这不是本轮海床/鱼群/海鸥造成的回归；本轮不修改该玩法文件，也不把 minimum-loop 失败写成通过。

随后独立当前 minimum-loop 报告恢复为通过（147 checks / 0 failures），但该结果来自并行工作树的玩法状态变化，登记证据保留上述因果对照，不宣称本轮修复了种植系统。
