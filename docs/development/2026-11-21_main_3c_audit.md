# 2026-11-21 正式 Main 3C 与移动复核

检查对象为当前工作区默认 F5 的 `main.tscn`，包含阳光房 1.6 和船壳靠泊触发区。审计使用工作区快照，未修改运行实现。

## 正式入口的问题

- `main.gd` 的 `_uses_scene_ground()` 在返回后还有初始化代码。这段本应由 `_setup_actor_controller()` 执行。实际 Main 探针确认镜头面板输入门禁、划桨状态端口、船升级速度端口、交互可达性端口及 GameState 到角色的模式同步均未绑定。交互完成回调、船升级解锁、上岸补水监听也处在不可达块。
- 陆地物理和存档采用了不同的通行范围。阳光房一处甲板物理射线命中 `SurfaceCollision`，使用真实 `save_game` 写隔离槽位时返回 `Saved player is outside walkable ground`。读档恢复还会调用旧 `surface_point` 调整位置。
- 海面也有同类差异。船壳扫掠未碰撞的一处水面，实际保存返回 `Saved boat is outside navigable water`。存档仍调用 `WaterNavigation.is_geometric_water` 检查船中心，并使用旧轮廓外扩。
- 家园点击地面已关闭，若干可交互菜单仍执行旧的自动接近命令。`ActorController.approach` 在家园直接返回失败，`_approach_command` 因此不会提交选中的业务命令。该点为源码链路确认，未做 UI 操作验收。

## 仍参与运行的旧分支

- 普通陆地走法按当前登记泊位切换。只有 `zone1/main` 启用场景碰撞。绞盘泊位、其他设施与室内仍有 `WalkArea` 和 `GroundSpace` 生成的物理支撑及边界，并可走旧点击与键盘通行判定。动态建造、NPC 和存档也还有查询消费者。
- 家园下船走实际船壳与 `DockingArea` 重叠。其余泊位的下船和家园上船仍查泊位距离等条件。手动船走 `FormalHullMotion`。`Boat` 的旧推进和航线仅在无正式船壳分支执行，Main 的远程自动航行入口返回失败。旧水面查询另有存档及建造消费者。
- 家园潜水实际移动由碰撞运行时执行胶囊扫掠。九张既有海底场景仍实例化 `underwater_world.gd`，通过 0.12 米子步、地图边界、地形及障碍查询更新 `diver_pos`。正式潜水控制器还消费各图自己的点击路径。
