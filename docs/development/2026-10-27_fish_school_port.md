# 鱼群与巨鲸移植：网页版模型与动画进 Godot，配色去脏，单群散开

日期：2026-10-27 起，第三轮修订 2026-10-28。功能：SEA-AMBIENT / SEA-PICKUP / SEA-ASSET。

[主文档](../../GDD_V1.0.md) · [SEA-AMBIENT 账本](../features/ambient/ledger.md) · [SEA-PICKUP 账本](../features/pickup/ledger.md)

## 用户提出的要求

第一轮：

1. 水里新加的那只鱼很难看 —— 把网页版的鱼模型和动画都搬进 Godot。
2. 新加的鱼群颜色很脏 —— 参考网页版的颜色。
3. 单个群体里的鱼太拥挤 —— 散开一些。

第二轮（看图反馈）：

4. 鱼群里的每只鱼还是太大 —— 小一倍。
5. 旁边那只大的（鲸）也要换成网页版的。

第三轮（看图反馈）：

6. 鲸颜色太深，好像没被海水深度影响。
7. 小鱼群数量太多。
8. **不要改可捕捞鱼群的大小** —— 现在太小了。

## 结论先行

三轮反馈合起来是七个独立缺陷，逐条改掉（前三条是第一轮的，后四行是第二、三轮的）：

| 现象 | 真正原因 | 修法 |
|---|---|---|
| 鱼"很难看" | Godot 侧的鱼是 `SphereMesh` + `PrismMesh` 拼的，只有身体和尾巴，没有眼睛、没有背脊，也没有摆尾；体型还是宽 > 高（俯视像叶子） | 模型按网页版逐件重建，分段网格烘进最终尺寸；动画移植轨道巡游 + 切线朝向 + 尾鳍摆动 |
| 颜色"很脏" | 三层叠加：① 旧色板本身偏褐（`#e8603f` 一族）；② 鱼被放在水面 +0.04 m，Godot 浪高 ±0.29 m，整条被半透明水膜盖住洗白；③ 环境后处理 `adjustment_contrast=0.75` 把颜色往中灰压 | 色板按网页版色相提纯；鱼抬到浪峰之上（`RIDE_LIFT=0.42`）；水面群去掉俯视时会盖满整条鱼的奶白背斑 |
| 单群"太拥挤" | 网页版 6 条鱼共用同一个圆心、只靠相位错开，俯视看就是一个旋转木马环；Godot 装饰群更糟，18 条撒进 ±1.2 m 方框 | 每条鱼给独立地盘：抖过的黄金角螺旋 + 两两互斥迭代 |
| 鲸"没被海水影响" | 漏了网页版 `makePainterlyMat(color, {}, true)` 的第三个参数，也就是整条深度染色链路 | 改走 `toon.gdshader` 的 `depth_tint`，并补两个可选 uniform 把强度调到可读 |
| 小鱼群"太多" | 18 条小鱼挤在同片地盘里，俯视是一片密不透风的小点 | 水面群降到 10 条，巡游半径与最小间距都改成随 `size_scale` 缩放 |
| 可捕捞群"太小" | 上一轮把装饰群和交互目标用同一个缩小倍数处理了 | `SIZE` 回到 1.0；装饰群才缩小 |
| 水下鱼像"一根棍/一张叶子" | 宽高比写反了（宽 0.13 > 高 0.09），网页版是宽 0.18 > 高 0.26 | 改正为薄 0.09 / 高 0.13 / 长 0.28 |
| 鱼还是太大 | 网页版把相机贴得很近，同一尺寸在 Godot 的俯视机位下占屏更多 | 水面群与可捕捞群统一 `SIZE = 0.5`，抬升量同步按体型收 |
| 鲸像一根灰青香肠 | 上一版多塞了网页版没有的椭球腹块、椭球尾鳍、球状眼，尾段也做成了椭球 | 按网页版构件表重建：头球 + 躯干球 + 两块 Box 胸鳍 + 圆锥尾段 + 一块 Box 尾鳍 |

## 模型与动画（`godot/src/ambient/animal_mesh.gd`）

网页版有两套鱼，形状不同，硬套一套就会读错：

- **水面**（`web/fish-schools.js`）：扁胖型，半轴 宽 0.17 / 高 0.11 / 长 0.30，俯视看背宽侧薄，符合鱼形。
- **水下**（`web/underwater-art.js`）：细长型，半轴 薄 0.09 / 高 0.13 / 长 0.28，长轴朝前。

两者统一转到"鼻尖朝 +Z"，尺寸按最终大小烘进网格（`SurfaceTool.append_from`），实例矩阵只负责位置和朝向。零件：椭球身体、背脊高光（只有水下群有）、双眼合成一份网格、三角尾鳍（根部为枢轴）。

尾鳍的形状抄自网页版 `ConeGeometry(0.16, 0.34, 5)` —— 截面近似**圆形**，这是关键性质：俯视和侧视都能看到一片扇形。两个"看起来更合理"的改法都实测失败过：

| 尝试 | 结果 |
|---|---|
| 压 Z 成水平薄片 | 侧视只剩一根针，鱼像箭 |
| 压 X 到 0.26 成竖直薄片 | 俯视看不见尾巴，整条鱼像颗豆子 |
| 最终：压 X 到 0.75 | 略薄像鳍，但任何角度都看得见 |

动画（`decorative_fish_school.gd::sample`）：每条鱼绕自家小轨道做椭圆巡游，朝向取轨道切线，尾鳍按 9 rad/s 摆，身体随摆尾侧倾，头部小幅摆。水面群额外跟随 `water_surface.sample_surface()` 的同一套波场。

绘制用 4 个 `MultiMesh`（身体 / 背脊 / 双眼 / 尾鳍），尾鳍单独一份实例矩阵，否则摆尾摆不出来。

## 配色（`decorative_fish_school.gd`、`fish_school_visual.gd`）

色相照网页版，明度/饱和度按 Godot 的成像链路反向补偿。这是实测出来的，不是配色偏好：

| 用途 | 网页版 | Godot 采用 | 依据 |
|---|---|---|---|
| 水面装饰群 | `#7fd6c9` 一族（薄荷青） | `#1fd0b8` / `#3fdcc2` / `#17c0a9` / `#5fe6cd` / `#12b3a2` | 原 hex 在 ACES + 曝光 1.17 下贴顶，屏幕读数变成 `#a8c8c0` 灰绿；压明度提饱和后回到干净青绿 |
| 水面可捕捞群 | `#ffc55c` / `#f19c4a` / `#66dcf2` / `#cd8fea` 六色 | `#ff5f3d` / `#ffc21a` / `#ff6fae` / `#2fe3c8` / `#2fb8ff` / `#97df3c` | 同上；旧版偏褐一族出水就是土黄/橄榄，这才是"脏" |
| 水下群 | 同网页版四色轮换 | `#ffa726` / `#e0712a` / `#2fb6e0` / `#a865d8` | 水下多了深度雾洗色，需要比水面更深一档 |

材质：toon 漫反射 + 关高光 + `cull_back`；自发光只用于抵消水色吸收（水面 0.16、水下群经 `uw_materials.from_color` 注入）。给多了整条鱼会抬成灰白 —— 这是实测过的失败路径。

## 第二轮：体型减半与巨鲸

### 鱼缩小一半

`SIZE = 0.5`（`fish_school_visual.gd`）/ `size_scale = 0.5`（`surface_animals.tscn` 三条水面群）。

改体型有个连带项：**抬升量必须跟着收**。原来固定 0.42 m 是按"浪峰 0.29 + 全尺寸半高 0.11"推的；鱼缩到一半后如果还抬 0.42，整群会浮在离水面 30 cm 的空中。所以改成按体型算：

```gdscript
const RIDE_LIFT := 0.29 + 0.11 * SIZE + 0.02   # 0.29 是浪峰，不能压
```

`decorative_fish_school.gd` 的 `water_lift` 现在默认 0 = 自动，等价于同一个公式。

### 尾鳍形状（本轮最大的坑）

鱼缩小之后暴露出：旧尾鳍是"轴向朝后的小圆锥"，俯视看只剩一根尖刺，整条鱼读成叶子。这里连错三版，最后才定：

| 尝试 | 俯视读成什么 |
|---|---|
| 轴向朝后的圆锥，半径 0.155 | 一根尖刺，鱼像叶子 |
| 圆锥压 X 成 0.26（竖直薄片） | 看不见尾巴，鱼像豆子 |
| 三棱柱躺平，外接圆半径 0.24 | 一块比鱼身还宽的菱形 |
| **显式三角网格：顶点接身体，尾端向两侧张开到半宽 0.19** | 鱼尾 ✓ |

另外：薄片三角形没有背面，材质必须 `CULL_DISABLED`，否则从下方看是空洞。水下群仍用圆锥（侧视机位，侧面看到的就是三角扇）。

### 巨鲸换成网页版

网页版 `web/gameplay.js` 1249–1305 的构件表：

| 件 | 网页版 | Godot |
|---|---|---|
| 头 | `SphereGeometry(1.35)` × (1.05, 0.82, 2.2)，z=1.6 | 同参数（半径 1 球 × 1.4175/1.107/2.97） |
| 躯干 | `SphereGeometry(1.42)` × (1.0, 0.85, 2.4)，z=-0.8 | 同参数 |
| 胸鳍 ×2 | `BoxGeometry(2.6, 0.14, 0.85)`，外撇 0.35、下压 0.25 | 同参数 |
| 尾段 | `ConeGeometry(0.95, 3.6, 10)`，尾枢轴 z=-3.2 | 同参数 |
| 尾鳍 | `BoxGeometry(3.4, 0.14, 1.1)`，尾鳍枢轴 z=-3.3 | 同参数 |
| 皮肤 / 鳍色 | `#062356` / `#16589e` | 同 |
| 描边 | `#2ec4e8`（躯干）、`#52e8ff`（尾鳍），22% 不透明线框 | 同色，改用 grow 描边 |

巡游与摆尾也照网页版：椭圆轨道（半径 8×3）、0.16 rad/s、垂直起伏 0.65、`tail.rotation.y = sin(t·2.1)·0.28`、`fluke.rotation.x = cos(t·2.1)·0.35`。

两处 Godot 侧的适配（数值都写在导出变量上，可调）：

- **自发光 0.18**。`#062356` 是近乎黑的深蓝，纯吃光会变成一块黑影；但给到 0.5 以上整条鲸变亮蓝色，完全不是"深海暗影"了。
- **描边用 `grow` 而不是整体缩放**。按比例缩放在细长构件的短轴上几乎无效，描边会被本体整片盖住 —— 实测第一版就是这样，描边等于没画。改成 `cull_front + grow_amount = 0.10 m` 才看得见。

## 第三轮：鲸的水下染色、水面群减量、可捕捞群恢复原尺寸

### 鲸"没被海水影响"的真正原因

不是参数不够，是**材质走错了链路**。网页版给鲸材质传的第三个参数是 `true`：

```js
const whaleMat = makePainterlyMat('#062356', {}, true);   // ← 第三参 = 开深度染色
```

那个 `true` 会挂上 `enhanceWithUnderwaterDepthShader`，也就是"按水深把物体混成水色"。
上一版把鲸做成了 `StandardMaterial3D`，这条链路整个不存在 —— 于是水下 4.5 m 的鲸
还是一片死蓝，这正是"好像没被海水影响"的字面原因。

现在改走项目已有的 `toon.gdshader`：它的 `apply_depth_tint()` 就是照网页版那套
四层色梯 + absorb 混色 + 浅水焦散写的，参数名也一致（`depth_tint` / `water_level`）。

### 为什么还加了两个 uniform

`toon_common.gdshaderinc` 原本只服务沉没城市的建筑，有两个隐含假设对鲸不成立：

| 原行为 | 对建筑 | 对鲸 |
|---|---|---|
| `absorb × 0.56` 固定力度 | 亮 albedo，混 19% 水色就看得出 | `#062356` 近黑，混完还是黑 |
| 额外 `uw_glow` 自发光补偿 | 需要，否则水雾里看不见体量 | 会把它抬成一块发亮青板 |

所以补了两个 uniform，**默认值都等于原行为**（既有材质零影响）：

```glsl
uniform float depth_tint_strength = 1.0;  // 染色力度倍数
uniform float uw_glow_amount = 1.0;       // 自发光补偿倍数
```

鲸取 `depth_tint_strength = 2.0`、`uw_glow_amount = 0.60`、`ambient_boost = 0.55`。
这组数不是拍的，是四组实拍扫出来的：

| ambient / tint / glow | 观感 |
|---|---|
| 0.12 / 1.5 / 0 | 一团黑，看不出是鲸 |
| 0.35 / 1.8 / 0.35 | 仍是深色剪影，几乎读不出水色 |
| **0.55 / 2.0 / 0.60** | **深青蓝、看得出体量、像隔水看** ✓ |
| 0.75 / 2.4 / 0.85 | 洗成发亮青板，比水面还亮 |

### 水面群减量 + 地盘按体型收紧

- 条数 18 → 10（`surface_animals.tscn` 的 `count`）。18 条挤在同片地盘里是一片密不透风的小点。
- **巡游半径改成随体型缩放**：`orbit_radius × size_scale`。原来是写死的 2.4×1.3 m，
  鱼缩到一半后单条鱼的游程就盖住整个地盘，群被拉散成沿水面的散点。水面群现配 0.84–0.98 m。
- 地盘半径 4.0–4.4 → 0.92–1.02 m。
- **最小间距改成随体型缩放**：`0.60 m × size_scale × 1.70`。

第二条是关键。上一轮把间距写死 1.0 m，鱼缩到一半后间距相对体型翻倍，10 条小鱼
摊在 4 m 地盘里就成了点缀水面的散点 —— 这是"太散"和"太挤"会互相转化的原因：
**间距要相对体型，不是相对世界**。

### 可捕捞群恢复原尺寸

`fish_school_visual.gd` 的 `SIZE` 从 0.5 改回 1.0。理由：这是玩家要靠近、要点的目标，
缩小后既难辨认也难点中。配套改动：

- 抬升量自动跟着回到 `0.29 + 0.11×1.0 + 0.02 = 0.42`（公式本来就是这个设计）。
- 地盘半径 1.45 → 1.35，最小间距 1.05 → 1.15 —— 与放大后的体型配套；
  涟漪圈按 `RING_RADIUS = (SPREAD×1.16 + ORBIT_MAX)/0.72` 自动跟随，不手填。

装饰群与可捕捞群现在尺寸不同，这是**有意分化**：一个是背景氛围，一个是交互目标。

## 单群散开

`Geometry.school_offsets(count, radius, squash, min_gap, rng)`：抖过的黄金角螺旋给初值，再做最多 12 轮两两推开，最终最近间距不小于 `min_gap`。同一个 rng 序列结果确定，读档可复现同一片鱼群。

| 场景 | 条数 | 地盘半径 | 最小间距 | 体型 |
|---|---|---|---|---|
| 水面装饰群 | 10 | 1.5–1.65 m | 0.6×0.5×1.7 ≈ 0.51 m | 0.5× |
| 可捕捞群 | 3–6 | 2.00 m | 1.30 m | 1.0× |
| 水下群 | 18 | 6.2 m | 0.6×1.0×1.7 ≈ 1.02 m | 1.0× |

涟漪圈半径不手填，由鱼群外沿反推：

```gdscript
const RING_RADIUS := (SPREAD * 1.16 + ORBIT_MAX) / RING_INNER_RATIO  # ≈ 3.14 m
```

因为 `surface_ripple.gdshader` 画的是节点半径的 55% 和 72%（最外扩散弧到 95%），
想让它"刚好包住鱼"，节点半径得除以 0.72。拿鱼群半径直接当节点半径，鱼会压在圈线上 —— 这是实测踩到的。

## 需要记一笔的两个坑

**`sample_surface()` 的高度在返回向量的 `.x`，不是 `.y`。** `.y`/`.z` 是坡度。旧可捕捞鱼群用 `.y` 给鱼定位，等于把坡度当高度用，鱼上下乱跳。

**鱼必须浮在浪峰之上。** Godot 浪高合计约 ±0.29 m，网页版把鱼放在水面 +0.04 m。直接搬过来会被半透明水膜整条盖住 —— 屏幕上就是"发白、发脏"，而不是"看不见"。`RIDE_LIFT = 0.42`（浪峰 0.29 + 扁胖型半高 0.11 + 余量）。

### 本轮修掉的一条失效断言

`selftest` 的「环境亮度是标定值」原本直接对比 `we.environment.ambient_light_energy == 0.36`。
日照系统（`src/rendering/daylight_rig.gd`）接入后，这个值每帧被写成 `基准 × 时段系数`，
所以任何非 09:00 的时段都会失败（实测 0.32 @ 06:00）。这条不是本轮改动引起的，
但它会长期飘红、掩盖真回归，所以改成两步验：

1. 基准仍是标定的 0.36（`daylight_rig.base_of("env", "ambient_light_energy")`）；
2. 运行时值确实等于 `基准 × 当前时段系数`（`daylight_rig.phase(hour).ambient_energy`）。

这样既保住了"资源里的标定值不许漂"，也允许时段变化，两条都是真的能失败。

作用域要分开跑：`minimum-loop` 是刻意锁死的最小版本专项，只开家园水域并禁用潜水；用 `--full-world` 跑它必然大面积失败（本轮就先踩了一次，42 条红项全部来自作用域错配，不是回归）。同理 `decorations` / `selftest` 的潜水与全图断言需要 `--full-world`。

`visual-fish-schools` 是新加的专项（`godot/tools/capture_fish_schools.gd`）。加它的理由：鱼群是"看得见才算过"的资产，而旧测试只有一条"鱼在动"的断言 —— 于是椭球拼的鱼、被水膜洗白的颜色、共心挤成一圈，全都能通过。新专项把肉眼才发现的每个问题变成一条会失败的断言（现共 81 条）：

- 水面群必须是扁胖型、取网页版色板、饱和度 > 0.5；
- **水面群每群 ≤ 12 条**（"小鱼群数量太多"）；
