# 2026-11-08 周边可打捞密度减半（鱼群与浮木）

主人反馈：**周边的可打捞的鱼和木材数量太多了，减掉一半。**

本轮只改数量密度，不改打捞流程、奖励档次、补货节奏与存档结构。

## 1. 改了什么

`godot/src/pickups/ocean_population.gd` 新增 `KEEP_PERCENT := 50` 与两个函数：

- `_keep_quota(count, cell)` —— 这一格这一类资源留几个；
- `_thin(result, cell)` —— 按坐标与日次确定性筛掉多余的槽位。

`_make_cell` 在 `_make_base_cell` 之后立刻 `_thin`，因此**容量（每格生成几个）不变，留下的数量减半**。选这个做法而不是把 `crate_count 9 → 4`、`school_count 7 → 3`：

1. 槽位编号不变。旧存档里 `missing` / `harvested` / `wood_yields` 记的 `x:y:wood:6` 仍然指向同一格同一束，不会变成孤儿记录，也不会因为编号空间收缩而让某条冷却记录突然对上新束。
2. 鱼群的随机流在 `_make_base_cell` 里已经跑完，筛减只删点、不改点 —— 满足 R14／R17「不得为了筛减重排或重抽鱼群」。
3. 家园那 6 束、外海那 30% 都还是原来的算法，只是基数先砍一半。

## 2. 数量公式

设某格某类资源容量为 `n`，日次为 `cycle`：

```
scaled = n × 50
quota  = ⌊scaled / 100⌋
若 posmod(cell.x + 3·cell.y + cycle, 100) < scaled % 100  →  quota += 1
```

整数余数按坐标与日次交替，不做统一向下取整（9→4 是 44%，十格就少一成）：

| 容量 n | quota | 占原 |
|---|---|---|
| 4（最小循环鱼群） | 2 | 50% |
| 6（最小循环浮木／家园） | 3 | 50% |
| 7（正式鱼群） | 3 / 4 交替，平均 3.5 | 50% |
| 9（正式浮木） | 4 / 5 交替，平均 4.5 | 50% |

外海木材在减半之后**再**乘既有的 30%（R14 不变），所以十个开阔格：

```
60 束 → 减半 30 → ×30% → 9 束（原 18 束的 50%）
```

保留哪些槽位不看插入顺序，而是按 `slot + ":thin:" + cycle` 的散列排序后取前 `quota` 个。否则浮木永远占本格前半段、鱼永远压在后半段，同一天回访同一格会看出「一边挤一边空」。读档、卸载回访、日更同种子同结果，跨天才重排。

家园格原本就在 `_make_cell` 里清空外海木、再按 `0:0:wood:i` 补满，本轮把补的数量从 `wood_count` 改为 `_keep_quota(wood_count, HOME_CELL)`，6 束 → 3 束。`_add_home_wood` 的避让参考点也改为筛减后的鱼位，否则按满编 4 群/格避让、实际只有 2 群，家园木会放不满。
