# sea 植被视效制作规范 · v1

[主文档中控](../../GDD_V1.0.md#sea-ambient) · [选型与实现方案](../features/ambient/vegetation_visual_plan.md) · [功能账本](../features/ambient/ledger.md) · [美术功能规格](../features/asset/spec.md)

2026-11-05 制定。PC 优先。**以下为待实现的统一生产契约，不代表已经存在导出器、shader 或示例资产。** 参数与工具在样板验收后冻结为 v1.0；实施状态不得在本页重复维护。

## 1. 管理边界

后续制作植物必须先读 SEA-AMBIENT 的规格/账本、本规范与场景组件 Skill。功能规格拥有需求，规范拥有生产协议，功能账本记录实施与证据；资产主记录仍从 `assets/registry/ledger_index.json` 解析所属域。装饰植物归 scenes，四阶段作物归 crops；不另建一份相同资产主表。

共享能力只建一次：风函数、光照函数、通道定义、实例数据写入、分块规则和验证入口。新植物一般只增加几何/权重、已有 profile 的参数和实例布局，不能复制一份 shader 或控制器到新套件。出现新能力时扩展公共能力并回归旧消费者。

源码主导的职责仍按既有规则：正式场景持有摆放；植物不焊进建筑或容器；升级/生长由原玩法所有者写入；纯装饰不生成碰撞、导航、交互或存档状态。已有 AssetID、ContentID、稳定 PackedScene 路径不因换表现而改名。

## 2. 制作前分类

每件先选择一个主 profile：`broadleaf`、`flower_stem`、`grass`、`reed`、`moss_fuzz`、`water_leaf`、`submerged_foliage`；静止覆盖用 `ground_cover_static`。profile 是表现类型，不代替资产分类或建筑职责。

按既有场景 Skill 判断实际 building_class；非建筑新资产不强行归类。现存植物若登记为所属建筑的部件，先保留原记录并按原规则核验，不凭名称批量清空。海下观赏建筑子树只能观赏；独立潜水地图另行验收。

在 `component_plan.json` 冻结轮廓、尺寸、根部锚点、材质角色、面数、LOD、权重方案、碰撞职责和引用消费者。优先 2–3 个轮廓变化，同色变化不新增几何。单套件不超过 50 个组件；复用现有件先查 AssetID，计划阶段不向资产分账本登记不存在的源文件。

## 3. 网格与风格

| 类型 | 初始制作指引 | LOD 策略 |
|---|---|---|
| 草簇 | 3–7 片不等高、略弯、圆端或柔尖草叶；高度建议 0.12–0.35 m；每片约 2–4 个纵向弯曲段；一簇起始预算 24–60 三角面 | 中景 8–24 面并减密度；远景依托覆盖基底 |
| 苔垫 | 低矮、不规则起伏与软轮廓；建议厚 0.02–0.08 m；单片初始 80–240 面 | 静止底层保持，远景简化轮廓/法线 |
| 苔绒 | 约 0.01–0.04 m 的短绒/小叶簇；重点放轮廓、断口与近景；单簇 12–24 面起步 | 像素不可辨时退出；不为远景堆绒 |
| 宽叶簇 | 片形圆润、有主曲面和叶尖；一簇起始预算 300–1,200 面，按现有主角植物例外登记 | 显式中/远 LOD；不能为少量节面毁掉叶形 |
| 花茎/蒲草 | 瘦长但有分段；花头用大色块，茎基部固定 | 远景保留花色点与整体剪影 |
| 荷叶 | 实体不透明叶面、少量厚边，枢轴与水面接触合理 | 避免过密透明叠片；远景保留大圆叶轮廓 |

这些数值是样板预算，不覆盖历史资产的已批准尺寸/面数。正式面数按修改器求值后三角面记录，展示面数不能用 N 边面蒙混；需乘实际可见实例统计。草簇不能大量使用低于一个像素宽的针叶。

Godot 为 +Y 向上，Blender 为 +Z；沿用 `(x,y,z) -> (x,z,-y)`。母版根/网格变换恒等、底心原点、Collection.instance_offset 为零。挂墙、藤蔓等不是地生根的件，另写 attachment/root 信息，不能用世界高度算根尖权重。基础转换烘到网格一次；实例仅允许正向等比缩放，非等比/负缩放须先离线烘入并复核法线/枢轴。

### 3.1 颜色、UV 与材质角色

- 公共色板源保持 `art_source/shared/palettes/` 唯一；按资产原族使用既有 8×8 色板及正式运行纹理，不擅自复制或改旧色格。
- `PaletteUV` 为活动/渲染 UV，导出到 `TEXCOORD_0` / Godot `UV`。每面 UV 有面积、单格内至少 8 px 安全边，取样 nearest；不会拿 UV0.y 当根尖高度。
- 仍属 `SEA_Matte` 角色；运行时允许共享植被 ShaderMaterial 实现该角色，不增加“每种绿一个材质”。叶片不启用 Emission 角色来造假背光。
- v1 主几何无 alpha。确有细叶卡需求时，另登记 UV2=`DetailUV` 和共享遮罩 atlas，颜色仍由 UV0 色板决定；遮罩线性过滤、mipmap 与色板过滤分开。此类例外逐资产记录与验收，不反向改所有植物的 UV。
- 有细节卡的资产 UV2 不再用于光照烘焙；v1 动态植被不依赖 LightmapGI UV2。若将来需要，两者冲突先升级通道协议，不静默覆盖。

### 3.2 顶点通道协议 `sea_vegetation_v1`

| 数据 | 语义 | 默认/范围 | 使用约束 |
|---|---|---|---|
| COLOR.r | 主弯曲权重：根/木质部 0，柔软尖端趋于 1 | 0–1 | 根环、花盆、泥土和刚性果实置 0；按附着链绘制，不只按世界 Y |
| COLOR.g | 叶尖/叶缘细动权重 | 0–1 | 叶柄附着处为 0；苔垫整面为 0，短绒单独设置 |
| COLOR.b | 每叶/每分支相位种子 | 0–1 | 同叶内部恒定；相邻叶片不同；不能逐顶点乱噪产生撕裂 |
| COLOR.a | 静态 AO/根部柔和明暗 | 1 为无遮蔽 | 仅送入受控 AO/颜色函数，**不写 ALPHA**；不可烘死阳光方向 |
| UV0 | 公共色板 | 原 PaletteUV | 不改用途 |
| UV2（可选） | 细叶卡遮罩坐标 | 无卡可省略 | 必须在 manifest 声明，缺失不得静默读取 UV0 |

顶点色为数值属性，按线性数值导出；避免 sRGB 转换改坏权重。旧模型如用顶点色表达真实颜色，不能原地重写：先保留旧 shader 路径，迁移源到 PaletteUV 或单独版本化的兼容入口，再写风权重。现有旧烘焙植物 `BakeStore` 的 toon 路径属于这一类风险，不能批量猜测 COLOR 是权重。

源文件中保留属性名 `WindData`，GLB 检查实际输出是否为 `COLOR_0`，Godot 再检查 ARRAY_COLOR 值域。导出器不支持时判失败，而非以“模型能显示”通过。自动生成权重只能给简单竖直草簇初值；叶柄、垂藤、分枝必须校正连接处。

v1 是低幅度柔性弯曲协议，不含逐叶三维枢轴。若某大叶在上限幅度仍明显拉伸，先调整拓扑/降低细动，必要时将叶片作为可复用子件；复杂枝条枢轴动画属于另一个版本，不私自占用颜色或 UV 通道。

### 3.3 实例数据协议

`MultiMesh.use_colors=false`，以免实例色乘入 COLOR 破坏权重。`use_custom_data=true` 在 `instance_count` 前设置；`INSTANCE_CUSTOM` 四个浮点数约定如下：

| 分量 | 语义 | 解码 |
|---|---|---|
| x | 稳定实例相位 | `phase01 × TAU` |
| y | 小幅色调变化种子 | 0–1 经 profile 映射成有限亮度/色相变化，不直接当 RGB |
| z | 柔度倍率 | 直接线性倍率，默认 1，允许 0–1.5 |
| w | 实例生长/表现权重 | 默认 1，0–1；由原所有者的离散生长事件更新 |

这里的 Color 容器只储存四个数，不做颜色空间转换。稳定相位由资产和布局实例 ID 的固定散列生成；不能依赖运行时节点分配顺序。对独立 MeshInstance 采用等义的 per-instance uniform，两个小包装 shader 共用同一风函数；若兼容后端不支持相应绑定方式，使用单实例 MultiMesh 或静态降级，并单独验证。

冠幅、静止包围盒和最大位移由 profile/资产清单提供，不滥用自定义四通道。草生长若已通过外层 scale 表现，w 不能再次缩放造成平方生长；两个路径择一，由适配器声明 `growth_binding`。

## 4. 风、材质与安全包络

世界风使用静止世界坐标采样；局部权重使用未变形模型坐标。风向正确转换到植株局部，避免旋转实例各吹各的风；同块相邻植物共用宏观风，实例相位只扰动细节。顶点偏移限制在 profile 的 `max_displacement_m`，并将限制后的最大值计入 AABB。

主体摇摆与细动在公共 include 定义，所有 pass 同相位、同变形。法线随弯曲正确更新；正反面、朝向 0/90/180/270°、等比缩放 0.5/1/2 都验证。已验收包装才开启风，缺权重的旧资产默认静止或走原旧动画，不能全白 COLOR 导致根部跟着飞。

全局 uniform 仅由风控制器写；共享材质的 uniform 只能代表 profile 层级。单株差异写实例数据，不 `duplicate()` 出上千份材质。新材质在既有 material guard 使用的基线表登记必要纹理/参数，冷启动、保存与重开核验参数未丢。实际材料覆盖必须写到 MeshInstance 的 surface 或 MultiMesh；检查 sunny_palette_binding/sunny_bloom_visual 是否在之后覆盖它。

PC 主方案不写透明 ALPHA；需要裁切卡时独立小 shader 使用 Alpha Scissor。alpha-to-coverage 仅作 Forward+ / MSAA 条件下的可选样板，不假设所有后端等效。水下卡片、LOD 过渡必须对两套水面渲染检查。法线柔化、轻背光和根尖明暗参数集中于 profile，不使用常亮发光作弊。

## 5. 散布、布局与分块

布局由正式 TSCN 引用的 `VegetationLayout` 资源拥有。手工点位与 Scatter 输出都进入同一协议；编辑器配方是可追溯来源，运行时不同时读取配方来覆盖布局。

每片按设施/楼层/水域职责独立生成局部变换：允许区 → 排除门/路/梯/种植格/泊位 → 表面投射 → 坡度过滤 → 密度和轮廓分布 → 小幅随机旋转/尺度 → 稳定实例 ID → 分块。只重建选中的 patch，不碰别的建筑 TSCN。

允许表面与排除区由场景作者显式定义或从玩法所有者的公开查询导出；运行时不扫描 Main/Economy 内部字段。可移动平台的草随所属设施局部变换移动。多楼层要约束投射起点、射线长度与目标层，防止屋顶草掉到下层。

如果使用 Scatter：锁定 commit；默认约 6 m 块另加楼层隔离；关闭静态碰撞；优先只给单 mesh/单材质的纯视觉植物。编辑器投射代理只存在制作场景，正式输出无代理/RID/插件节点。禁止保存与重开自动改变正式布局。

中立导出器至少校验 seed 重建一致、四通道保真、变换精度、材质角色、实例数、分块范围及所有权。插件 cache 只存变换，不作为完整正式交付。输出应引用原共享 Mesh，不因分块复制网格。

### 5.1 布局资源字段（规划）

| 字段 | 约束 |
|---|---|
| schema_version / layout_id / feature_id | 协议版本；稳定布局身份；SEA-AMBIENT |
| owner_scene / facility_id / attachment_slot | 唯一正式消费者与局部坐标基准 |
| coordinate_system / units | Godot Y-up / metre；不能混入 Blender 坐标 |
| recipe_path / generator_version / plugin_commit / seed | 来源追溯；手工布局也说明来源 |
| source_asset_ids / source_hashes / profile_ids | 从主资产记录解析；实际核验后填哈希 |
| surface_mask / exclusion_mask / layer_id | 离线输入引用；水面/楼层规则明确 |
| instances | 稳定 instance_id、AssetID、完整 Transform3D、custom_data |
| chunks | 分块键、实例范围、静止 AABB、扩展后 AABB、LOD/阴影策略 |
| expected_counts / generated_hash / status | 重建比对与验收状态；不拿输出哈希接受未知源变更 |

制作配方保存在 `art_source/vegetation/layouts/<区域>/v###/`，正式中立布局保存在 `godot/assets/data/vegetation/layouts/`，主场景只引用稳定资源。两者是来源/消费关系，不是两份都可写的当前摆放。

## 7. 清单与资产账本字段

扩展原 `asset_manifest.json` 的 `vegetation` 字段，初始建议如下；正式 schema 与导入检查在 P1 一起实现，当前不往现有资产伪填这些值：

```json
{
  "vegetation": {
    "schema_version": 1,
    "attribute_layout": "sea_vegetation_v1",
    "profile_id": "broadleaf_calm",
    "growth_binding": "owner_scale",
    "root_anchor": [0, 0, 0],
    "rigid_parts": [],
    "lod_meshes": [],
    "max_displacement_m": 0.04,
    "material_role": "SEA_Matte",
    "alpha_mode": "opaque",
    "detail_uv": null,
    "collision_policy": "visual_only",
    "verification_status": "pending"
  }
}
```

示例的 0.04 m 仅示意，不可抄到所有植物。正式清单还须由已有字段或扩展字段记录：源/优化源/GLB/包装路径及真实哈希、尺寸、分 LOD 顶点/三角面/surface 数、色板路径、属性值域、法线策略、最大位移、轮廓预算例外、消费者、来源/授权、源验收/接入/视觉/性能状态和证据。

新建资产先由总索引路由并查重；原件升级保留 AssetID，几何职责变化确需新件才申请新 ID。共享 shader/profile 是公共代码/资源，有唯一维护路径与版本；需要资产登记的贴图/网格分别归所属域，不靠复制“组件专用材质”解决记录问题。

授权、运行验收、性能任一未知则该维度 pending；功能已实现不自动提升资产授权。禁止批量更新未知源/运行哈希。

## 8. 一件新植物的标准流程

1. 从 GDD → SEA-AMBIENT/SEA-ASSET 读取当前契约，解析分账本并查找同族复用件；选择 profile、消费者和空间职责。
2. 写组件计划；建模或从明确版本派生。独立保存优化源，保留用户母版。
3. 完成 PaletteUV、WindData、法线及 LOD；根、木质部、容器和果实逐项检查。
4. 保存后重开母版和独立包，检查坐标/变换、UV 安全区、属性、材质与面数；导出 GLB 并回读核对。
5. 用统一包装绑定共享材质/profile；检查实际渲染网格上的覆盖未被旧绑定器重写。新件不复制 shader/风脚本。
6. 小样中测静止/微风/阵风和近中远；通过后手工或 Scatter 布置，导出中立布局；根位置与道路/水线核验。
7. 通过统一 runner 专项及受影响集成，保留原生截图/录屏、性能采样与退出码；记录未执行项。
8. 更新唯一资产主记录、原功能账本、开发记录和派生索引；运行 feature contracts 的 `--sync` 与无参数检查；任何无关漂移单列。

## 9. 验收清单与复用完成定义

| 层次 | 必须能发现的错误 | 证据 |
|---|---|---|
| 源/导出 | UV0 被挪用、COLOR 丢失/错误转换、根权重不为 0、非等比变换、少分段、超预算 | 重开记录、属性统计、GLB/Godot 数值对照 |
| 风/渲染 | 根滑动、所有草同步、各方向乱吹、花盆跟着动、叶缘拉伸、背面发黑、阴影不跟动 | 固定 seed/phase 多帧与真实录屏；至少一个故意错误样本被拒 |
| 场景 | 楼层投错、穿墙、漂浮、阻挡/导航多出来、退出潜水后植物消失 | 正式消费者与空间查询；检查插件潜在 RID，不只看节点 |
| 性能 | 每株 `_process`、材质重复、全图一个 AABB、风摆出界消失、过密透明层 | 节点/资源计数、边缘镜头、GPU/CPU 基准与压力档 |
| 生命周期 | 重建重复、卸载泄漏、生长两次缩放、暂停继续跳相位、读档重抽布局 | 加载/卸载循环、等级/保存恢复、固定 seed 布局校验 |
| 管理复用 | 第二个植物重写 shader、换插件就不能运行、布局与配方互相覆盖 | 用至少两种植物、两个区域复用同一公共风/材质；无插件冷启动 |
