# 主文档驱动的工程管理规范

[返回主文档](../../GDD_V1.0.md#feature-control)

## 唯一事实来源

| 对象 | 编辑主源 | 汇总/消费方 |
|---|---|---|
| 产品目标、全局规则、功能范围和关系 | GDD_V1.0.md | 功能文档、运行实现 |
| 单功能规则、接口与验收要求 | docs/features/<功能>/spec.md | 对应 ledger.md、代码、测试 |
| 单功能实施状态与证据 | 同目录 ledger.md | 主文档状态摘要、生成索引 |
| 物品/作物/订单数值 | 各自运行配置或明确登记的现有所有者 | UI、业务查询、内容索引 |
| 资产生产登记 | assets/registry/ledgers/<域>.json | 源索引、功能账本、生产工具 |
| 一次交付事实 | docs/development/<日期>_<主题>.md | 功能账本的证据链接 |

`docs/generated/feature_index.json` 是从主文档与功能账本生成的只读投影。更新命令是 `python3 scripts/check_feature_contracts.py --sync`；它只同步摘要和索引，不自动改玩法、实现状态或资产哈希。普通检查发现不一致必须失败。

## 功能划分与接口

本次主文档登记 31 项功能。完整种植经营链作为一个功能，播种、浇水、生长、收获分别有条款，其他功能同理。若后续要把某步骤独立管理，先变更主文档功能清单，再分离文档与账本，保留原 ID 的迁移记录。

模块目录用于代码职责；一个共享服务仍承载多个功能时，账本必须说明当前所有者与未拆部分，不能宣称完全解耦。场景/控件通过接口调用规则；规则不依赖 UI、主场景或特定场景树形状。FarmModel 与 OrderBoard 通过显式 ports 在添加到场景树前配置。

## 目录职责

- `godot/src/`：正式代码，按职责分目录；`godot/tests/parity/`：旧规则镜像。
- `godot/scenes/`：正式可编辑场景；`godot/assets/`：正式运行资源及现有配置，暂保留稳定路径。
- `web/`：网页原型全集，内部自洽——`index.html`、`*.js`、`ui.css`、`vendor/`（three.js）、`refs/`（原画参考）、`web/tests/`（网页回归）、`web/tools/`（CDP 调试）。静态服务以 `web/` 为根，页面 URL 保持 `/index.html`。
- 根 `art_source/`：制作源；根 `assets/registry/`：登记；根 `assets/art/shared/`：制作共享色盘。
- 根 `scripts/`：工程门禁与验收；`godot/tools/`：Godot 生产与导出工具；`tools/blender/`：美术管线。
- 根 `tests/tooling/`：跨端工程门禁自测（契约、false-green 防护），不属于网页版。
- `docs/archive/`：拆分前原文，不参与现行状态检查；原文相对路径按原位置理解。
- 工程外 `sea-work/`：候选重生成、日志、测试快照、截图及发行产物。

## 生成和手工编辑

`build_zones.py`、`build_underwater.py`、`build_models.py`、`build_plants.py`、`build_plots.py`、`build_zone_scenes.gd`、`make_scene_resources.gd` 必须在候选副本运行。先执行 `python3 scripts/create_generation_candidate.py`，再在输出目录运行原构建器。候选不得用硬链接或可写符号链接连接正式资源，当前工具使用独立文件复制。

已审阅的资源逐文件接入，必要时保留原场景的手改层。候选标记不能复制回正式工程。该保护针对上述会重写资产/场景的工具，不表示所有旧制作脚本已经完成统一迁移。

## 验收与状态

`planned`=尚未实现，`partial`=目标/实现/独立性/验证尚未全部闭环，`implemented`=正式路径具备且仍可能有专项待验，`verified`=对应目标条款已有最新完整证据，`blocked`=有明确阻碍。整体状态不自动根据一次测试变成 verified。

结构检查：`python3 scripts/check_feature_contracts.py`。运行回归：`python3 scripts/run_verification.py core`。无主场景无 Autoload 的正式规则专项：`python3 scripts/run_verification.py modules`。单项名称还包括 farming、surface、click、management、camera、ocean、selftest、parity。真实渲染检查包括 visual-farming、visual-management、visual-click、visual-underwater-depth、visual-underwater-capture；也可用 `--visual`，不能拿 headless 图片当证据。

runner 每轮建立唯一 project 和用户目录，复制代码与场景，复用只读资源和导入缓存；自动存档、日志、截图均不触及玩家槽位。日志退出码和完成标记都必须通过，只有 selftest 允许至多一次精确坏 JSON 预期诊断。超时计为失败。
