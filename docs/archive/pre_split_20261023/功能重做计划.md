# 功能重做计划

> 版本：v0.1 · 2026-10-19
> 目标：把sea 的玩法功能**按 Godot 的方式重新实现**，不再把网页版的 JS 逐行翻成 GDScript。

---

## 0. 为什么要重做

现有 Godot 工程是在两周内"把网页版搬过来"的产物：

- 数据层是网页版数值表的直接拷贝（`economy.gd` 的资源变量、建造费用）；
- 交互是网页版 DOM 图标的翻译（把所有可点目标投影到屏幕，按像素距离命中）；
- 表现是烘焙好的静态网格，行为靠每帧轮询；
- 没有存档、没有音频、没有引导、没有可扩展的物品定义。

它能跑、画面也对，但每加一个功能都要在 `main.gd` 里加分支，且无法脱离网页版的数据结构思考。
从这一版起，功能按下面的原则重做。

## 1. 重做原则

1. **先定玩法，再定实现**：写清"玩家做什么、得到什么反馈、失败会怎样"，再写代码。
2. **世界里的东西是节点**：可交互物、资源、建筑都是场景节点，不是屏幕上的图标或全局表里的一行。
3. **数据与逻辑分离**：数值进 `assets/data/*.json` 或 `.tres`，逻辑进脚本；改数值不该改代码。
4. **用 Godot 的惯用法**：信号而不是轮询、`Resource` 而不是字典、`AnimationPlayer` 而不是手写插值、
   `NavigationAgent3D` 而不是自己写寻路（海面 A* 保留，因为水面不是导航网格）。
5. **每个功能自带验收**：headless 断言 + 一张实机截图 + 一段可复现的操作路径。
6. **允许和网页版不一样**：只要更好玩、更清楚。画面风格保持一致，机制不必一比一。

## 4. 功能 1：交互与采集（已完成）

### 玩法

- 走到物件旁 2.4m 内出现焦点环与底部提示：`[E] 采集 · 海贝`。
- 按住 E 读条（不同资源 0.9~1.8 秒），松手或走动即中断。
- 采完物件缩小变暗、信号珠熄灭，进入冷却（55~130 秒），到时原地恢复。
- 部分采集点有建造前提（如铁道站的玻璃需要车站 2 级），未满足时提示原因。
- 同距离下 `priority` 高的先被选中；朝向只影响排序，不构成硬门槛。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/interactable.gd` | 可交互物基类：焦点环、`focus_text()`、`can_interact()`、`interact()` |
| `scripts/core/gather_spot.gd` | 采集点：资源类型、产出、冷却、前提、程序化造型与信号珠 |
| `scripts/core/gather_field.gd` | 从 `assets/data/gather_spots.json` 生成，统一抛 `collected` |
| `scripts/core/interactor.gd` | 玩家侧探测器：扫描、焦点、长按、走动打断 |
| `scripts/ui/interact_prompt.gd` | 只显示当前焦点的提示条与进度 |
| `tools/build_gather_spots.py` | 从行走矩形与烘焙 AABB 求解空位，生成摆放表 |

### 数据契约

`assets/data/gather_spots.json`：

```json
{"id": "zone1_shell", "zone": "zone1", "kind": "shell", "amount": 2,
 "x": -1.8, "y": 2.15, "z": 10.5, "priority": 2,
 "requires_site": "yokohama_station", "requires_level": 2}
```

- 坐标是**世界坐标**，`y` 必须等于所属 `walk[].y`；
- 每个点必须落在所属区块的某个 `walk[].rects` 内（自检会逐点断言）；
- 新增资源类型只需在 `GatherSpot.KINDS` 里加一条（标签/颜色/造型/冷却）。

### 与旧实现的差异

| 旧 | 新 |
| --- | --- |
| 所有可点目标投影到屏幕，按像素距离命中 | 世界里只有物件本身，焦点由空间关系决定 |
| 点一下立刻进账 | 按住读条，走动打断 |
| 无限刷 | 枯竭 + 原地再生 |
| 无前置条件 | 可绑定建造等级 |
| 新增资源要改 UI/HUD/经济三处 | 只加一条数据 |

## 5. 功能 2：资源与背包（已完成）

### 玩法

- 按 **Tab / B** 打开面板，默认是「背包」页：`背包 7 / 24 格`，每样东西一格（按堆叠上限分格），
  空位画成暗格，超出可视范围显示 `+N`。
- 货币（海贝）不占格，单独一行常驻。
- 装不下时产出不会静默消失：底部提示 `背包已满 · 木料×3 没能装下`。
- 「建造」页与背包同面板，成本直接显示成图标 + 数量，按钮按「材料是否够」自动灰显。

### 实现

| 文件 | 职责 |
| --- | --- |
| `assets/data/items.json` | 物品定义：id / 名称 / 图标 / 分类 / 堆叠 / 售价 / 颜色 / 描述 |
| `scripts/core/item_db.gd` | 静态读表；未知 id 回显 id，不让 UI 出空白 |
| `scripts/core/inventory.gd` | 账本：`add/remove/pay/missing`、格数计算、`to_dict/from_dict` |
| `scripts/ui/backpack_grid.gd` | 背包页渲染：有货的格子 + 空位 |
| `scripts/economy.gd` | 只留规则；资源经 `inventory` 读写，旧属性做兼容层 |

### 数据契约

- **加一种物品只改 `items.json`**，不用动 HUD/经济/费用文案。
- `stack` = 每格上限；`stack: 0` 表示不占格（货币）。
- 存档 `{"capacity":24,"counts":{...}}`；读档按物品表过滤，**删掉的物品不会让存档报错**。

### 与旧实现的差异

| 旧 | 新 |
| --- | --- |
| 9 个 `var wood: int` 散在 economy.gd | 一份 `Inventory` 账本，唯一真源 |
| 新增资源要改 4 处（变量 / add 分支 / HUD / 费用文案） | 只加一条数据 |
| 无容量概念，随便装 | 24 格上限，按堆叠分格，满了给明确反馈 |
| 扣除不是原子操作 | `pay()` 不足则一件不扣 |
| 无存档接口 | `to_dict/from_dict` 已就绪，过期物品自动忽略 |
| 顶部资源条写死 5 项 | 按「货币 + 手里最多的 4 样」动态生成 |

### 顺手修掉的既有缺陷

`build_models.py` 的 `detail` 单元被生成了两次（锚点命中一次、兜底又一次），
两个同名 glb 互相覆盖，manifest 与文件对不上。另外清单里的包围盒是用「实例原型 AABB」
累加的，细长斜管会把尺寸撑大一倍——现在改成按**真实顶点**计算。
`apply_unit_plan` 也不再被重复定义两次。

## 6. 功能 3：建造与升级（已完成）

### 玩法

旧版是「面板里点一下就升级」：材料够就瞬间完成，等级只是一个数字，世界里什么都看不见。
现在建造是一条**有时长的流程**：

1. 每个可升级的建筑旁立着一块**施工牌**（世界里真实存在，有焦点环）；
2. 走近按住 **E** 交付材料，一次扣齐、缺一件都不开工，并直接告诉你缺什么；
3. 交付后牌子换成琥珀色、立起警示围栏、旁边堆上木料与木箱，开始**真实倒计时**
   （木屋 18s / 30s、铁道 22s、农场 20s / 34s，写在 `SITES[id].seconds`）；
4. 走开、关面板、去别的区块，施工照常推进——计时在规则层，不在节点里；
5. 到点竣工：等级 +1，围栏与材料收起，牌子闪一下。
6. 「建造」页变成台账：每个点的等级、下一级费用、施工进度与剩余秒数，按钮从「升级」改成**「前往」**
   （点一下把镜头挪到那块牌子，真正的施工要在世界里做）。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/build_site.gd` | 建造牌：造型、焦点文案、`interact()` 交付、施工中的现场（围栏/材料） |
| `scripts/core/build_field.gd` | 从 `assets/data/build_sites.json` 生成，转发 `work_started` / `finished` |
| `scripts/economy.gd` | 规则：`begin_site_upgrade()`（扣材料、记工期）/ `tick_sites()`（倒计时、升级）/ 进度查询 |
| `scripts/hud.gd` | 建造页台账，逐行更新进度但不重建整页（否则按钮焦点会丢） |
| `tools/build_build_sites.py` | 从行走矩形 + 烘焙 AABB 求空位，生成摆放表 |

### 数据契约

`assets/data/build_sites.json` 只描述**位置**，费用与工期仍在 `Economy.SITES`：

```json
{"id": "home_cabin", "name": "太阳能木屋", "zone": "zone1",
 "x": -1.6, "y": 2.1, "z": 8.2, "yaw": 0.0}
```

- 牌子必须落在所属区块的 `walk[].rects` 内、`y` 等于该 `walk.y`（自检逐块断言）；
- 与采集点至少隔 2.2m——否则两个目标会同时进交互半径，按 E 抢焦点（第一版就撞了）；
- 牌子四角 1.0×0.6m 内不能有建筑，否则会插进墙里。

### 两段式状态机

```
site_work = {}                    待施工
begin_site_upgrade(id)  →  pay(cost) + site_work[id] = {left: s, total: s}
site_work_progress(id)  →  0..1   （HUD 与焦点文案都读它）
tick_sites(dt)          →  left 归零 → site_levels[id] += 1 → site_work.erase(id)
```

- 等级在**竣工时**才变，施工中读 `site_level()` 仍是旧等级；
- 施工进度写进 `to_dict()/from_dict()`，读档接着倒计时；
- `Economy.ticking = false` 可关掉自动推进，测试按固定步长手动 `tick_sites()`。

### 与旧实现的差异

| 旧 | 新 |
| --- | --- |
| 面板点一下，瞬间升级 | 世界里交付材料 + 真实倒计时 |
| 世界中没有建造点 | 每个建筑旁有施工牌，有焦点环与状态色 |
| 等级只是个数字 | 待施工 / 施工中 / 满级 三种状态，造型与文案都跟着变 |
| 关掉面板就看不到进度 | 建造页实时进度 + 剩余秒数，镜头可一键跳转 |
| 材料不够只灰按钮 | 明确提示缺哪几样、缺多少 |

## 7. 功能 4：种植与温室（已完成）

### 玩法

旧版菜箱在面板里，只有一条「湿度」数字，作物写死成一种，浇水就是点按钮。

现在菜箱是世界里的一只木箱，**状态长在箱子上**：

| 状态 | 看到什么 | 按 E 做什么 |
| --- | --- | --- |
| 空地 | 浅色干土 | 播种（消耗 1 颗种子，种的是面板里选中的作物） |
| 生长 | 土变深、作物分三段长大 | 湿着时只是「查看」，告诉你还差几秒 |
| 缺水 | 叶片发黄下垂、土变浅 | 浇水（一次浇满，继续长） |
| 成熟 | 果实微亮 | 收获，产出入背包 |

关键设计：**缺水只是停长，不会枯死**。这是刻意的——玩家离开一段时间回来，看到的是「它还在等你浇水」，
而不是「你毁了一茬」。惩罚留给真正的风险（背包满、没种子），不留给时间。

一茬要浇好几次水：番茄 46 秒长成、一次浇水只维持 18 秒，所以中途至少回来两趟。
温室把生长缩到 0.72 倍、每次浇水多维持 30%、每茬多收 1 份主产物。

### 实现

| 文件 | 职责 |
| --- | --- |
| `assets/data/crops.json` | 作物表：id / 名称 / 种子 / 生长秒 / 浇水维持秒 / 产量 / 颜色 / 描述 |
| `assets/data/plots.json` | 菜箱位置与前置（工具生成，世界坐标） |
| `scripts/core/farm.gd` | 规则：播种 / 浇水 / 生长 / 收获 / 温室加成 / 存档（`FarmModel`） |
| `scripts/core/farm_plot.gd` | 世界里的菜箱：造型、四段生长、土壤干湿、焦点文案 |
| `scripts/core/farm_field.gd` | 从 `Economy.farm.specs` 生成菜箱节点 |
| `scripts/hud.gd` | 「种植」页：选作物 + 每块地实时状态 + 「前往」 |
| `tools/build_plots.py` | 行走矩形 + 烘焙 AABB 求解位置，避开建筑 / 采集点 / 建造牌 |

### 数据契约

- **加一种作物只改 `crops.json`**；产量引用的物品必须在 `items.json` 里（自检逐条校验）。
- 生长与浇水是**两个独立的量**：`remaining` 只在「还有水」的时间里减少，`water` 按真实秒数减少。
  这样大步 `tick()` 也不会把湿润期整段吞掉。
- 存档 `{selected_crop, plots:{id:{crop, remaining, total, water}}}`；读档时表里没有的菜箱/作物会被忽略。
- 温室只影响 `grow_seconds()` / `thirst_seconds()` / `yield_of()` 三个查询，不改状态结构。

### 与旧实现的差异

| 旧 | 新 |
| --- | --- |
| 菜箱只存在于面板 | 世界里真实的木箱，有接触阴影与焦点环 |
| 湿度是一个数字 | 土壤颜色 + 叶片姿态直接表达干湿 |
| 只有一种作物 | 三种作物（生菜 / 番茄 / 南瓜），面板里切换 |
| 点一下浇水，看不出生长 | 分阶段造型、缺水停长、成熟发光 |
| 温室只是「时间变短」 | 更快 + 更耐旱 + 多收一份 |
| 无存档 | 作物、进度、水分都进存档 |

## 6.5 功能 6：航行与靠泊（已完成）

### 问题

移植版原来把航行写成「起点 smoothstep 到终点」：位置永远在一条直线上。
实测六条跨区航线里**五条会从岛上穿过去**（zone1→zone2 穿两块地块，zone1→zone4 连穿三块），
俯视镜头下非常显眼。工程里 `src/core/sail_nav.gd` 其实早就有 `SailNavLib`（网页版 `sail-nav.js` 的移植，
`test_core` 里有 15 条断言），但从来没被 boat 用过。

### 现在的做法

1. **绕岛**：用 `SailNavLib.create_nav_grid()` 把 `assets/baked/shore.json` 的岸线轮廓压成 0.5m 栅格
   （矩形直接建，两个圆形轮廓手工补 blocked —— 接口只吃 Rect2，外接正方形会把旁边水道也堵死），
   再 `plan_route()` 做 A* + 拉绳平滑。clearance 2.3m（船体半宽 1.5、半长 2.9 之间取折中）。
2. **真运动学**（`boat.gd` 的 `_steer`）：
   - 逐段追航点，到段尾 0.75m 内自动切下一段；
   - 速度有加速（2.2 m/s²）/ 刹车（4.2 m/s²）；转弯时按朝向偏差降速；
   - 朝向按最大角速度 1.55 rad/s 趋近目标航向，**转不过来就绕大圈**（不会横向平移）；
   - 最后一段用「速度 ∝ 剩余距离」的比例控制靠岸，到站后原地按同样角速度把船身摆正。
3. **航线预览**：`scripts/world/route_ribbon.gd` 在水面铺一条虚线（1.1m 周期）+ 终点呼吸圆环。
   水面着色器是 `unshaded + depth_draw_never + render_priority 2`，会盖住普通不透明物，
   所以虚线抬到水面上 0.10m 且 `render_priority = 6`。

### 验收

`--selftest` 的 `[sail-nav]` 小节：栅格规模与障碍格数、岛心判障碍、开阔水面可通行、
**五个泊位两两可达且航线不穿岛**（逐点采样比岸线轮廓，跳过首尾各 3m）、绕行航路比直线长、
按航路能开到 zone3、贴住泊位 0.5m 内、每帧转角不超过角速度上限。

调试：`--sailto=zone3` 直接朝该区块出航（截图核对航线用）。

## 6.6 基础操作：相机与点击水面（专项打磨）

用户在试玩后提的第一条意见不是缺玩法，而是「镜头没法缩放、移动反馈不足」。
这类东西不影响数值，但决定「能不能好好看这个世界」，所以单独列一节。

### 相机（`scripts/orbit_camera.gd`）

| 操作 | 行为 |
| --- | --- |
| 左键拖动 | **抓地平移**：按住时鼠标下的那块地 1:1 跟着走（不是按基向量乘像素，远近手感一致） |
| 右键 / 中键拖动 | 绕目标旋转：水平自由，俯角限制 22°~78°（永不翻面、不会看到海平面切口） |
| 滚轮 | **朝指针缩放**：缩放前后指针下的地不移动；每档 ×0.86（旧版只 8%） |
| 触控板捏合 | `InputEventMagnifyGesture` 同样缩放 |
| 触控板双指滑动 | `InputEventPanGesture` 当作地图平移 |
| WASD / 方向键 | 平移，速度随高度缩放，Shift/⌘ 加速 |
| Q / E | 水平旋转 |
| 松手 | 平移有很短惯性（约 0.3s 阻尼收尾），缩放有阻尼收敛 |

- 缩放范围 **9~190**（旧版 30~120，近景根本看不出绞盘/菜箱的细节）。
- `target` 平移有边界（`pan_bounds`），不会被拖到虚空。
- 反馈：拖动时指针变「抓取」，缩放时底部提示条显示「缩放 62%」。

**为什么原来"没反应"**：滚轮只认 `InputEventMouseButton` 的 WHEEL 事件，
macOS 触控板双指缩放发的是 `InputEventMagnifyGesture`，代码里根本没接；
再加上每档只改 8%，即使有鼠标滚轮也几乎看不出来。

### 点击水面划船（`main._try_sail_to`）

- 点击 → 射线与水面平面求交 → 命中点在岸线形状内（外扩 0.9m）就当作陆地，拒绝。
- **在岸上点水面**：先上船再划过去（船就停在泊位，不需要先点船）。
- **航行中点水面**：直接改道，可以中途换目标。
- 落点有琥珀色光环；航线虚线只显示**剩余**航段（每 0.3s 刷新一次）。
- 手动到达不发区块切换（`arrived("", "manual")`），只回到「在船上」状态。

### 划船状态（`scripts/boat.gd`）

- 两根**可见的桨**挂在舷边，随桨频 ±17° 前后摆、入水出水；停泊时收起来。
- 桨频跟速度：慢 2.0 次/秒 → 满速 3.0 次/秒；速度本身每桨 ±9% 脉动。
- 船身向转弯内侧倾（按转向速率），随桨左右轻摆、上下微浮。
- 转向角速度上限从 1.55 降到 **0.95 rad/s**（转弯半径约 3.6m），
  配合转弯降速，手感从「快艇」变成「划桨小船」。

### 相机面板（C 键）与「最远 / 最近」定位

滚轮能缩放还不够：试玩时最常见的是「想一眼看全，或者扑到近处看细节」——
连续滚十几下才到位很烦。所以加了一个相机面板（`scripts/ui/camera_panel.gd`，C 键开关）：

| 控件 | 行为 |
| --- | --- |
| 最近 | 一键到 `zoom_min`（9 m） |
| 中景 / 远景 | 区间 45% / 72% 处（约 90 m / 139 m） |
| 最远 | 一键到 `zoom_max`（190 m） |
| 默认机位 | 回到 `main.tscn` 里存的 `distance`（108 m） |
| 滑杆 | 9~190 m 连续调，读数实时显示米数与百分比 |
| −10m / +10m | 微调 |

- 快捷键 **Z = 最近、X = 最远**，面板关着也能用；滚轮/捏合缩放时面板读数会跟着变。
- 面板不参与玩法：打开时只屏蔽悬停铭牌与点击走路，相机本身照常可以拖/滚。
- 距离走 `OrbitCam.set_distance()`（即时生效，无平滑）——「定位」要所见即所得。

命令行（截图/回归工具）同样支持：

```
--zoom=near | mid | far | farthest | default | 40%   # 定位到档位或区间百分比
--zoom=42                                            # 仍然支持直接给米数
--campanel                                           # 启动就打开面板（截面板本身用）
```

### 顺带修掉的中文字体缺字

面板第一版里「最远」两个字显示成方框（苹果 LastResort 的缺字占位）。查下去发现是
`SystemFont` 的 `font_names` 第一项写的是 `"PingFang SC"`，而 macOS 上它实际解析成了
**PingFang HK**——港版字形没有简体独有的字。用脚本把 `scripts/` 里 1046 个汉字逐个 `has_char` 测了一遍：

| 字体 | 缺字 |
| --- | --- |
| PingFang SC（实际 PingFang HK） | 3 个：稳、远、迟 |
| Hiragino Sans GB | 0 |
| Heiti SC / Songti SC / Arial Unicode MS | 0 |

于是把 `Hiragino Sans GB` 提到首位（其余顺序不变），6 个 UI 脚本一起改。
这不只影响新面板：`远岸`（zone4 名字）、`稳稳`、`延迟` 之前都会缺字。

### 验收

`--selftest` 新增 `[camera]`（滚轮/捏合能缩放、上下限、旋转不改俯角区间、平移有边界、
**面板最近/最远/默认/百分比定位精确命中、米数被夹在区间内、面板开关**）
与 `[water-click]`（陆地/水面判定、能划到指定点、桨真的在动）两节。
截图：`outputs/cam-default.png` / `outputs/cam-close.png` / `outputs/rowing.png` /
`outputs/camera-near.png`（9 m）/ `outputs/camera-far.png`（190 m）。
调试参数：`--zoom=18`、`--zoom=near|farthest`、`--campanel`、`--orbit=0.95,0`。

## 7.5 功能 5：打捞（已完成）

旧版是「点到上岸桩就进账 + 40 秒冷却」：点一下、等一会儿、再点一下，中间没有任何操作，
世界里也看不到打捞台。现在它是一台真实的绞盘，产出取决于你自己怎么操作。

### 玩法

1. 走到 zone1 打捞浮台西侧的**绞盘**旁（世界里真有这台机器：立柱、卷筒、摇柄、垂进水里的钩子）。
2. 按 **E** 打开打捞面板，钩子开始下沉。
3. **下钩**：深度条从 0 涨到 100%，按 E 停住。越深产出越好，但 75% 之后载荷变重、张力涨得更快。
4. **收线**：按住 E 收线（张力上升），松手放线（张力回落）。
   张力落在**绿区（42%~78%）**才有收线进度；顶到红线超过 0.55 秒 → **缆绳绷断，这一趟归零**。
5. 收满 100% 结算：`木料 = 2 + 深度×2.4 + 准度奖励`，`零件 = 1 + 深度×1.6 + 准度奖励`，
   深度 ≥72% 且准度 ≥50% 额外带 1 玻璃，深度 ≥90% 且准度 ≥80% 额外带 1 珍珠。

| 阶段 | 玩家在想什么 | 系统在做什么 |
| --- | --- | --- |
| DROP | 「再放深一点…还是现在就停？」 | 深度线性增长，2.6 秒到底 |
| REEL | 「张力高了，松一下」 | 张力随按住上升、松手回落，绿区才累积进度 |
| DONE / FAILED | 「这趟值不值」 | 结算产出，或者断线清零 + 8 秒短冷却 |

设计取舍：**深度不是越高越好**。第一次玩家会冲到底，被断线教一次，第二次开始挑「七八成」这个甜点。
断线给 8 秒短冷却而不是 40 秒——惩罚是「重来一次」，不是「干等」。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/salvage.gd` | 规则层（`SalvageModel`）：深度 / 张力 / 准度 / 断线 / 产出，纯状态机 |
| `scripts/core/salvage_winch.gd` | 世界里的绞盘：造型、焦点文案、冷却提示、收线与断线动画 |
| `scripts/ui/salvage_panel.gd` | 面板：深度条、张力表（绿区/红线/指针）、收线进度、结算文案 |
| `scripts/economy.gd` | `commit_salvage(now, haul)`：进背包 + 进冷却 |

### 数据契约

- 产出全部由 `SalvageModel.haul()` 计算，UI 只显示不计算；自检直接推状态机。
- 绞盘位置从 `zones.json` 的 `walk[id=zone1_salvage]` 矩形推出（西边缘内缩 0.7m），不写死坐标。
- 面板打开时主场景不再吃 E / 空格 / ESC；ESC 中途退出**不结算、不进冷却**（不罚误按）。

## 7.6 交互细节复刻

前面几节重做的是「玩法」，这一节补的是网页版那些**手感细节**——它们不影响数值，但决定「像不像原来的游戏」。

| 细节 | 网页版 | Godot 版现在 |
| --- | --- | --- |
| 悬停铭牌 | 鼠标移到建筑/物资上浮出卡片（名字 + 动作 + 产出） | `scripts/ui/hover_card.gd`：世界投影命中，浮在目标上方 |

| 点图标 → 自动走过去 | 点可交互物，小人走到位再动手 | `_approach()`：算站立点（目标靠玩家一侧 1.35m）→ 走过去 → `interactor.auto_hold` 自动长按 |
| 落点反馈 | 无（只能看小人动） | `scripts/ui/click_reticle.gd`：贴地光环扩开淡出；航行目标用琥珀色 |

| 右键拖镜头 | 右键拖动 = 用户接管镜头 | 左键/右键都能拖，右键不会触发「走过去」 |

## 7.7 功能 9：交易与订单（已完成）

网页版没有交易：鱼、菜、番茄只能囤在背包里看数字。这一版把「产出」接上了一个**出口**，
而且不是「一键卖光」，是一块真的立在码头上的板子。

### 玩法

1. 走到 zone1 **打捞浮台**上的订单板（木板 + 三张钉着的单子 + 一盏会晃的灯）旁按 **E**。
2. 板上同时挂 **3 张订单**：客人、货品 ×数量、报酬（海贝）、可选的额外货、**剩余时间**。
3. 货够 → 点「交付」：立刻扣货、报酬当场入账，那个位子空出来，**9 秒后**补一张新单。
4. 货不够 → 按钮显示「缺货」并禁用，行内写「手上 2/6」，不给你「点了才知道不行」。
5. **到期**（260~430 秒）没交 → 这张单子自己换掉，**不罚款**——你损失的只是「本来能赚的那笔」。
6. **换一批**（2 海贝）→ 把板上三张全部重抽。手上只有鱼、板上全是木料单时，这是唯一的出路。
7. **档位随进度解锁**：船 2 级或有 2 级建造点 → 出现 2 档单（玻璃、番茄）；船 2 级 **且** 有 3 级建造点 → 3 档（珍珠、南瓜、成批玻璃）。

| 档位 | 典型订单 | 报酬区间 |
| --- | --- | --- |
| 1 | 鱼×3 / 贝壳×4 / 木料×6+缆绳×1 / 种子×4 / 蔬菜×3 | 12~21 |
| 2 | 零件×4 / 玻璃×3+4 贝 / 番茄×4 / 蔬菜×5+种子×2 / 鱼×6 | 24~44 |
| 3 | 珍珠×1+玻璃×1 / 南瓜×2+8 贝 / 玻璃×6+零件×2 / 番茄×6+缆绳×2 / 零件×6 | 36~72 |

设计取舍：

- **不做价格浮动**。浮动只让人反复刷到「好价格」为止，不如让档位随进度提升来得清楚。
- **到期不罚**。这是「机会溜走」，不是「你犯错了」；惩罚性设计留给打捞断线那种主动冒险。
- **报酬下限写死成断言**：`pay ≥ sell × amount`，否则「交单不如直接卖」，新加订单时自检会立刻红。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/orders.gd` | 规则层（`OrderBoard`）：抽单 / 到期 / 补位 / 换一批 / 档位 / 存档 |
| `scripts/core/trade_board.gd` | 世界里的板子：立柱、板面、三张纸、图钉、吊灯（灯会晃） |
| `scripts/ui/order_panel.gd` | 面板：三行订单、交付按钮、换一批、剩余时间 |
| `tools/place_trade_board.py` | 求解摆放位置（行走矩形 + 建筑 AABB + 避让所有交互目标 2.6m） |
| `assets/data/orders.json` | 订单池（16 条，跨 3 档，带权重） |
| `assets/data/trade_board.json` | 板子在世界里的位置与朝向（工具生成，不要手写） |

- 规则层的 `orders` 是 `Economy` 的子节点，和 `farm` 同级，天然跟着经济状态一起存档。
- 面板打开时主场景不吃别的键；ESC 由面板自己关（关不掉会把玩家锁在 UI 里，自检有断言）。
- 交付的扣货走 `Inventory.remove`（原子操作），不会出现「扣了一半」。

### 摆放位置的一个妥协

上岸码头那块甲板（`zone1_home_dock` 的 `[-2.4,2.8] × [6.4,11.2]`）本来最合适，
但 0.35m 网格采样下来，49 个候选点全部落在菜箱 / 施工牌 / 两个采集点的 2.6m 以内；
另一块上岸甲板只有一条 0.35m 宽的空带。所以板子立在更宽的**打捞浮台**上——
打捞一趟、上岸交单，动线反而更顺。工具里记了这条原因，别再手挪回去。

## 7.8 功能 11：存档与读档（已完成）

之前完全没有存档：关掉游戏，背包、建造等级、菜箱、订单全部归零。
这一版收成**一份带版本号的 JSON**，并且顺手修掉了「跨进程读档冷却变成几十年」这类坑。

### 玩法

| 操作 | 行为 |
| --- | --- |
| **F5** | 存档，底部提示「已存档 · 09:50 · 背包 7/24 格」 |
| **F9** | 读档，回到存档时的区块、船位、站位 |
| 自动存档 | 每 120 秒静默存一次（不打断操作，也不弹提示） |
| 潜水 / 收线中 | 拒绝存读并说明原因（这两套状态没有可序列化的中间态） |

存档位置：`user://save_slot_0.json`（macOS 在
`~/Library/Application Support/Godot/app_userdata/sea/save_slot_0.json`）。

存进去的东西：背包（含容量）、船等级、建造等级与施工进度、设施、菜箱状态、
**订单板三张单子的剩余秒数**、**打捞冷却还剩多少秒**、**每个采集点的枯竭剩余秒数**、
当前区块 / 上岸点 / 模式 / 船位朝向 / 岸上站位、远海解锁。

### 三条设计约束

1. **只存相对时间**。`Time.get_ticks_msec()` 每次启动从 0 开始，把绝对时间写进文件，
   重开游戏冷却就变成几十年（或者立刻失效）。所以冷却一律存「还剩多少秒」，读档时用
   `now + left` 复原。
2. **读档要容错**。物品表 / 订单池 / 菜箱表改过之后，旧档里的未知 id 直接跳过，
   而不是整档读废；读档前先按当前表重建，再合并存档。
3. **原子写入**。先写 `.tmp`、读回比对、再 `rename` 顶替——写一半断电不会留下半截 JSON。

版本：`VERSION = 1`。读到 v0（早期原型那种没有 envelope 的扁平格式）会自动迁移；
读到比本作新的版本直接拒绝，不猜。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/save_game.gd` | 编码 / 解码 / 迁移 / 原子写 / 应用（`SaveGame`，纯静态函数） |
| `scripts/main.gd` | F5 / F9、`--load` / `--saveshot`、自动存档倒计时 |
| `scripts/core/gather_spot.gd` | 新增 `restore_cooldown(秒)`：读档时把采集点摆回枯竭态 |
| `scripts/economy.gd` | `to_dict/from_dict` 增加订单；`salvage_ready_at` 改用相对冷却复原 |

### 踩到的坑

1. **采集点读档「看着有货、其实采不了」**：只改 `cooldown_left` 不改造型，
   物件是亮的但 `can_interact()` 返回 false。必须走 `_dim()`。
2. **`--saveshot` 与 `--savepath=` 的顺序**：参数遍历里槽位必须先解析，
   否则同一条命令行里 `--saveshot` 排在前面时会写到默认槽位（自检里踩过一次）。
3. **`hud.toast` 一直不可见**：标签字体色的 alpha 写成了 0，而 `toast()` 只改
   `modulate.a`——两者相乘还是 0。这个 bug 连采集/建造/航行的提示一起吞了，
   属于「画面看着对、反馈全靠猜」。现在改成：字体色不透明 + 深色药丸底
   （浅色甲板上白字会糊掉），淡出走 `PanelContainer` 的 modulate。

## 7.9 功能 8：潜水与宝箱（已完成）

旧版潜水**没有代价**：想潜多久潜多久，五个宝箱一进水就在屏幕上列成清单，
点一下就自动游过去、等 3 秒、到账。探索退化成「照着清单打卡」。
这一版把两件事改回游戏：**气是有限的**，**东西要自己看见**。

### 玩法

- 下潜从船边开始，氧气管够 100 点。三件事同时烧气（见 `scripts/core/dive_air.gd`）：

  | 消耗项 | 规则 | 玩家的取舍 |
  | --- | --- | --- |
  | 深度 | 每秒 0.85 × (1 + 深度 × 0.009)，75m 处约 1.7 倍 | 深沟只能快进快出 |
  | 动作 | 游动 ×1.35，按住 Shift 冲刺 ×1.9 | 赶路还是省气 |
  | 头灯 | 每秒额外 0.30 | 「看得见」和「待得久」互相挤压 |

- 氧气低于 35% 报一次「余气不多」，低于 15% 报「氧气见底」并让仪表呼吸闪烁。
- **归零不扣资源，而是强制上浮**，然后需要 6 秒才能再下潜。失败有代价，但不至于劝退。
- 回到 5m 以内（水面）快速换气，约 3 秒回满。
- 头灯（F 键）照 34m，椎角约 55°。它是唯一能在 26m 外发现宝箱的手段。
- **宝箱改成「发现式」**：没被发现的宝箱不画标签、也不能点。发现条件二选一 ——
  游到 11m 内，或头灯扫到 26m 内的锥形区域。发现后标签常驻本次游戏。
- 三个区块的深度差现在有意义了：珊瑚花园（-17m）随便逛，蓝礁（-30m）要看气，
  旧城（-45m）得规划路线，深谷（-73m）基本是一趟一趟抢。

### 实现

| 文件 | 职责 |
| --- | --- |
| `scripts/core/dive_air.gd` | 氧气 / 头灯 / 恢复冷却的纯状态机，可按固定步长推 |
| `scripts/world/underwater_world.gd` | 接入：每帧推氧气、头灯 uniform、发现扫描、强制上浮 |
| `shaders/uw_common.gdshaderinc` | `uw_lamp()`：锥形 + 距离衰减 + 朝向系数 |
| `scripts/hud.gd` | 左下的潜水仪表（氧气条 / 头灯 / 宝箱计数），低氧闪烁 |
| `scripts/core/save_game.gd` | 存「发现 / 打开过哪些宝箱」，不存氧气 |

### 头灯为什么必须写在 shader 里

水下材质的明暗是 `ALBEDO = base * (0.88 + uw_light() * 1.1)` **自己算的**，
引擎灯光几乎不参与。上一轮试过加一盏 `DirectionalLight3D` 补光，画面只变 0.39%。
所以头灯不能是 `SpotLight3D`，只能是一个 uniform：

```glsl
uniform bool lamp_on; uniform vec3 lamp_pos, lamp_dir;
uniform float lamp_range = 34.0, lamp_inner = 0.90, lamp_outer = 0.70;
```

`uw_lamp(n_w)` 做三件事：`smoothstep(outer, inner, dot(dir, to_lamp))` 出锥形、
`pow(1 - dist/range, 1.5)` 出距离衰减、`0.18 + 0.82 * max(dot(n, -dir), 0)` 留一点背光散射
（否则石头背面会硬切成黑块）。头灯**不吃深度衰减**，反而在深处更亮 —— 这正是它存在的理由。

实测（冻结焦散后对比开关灯）：街区机位平均 +0.5/255、`>20` 的像素占 1.1%；
深沟机位（-121m）平均 **+12.3/255**、`>20` 占 **24.6%**。浅水几乎看不出、深水一眼就亮，
说明「越深越依赖灯」这件事被做出来了。

### 验收

## 9. 工程配套：主场景可编辑化 + 滤镜面板

功能之外，为了能真正「像 Godot 项目那样」迭代，补了两件事。

### 9.1 主场景搬到 .tscn

以前 `main.gd` 在 `_ready()` 里 new 出灯光、水面、相机、UI —— 编辑器里看到的是空的，改不了。
现在这些节点都在 `scenes/main.tscn` 里，可以直接选中、拖动、在 Inspector 里改：

```
World/WorldEnvironment   Environment 资源（assets/materials/world_env.tres）
World/Lights/…           四盏灯，朝向即 Transform
World/Water              PlaneMesh + ShaderMaterial（assets/materials/water.tres）
World/Zones/…            区块实例
World/Gameplay/…         采集 / 建造 / 菜箱 / 海面道具
Camera                   轨道相机：target / orbit_dir / distance 都是 @export
Boat + Boat/Explorer     小船与小人
Birds / Underwater       飞鸟、海底世界
HUD / InteractPrompt / LandingMarkers / ColorGrade
```

`main.gd` 改成「先找节点，找不到才程序化创建」：

- 找到 → 只接线，**一个数值都不覆盖**（否则编辑器里调好的会被代码改回去）；
- 找不到 → 退回旧路径，所以老场景、测试脚本仍然能跑；
- `selftest` 里加了「场景契约」断言，列出这些路径必须存在 —— 有人改回程序化会立刻红。

灯光/环境的数值是脚本导出的资源（`tools/make_scene_resources.gd`），
不用手写 `.tres`（枚举值与属性名容易写错）。

### 9.2 滤镜面板（P）

整幅画面的最终调色位于 `Environment`：`tonemap_exposure` 与 `adjustment_brightness / contrast / saturation`。
按 **P** 打开面板即可实时拖：

| 控件 | 写入 |
| --- | --- |
| 曝光 | `tonemap_exposure` (0.4–2.0) |
| 亮度 | `adjustment_brightness` (0–2) |
| 对比度 | `adjustment_contrast` (0–2) |
| 饱和度 | `adjustment_saturation` (0–2) |

- 拖动即时生效，写的是场景里那一个 Environment；
- 「复位」回到场景资源默认值，「复制参数」输出一行数值；
- 「写入场景」把当前值保存回 `assets/materials/world_env.tres`，下次启动即默认值；
- 同时记在 `user://filter.cfg`，重启不丢。
