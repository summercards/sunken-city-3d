# sea 场景与设施制作细则

配合 `SKILL.md` 使用。SKILL.md 给判断依据与数值，本文给**逐条可核查的判定方法和退回理由**。

## 验收目录

```
sea-work/qa/<套件>_v###/
├─ validate.json              机检报告（validate_sea_scene.py 输出）
├─ render_overview.png        参考镜头全景（与参考图同焦距同分辨率）
├─ render_closeup.png         改动区域近景
├─ render_top.png             正交俯视
├─ render_<组件>.png          建筑单体 / 争议组件单独视图
└─ notes.md                   未做项、pending 授权、已知偏差
```

工程外输出，受 `SEA_WORK_ROOT` 控制。验收图不放进 `art_source/scenes/`，避免与可交付源混放。

## 1. 输入与范围

1. 参考图先归档进套件目录（`reference.png` / `reference_1.png`），算 SHA-256 记进 `component_plan.json.reference_sha256`；多张参考图进 `references[]`。
2. **参考图是唯一视觉真值**，不是灵感图。用户标线、手写注释、附件配色都算真值；功能上合理但外形不同的自主设计一律算偏差。
3. 参考图无比例尺时，用已存在游戏尺度（玩家身高约 1.7 米、门洞 2.0–2.1 米、栈桥板厚 0.22 米）反推，并把假设写进 `dimensions_assumption`，标注"非实测"。
4. 范围清单在动几何前写定：可改部件、锁定部件（世界变换、尺寸、网格、材质、修改器签名）、参考相机。局部任务不得顺手改范围外的墙、地坪、楼梯、栏杆。

## 2. 色板与 UV

- 色板：512×512、8×8 格、格边长 64 px，`row_origin: top`。索引公式：`column = floor(u*8)`、`row = floor((1-v)*8)`（Blender V 从底部起，JSON 行号从顶部起，取色时按 `1-v`）。
- 单格判定：一个面的全部 loop 落在同一 `column` 与同一 `row`。
- 安全边：距格边界 ≥ 8 px = **0.015625 UV**（512 色板）。机检默认就是这个值（`--safe-margin` 可调），不用松到 0.01 去将就小岛。
- 面积：UV 多边形面积 ≥ 1e-7（实际远大于此，正常小岛跨度 0.05–0.07 格）。**不允许单点 UV 靠插值到邻格取色**。
- `PaletteUV` 必须是活动编辑层与 `active_render` 层；`UVMap` / `UV贴图` 等旧层删除，确需保留要在清单登记用途且不得为活动层。
- 图片节点：`Closest`、外链唯一 PNG、不 pack。GLB `export_image_format="NONE"`，导出后检查 GLB 内无 image chunk。
- 改已用格子含义前，先列全部消费者（`assets/registry/current_source_index.json` + manifest 里的 `palette` 字段）；新增配色另开色板文件。

## 3. 材质节奏

默认一个套件最多四个角色，面积节奏：

| 角色 | 面积占比 | 典型件 |
|---|---:|---|
| `SEA_Matte` | 85–97% | 墙、木铺板、棚布、陶器、家具面 |
| `SEA_Gloss` | ≤12% | 窗玻璃、水面件、釉面 |
| `SEA_Metal` | ≤10% | 栏杆细杆、太阳能边框、机械件 |
| `SEA_Emission` | ≤3% | 灯、屏幕 |

实测基线（`validate_sea_scene.py` 的 `area_share_by_role`，按面面积算）：

| 套件 | Matte | Gloss | Metal | Emission |
|---|---:|---:|---:|---:|
| `reference_skiff/v001` | 91.5% | 4.9% | 3.6% | — |
| `sunny_bloom_retreat/v007` | 97.4% | 2.6% | 0.04% | 0.03% |

偏离这张表时先看是不是窗户或金属件失控，别靠新增材质球"调回来"。

判定法：

1. 发光只能靠"有自发光材质或非零 Emission Strength"，不能凭对象名里的 `灯`/`screen` 猜。
2. 自发光对象单独成网格、单独命名（`_发光` / `_Emission` 结尾），材质槽只 1 个。
3. 主体对象材质槽 ≤3 个；槽数超了说明在用颜色堆材质——回去合 UV。
4. `.001`、`_副本`、`_final`、按颜色命名的散料材质全部清掉。sea 不使用中文长名材质，统一 `SEA_*`。

## 4. 结构与合并

1. 一个组件 = 一份可复用母版几何；摆放靠 Collection Instance。
2. 修改器求值后合并输出：非自发光面合成主体网格，自发光面合成独立网格；保留面材质索引与 `PaletteUV`。
3. **不得把多个独立设施、多块地砖、多个建筑模块焊成一个不可拆网格**——那会让后续替换、优化、碰撞代理全部失效。
4. 倒角与加权法线必须在合并**之前**完成（合并后再倒角会把接缝一起磨圆）。
5. 显示用地面、底台、背景板、相机、展示灯不进游戏输出集合。

## 5. 命名规则

- 组件集合名 = AssetID（`SEA-SCENE-<套件简写>-<KEY>`），一个 AssetID 一个集合；分组集合（`01 建筑结构`）只用于浏览。
- 网格对象名用**中文语义名**（`座板前条`、`宽厚木底板`、`奶白厚舷边`），一眼能看出是哪个部件；未定名阶段可用英文语义名（`lantern_emissive`），交付前统一。
- 账本 `name` 用中文设施名（`黄白条纹圆边遮阳棚`）；文件、`asset_key`、`AssetID` 用英文大写短横（`awning` / `SEA-SCENE-SBR-AWNING`）。
- 绝对禁止默认名进交付：`Cube`、`Object`、`Plane`、`Mesh.001`、`Circle.003`。以 `.001` 结尾的复制件可以存在（同件多实例），但父级必须是语义名。
- 一个 AssetID 全库唯一、一份资产一条主记录；跨套件复用就登记共享，不复制第二份源。

## 6. 组件归类与目录

### 6.1 独立包判定

满足任一条即独立成包：有独立语义（可单独替换/搬走）、有独立碰撞责任、会被多个套件复用、有独立状态轴（开/关、有水/无水）。

不能独立成包：靠画面组合才成立的碎件、纯装饰螺栓、单个面片贴花。

### 6.2 宿主附着

- 灯带、屏幕、标签、控制面板、太阳能栅线归宿主组件。
- 跨设施管线、独立灯具可成"环境支持"包。
- 房间实际灯光节点与参数归 Godot TSCN，Blender 展示灯不导出。

### 6.3 Blender 与磁盘镜像

`components/<asset_key>/<asset_key>.blend` 与 `02_游戏输出_独立资产包_v###` 下的集合一一对应，数量相等、命名可推导。空包、一包两归属、磁盘有文件但集合缺失，任一即退回。

### 6.4 地面系统

地砖、铺板按"型号"做组件，行列号只属于实例坐标；同一型号不同配色用 PaletteUV 变体，不新建几何。整片地面不焊成一整块，也不按每一格导出。

## 7. 参考图高还原与局部锁定

1. 先还原：可见结构、比例、轮廓、位置、朝向、间距、开口数量与位置、材质分区、标识、视觉密度。读完再动手，不边看边加。
2. 固定参考镜头：相同构图、焦距或正交尺度、分辨率、色彩管理、关键灯光，做前后对比图。窗口分辨率变了要重设，别拿旧图对比新图。
3. 局部修改锁区：改前保存一份，记录锁定对象的名称/类型/世界变换/尺寸/网格/材质/修改器/动画签名；交付时证明锁定项未变。
4. 关键接口要写数字：楼层基准、平台顶面、对接坐标、门洞、入口缺口、水平包络。高度改动时联动相接的楼板、楼梯、栏杆、出口。

## 8. 尺寸与倒角的测量方法

- 厚度：取对象包围盒最小轴，或选中两面量顶点距离；报**实测米数**，不报"看起来厚"。
- 倒角半径：读 Bevel 修改器 `width`（或 bmesh 半径），段数读 `segments`；加权法线检查 `use_auto_smooth` 等价设置或 Normal 节点遮罩状态。
- 曲面分段：读 UV 球/环分段数（小叶片 10×6、大花瓣 12×8）。
- 面数：依赖图求值后三角化，累计可见实例；用 `polygon_count`（多边形）与三角化后计数两列分别报。

判定表（与 SKILL §3 一致，此处给违规示例）：

| 现象 | 判为 |
|---|---|
| 边缘有渐变但轮廓仍直角 | 平滑着色伪装倒角 → 退回 |
| 倒角 0.004 米 | 低于可见阈值 → 删掉或提到 ≥0.008 |
| 整件 Z 缩放 0.85 凑高度 | 非等比缩放 → 退回，重做几何 |
| 铺板无倒角但面数已紧 | 允许 L2 单段 + 加权法线；仍不许直角高光 |
| 花瓣单面片 | 退回，改闭合厚度 ≥0.02 |

## 9. 美术检查

逐张四视图看：轮廓是否与参考同构、体量是否饱满、密度是否过碎、有无穿插/浮空/贴面闪面、暗部是否死黑、自发光是否泛白、植物是否像塑料片、木纹方向是否顺板、焦点色是否超面积。

发现误读（把窗湾看成阳台、把布棚看成硬顶）时回到参考图重判，不用"功能上更合理"覆盖。

## 10. 技术检查

按 `SKILL.md §7` 表逐项，另加：

- 重开母版与每个独立包，确认组件数、实例复用、集合归属、根与网格变换、UV、图片路径、材质角色、非空几何。
- **倒角**：应用后修改器已消失，读不回半径。判定靠三条同时成立——计划里登记的 `radius_m/segments` 存在、该硬边在近景里确有 2–3 个中间环且高光连续、没有用全平滑遮掩直角。机检只报"残留未应用倒角修改器"与"全平滑对象"，后者出现时要确认它确实是绳/桨杆/圆件这类本来就是曲面的部件。
- **GLB 侧**：`images` 必须为 0（色板不内嵌）；`TEXCOORD_0` 必须在（颜色靠它取色）；不要求 `COLOR_0`——场景组件的颜色路径是 UV+色板，只有烘焙顶点色那一族（如绞盘打捞台）才要求 `COLOR_0` 非全白；不做自动 LOD、简化阴影网格、顶点压缩。
- **三角数**：按实例求值累计（`validate_sea_scene.py` 的 `triangles` 字段），同时报 `mesh_instances`。母版隐藏只算实例，别拿母版单次求和当场景数。
- 源级与运行级分开记录：源级通过不写"游戏内已验证"。

## 11. 常见退回原因（按出现频率）

1. 把多个设施焊成一个网格，后续无法替换。
2. UV 压成点或跨格，运行后颜色随视角跳。
3. 平滑着色冒充倒角，近景一看是豆腐块。
4. 板材薄于 0.16 米，整个建筑像纸糊。
5. 植物与墙体焊死，改花色要重做建筑。
6. 面数只报母版不报实例，或只报多边形不报三角。
7. 优化件就地改原文件，覆盖了已登记版本。
8. 参考图授权写成默认可用。
