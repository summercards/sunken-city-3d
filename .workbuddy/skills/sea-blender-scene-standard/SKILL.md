# sea Blender 场景与设施制作规范

sea 是**海上治愈系**世界：奶油白/暖木/海蓝的厚实体量，圆润饱满、边缘柔和、光感干净。本 skill 只服务 sea 一套口径，工程内不保留其他项目的尺度表、配色表与账本路径。

术语：`套件` = 一个场景源目录（如 `sunny_bloom_retreat`），`组件` = 可独立打开复用的母版，`实例` = 组件在装配中的摆放，`独立包` = `components/` 下一个可单独打开的 `.blend`。

**开工五步**：读 SEA-ASSET 与最近交付记录 → 冻结 `component_plan.json`（含 `visual_priorities`、`bevel`、`thickness_m`）→ 按 §3 建几何 → 按 §4 分材质与 UV → 跑 §7 机检 + 四视图渲染。

本机 Blender：`~/Applications/Blender.app/Contents/MacOS/Blender`（5.2.2 LTS）。

## 1. 适用范围

**适用**：场景建筑（房体、层楼、屋顶、栈桥、平台、围墙、楼梯、栏杆、窗洞门洞）、固定设施（太阳能板、遮阳棚、空调外机、灯、家具、容器、绞盘、泊位装置）、花草植被（叶簇、花瓣、藤蔓、盆栽、棕榈）。

**不适用**：作物四阶段模型（`art_source/crops` 独立域）、船（`reference_skiff` 独立套件）、UI 图像、可拾取道具、角色。正式 TSCN 摆位、碰撞、灯光节点属于 Godot 侧，不在本 skill 内决定。

## 2. 风格提示词（最常用的一节）

风格提示词是**设计输入**，不是装饰文字。生成参考图、向 Blender MCP 描述目标、或让模型深化某个组件时，都要带上命中的那几条，并在 `component_plan.json.visual_priorities` 里固化成可验收的条目。

### 2.1 词汇表（用这些词，不用近义词）

| 维度 | 用 | 不用 |
|---|---|---|
| 体量 | 厚实、错层、块面清晰、体量饱满、小体量大细节 | 纤细、镂空、机械感、工业感 |
| 边缘 | 圆润、厚倒角、柔和转折、边缘泛光 | 锐利、硬边、切角、金属棱 |
| 表面 | 奶油质感、哑光涂料、暖木纹理方向感、微磨损 | 镜面反射、湿滑高光、锈蚀斑驳 |
| 颜色 | 奶白、暖米白、浅沙、暖棕、海蓝、薄荷绿、珊瑚粉、赭黄 | 荧光、霓虹、金属紫、冷灰蓝主色 |
| 植物 | 饱满圆润、少量大叶、成簇花团、垂落藤蔓、向上或斜上方朝花 | 叶片单薄、锯齿裂叶、杂乱荆棘 |
| 光照 | 天光均匀、柔和阴影、正午散射、低对比 | 强方向光、竞技场灯、暗部死黑 |
| 情绪 | 慵懒、被海风晒过、可居住、松弛 | 破败、废弃、赛博、压迫 |

### 2.4 提示词 → 可验收参数的对应

提示词写得再好，不落到数值就等于没写。每条风格词必须在计划或几何里有对应物：

| 提示词 | 落地为 |
|---|---|
| 厚实 | 板材厚度 ≥ 0.16 米；墙壳 ≥ 0.12 米；倒角半径按 §3 |
| 圆润 | 硬边实体倒角，不用平滑着色伪装 |
| 饱满 | 花瓣/叶簇用闭合体块，禁止单面片 |
| 低饱和 | 只取色板里现有格子，不新建高饱和色 |
| 少量焦点色 | 焦点色面积 ≤ 视觉总面积 10% |
| 柔和阴影 | 投影保持真实，不用关闭投影换干净画面 |

深化单个组件时，把该组件的 `visual_priorities` 摘出来作为独立提示词开头，再补一句「只改 <部件>，其余几何与摆位锁定」。

## 3. 尺度、厚度与倒角

### 3.1 单位与朝向

1 Blender 单位 = 1 米，工程不做单位换算。源 +Z 朝上，组件正面为 **−Y**（`front_axis: "-Y"`），几何在**底部中心**为原点（`origin: "bottom_center"`），组件根与网格变换恒等，`Collection.instance_offset` 为零。到 Godot 的映射为 `(x, y, z) → (x, z, −y)`；倾斜组件记完整 Euler XYZ，不用单一平面角丢失姿态。

### 3.2 厚度基线

| 部位 | 厚度 | 说明 |
|---|---:|---|
| 墙壳（外墙板） | 0.12–0.18 | 白墙要"厚"，窗湾凹进才成立 |
| 楼板 / 地坪 | 0.16–0.22 | 承重视觉，边缘必须倒角 |
| 露台 / 栈桥铺板 | 0.20–0.22 | 现存参照：家园补给站浮板 0.18，木屋地坪与栈桥 0.22 |
| 平台实体（含基座边） | 0.50–0.70 | 现役一体化平台 Source 0.60；改动须同步支撑面高度 |
| 栏杆立柱 | 0.08–0.10 | 圆截面或厚方截面 |
| 扶手 / 栏绳横杆 | 0.06–0.08 | 绳类可细，但不得细于 0.02 |
| 太阳能板 | 0.06–0.08 | 厚圆角边，不建栅线级凹槽 |
| 玻璃 / 窗面 | 0.03–0.05 | 青蓝厚玻璃体块，不做单面片 |
| 门扇 / 百叶 | 0.04–0.06 | |
| 花瓣 | 0.02–0.04 | 闭合曲面，厚度不小于 0.02 |
| 叶片 | 0.015–0.03 | 有厚度中脉，禁双面片 |
| 藤蔓 / 绳 | 0.02–0.05 | 直径 |

厚度不是自由参数：**改了会动支撑面**（玩家站立面、泊位高度、种植点高度）的部件，必须同步记录并交给 Godot 侧重接，不能在 Blender 里单方面加厚了事。

### 3.3 倒角分级

| 等级 | 半径 | 段数 | 用在哪 |
|---|---:|---:|---|
| L0 轮廓 | 0.020–0.050 | 3 | 房体大轮廓、屋顶檐口、平台外沿、柱头 |
| L1 部件 | 0.012–0.020 | 2 | 门窗框、遮阳板、太阳能板边、家具主面、栏杆 |
| L2 铺板 | 0.008–0.012 | 1 + 加权法线 | 重复铺板、地砖、压边条 |

规则：

1. **实体倒角**（Bevel 修改器或 bmesh bevel），不是平滑着色。倒角后加**加权法线**保留平面，禁止用 `shade smooth` 假装圆边。
2. 有机件（叶、花瓣、藤蔓）走平滑曲面：小叶片 10×6 分段球面，大花瓣 12×8，裂叶用有厚度的闭合曲面；不靠细分修改器堆面数。
3. 面数紧时优先降段数（3→1），**不降半径**；半径低于 0.008 视觉上等于没倒角，直接删掉该倒角反而更干净。
4. 明显的镜面/玻璃件可以只倒 L1，不做 L0，否则高光会碎。
5. 禁止整件非等比缩放凑尺寸——会把倒角一起拉扁。
6. **倒角一旦应用（apply）就无法从修改器读回半径**，所以每件的 `tier/radius_m/segments` 必须在 `component_plan.json.components[].bevel` 里登记；验收靠「计划值 + 近景渲染 + 该硬边确实有中间环」三者对上。机检只能判两件事：有没有残留未应用的倒角修改器、是不是靠全平滑冒充。

### 3.4 面数与预算

面数按**整场景可见实例**统计：在最终保存文件的依赖图上取修改器求值后的网格 → 三角化 → 累计每个可见实例。母版隐藏时只算实例，不重复计算；相机、灯光不计几何；不能用大 N 边面掩盖真实三角数。两个数都要报：多边形数、三角数。

默认不设整场景上限；用户给了上限（例如 3000 三角）才作为任务约束写进 `component_plan.json.scene_triangle_limit`，并优先砍木纹、螺钉、栅线级细节，保留轮廓与倒角。

### 3.5 源与游戏的倍率

装配级缩放（例如整套 ×1.15、×1.5 换房间版）必须写进 `component_plan.json.layout_revision`，并附缩放轴心；厚度、净空、站立面都按缩放后数值验收，不能只核源尺寸。

## 4. 公共方格色板与材质

- 色板唯一位置 `art_source/shared/palettes/sea_*_8x8_512.png`，512×512、8×8 纯色格、每格 64 像素、行号自顶部起，配同名 `.json` 记录 `name/hex/row/column`。新套件要新配色时**新增一张**色板并在 manifest 里指定，不覆盖已登记色板。
- 所有组件**外链**同一 PNG，不在包内复制或打包（GLB 导出 `export_image_format="NONE"`）；图片节点 `Closest` 插值，由 `PaletteUV` 驱动。
- 每面 UV 是有面积的小岛，完整落在一个色格内并留 **≥8 像素（0.0156 UV）** 安全边；不压成单点。`PaletteUV` 同时是活动编辑层与渲染层，其余 UV 层删除。
- 材质角色最多四个，颜色只由 UV 决定，**不为每个颜色新建材质**：

| 角色 | 金属度 | 粗糙度 | 用途 |
|---|---:|---:|---|
| `SEA_Matte` | 0.00 | 0.72–0.90 | 墙漆、木板、布料、陶盆——绝对主力 |
| `SEA_Metal` | 0.60–0.85 | 0.28–0.45 | 栏杆、太阳能边框、机械件，占比压到最低 |
| `SEA_Gloss` | 0.05–0.20（清漆 0.5–0.7） | 0.12–0.22 | 窗玻璃、水面小件、湿滑表面 |
| `SEA_Emission` | 0.00 | 0.30–0.45 | 灯、屏幕，强度 1.0–2.0 |

上表是默认基线，按参考图微调；调整写进计划。自发光几何单独命名并分离成网格，不与主体混材质槽。

## 5. 集合、命名与目录

sea 的实际工程约定是**双场景 + AssetID 集合**（不是单一整合输出集合）：

```text
<套件>_组件母版                ← 场景一：几何真值
├─ 01 建筑结构                （语义分组，仅浏览用；可省）
│  └─ SEA-SCENE-XXX-HOUSE      ← 组件集合，集合名就是 AssetID，装母版网格
├─ 02 地面与平台
├─ 03 固定设施
└─ 04 花草植被

<套件>_参考装配                ← 场景二：摆位真值
├─ <分组>_组件实例            （EMPTY 集合实例，记录位置/旋转）
└─ 90 展示支持_不导出          （相机、灯光；永不参与几何验收）
```

- **组件集合名 = AssetID**（`SEA-SCENE-<套件简写>-<KEY>`），一个 AssetID 一个集合；分组集合只用于浏览。
- 摆位只在参考装配场景的实例上；母版网格保持恒等变换、底部中心原点。改整体布局改实例，改造型改母版。
- 展示支持集合（`90 展示支持_不导出`／`展示支持`）只放相机、灯光、背景板，不进任何导出。
- 中英文双轨：账本 `name` 与分组集合用中文设施名；组件集合、文件、`asset_key` 用英文；AssetID 全库唯一。
- 建筑、固定设施、花草**必须分属不同组件集合**；植物不焊进墙体、盆体或太阳能板。
- 源目录：`art_source/scenes/<套件>/v###/`（`<套件>.blend`、`component_plan.json`、`component_instances.json`、`catalog.json`、`asset_manifest.json`、`components/`、`export/`、`README.md`）。优化副本 `export/v00N/<套件>_optimized_v00N.blend` 独立另存，不在原文件上就地优化。
- 预览、临时导出、QA 图写入工程外 `sea-work/`（可用 `SEA_WORK_ROOT` 重定向）。

## 6. 流程

1. **读入口**：`GDD_V1.0.md` → SEA-ASSET → `docs/features/asset/{spec,ledger}.md`，并读最近一版 `docs/development/` 交付记录。
2. **冻结计划**：写 `component_plan.json`（模板见 `assets/component_plan_template.json`）。含参考图哈希与授权、尺寸假设、组件 AssetID、语义族、原点、正面轴、视觉优先级、三角预算、色板路径。参考图商业授权未核 = `pending`。
3. **建几何**：按 §3 尺寸与倒角；先做体块再切洞口，不为细节提前加面。
4. **分材质与 UV**：统一到四个 SEA 角色，逐面 PaletteUV 小岛，删旧 UV 层。
5. **写清单**：`component_instances.json` 记实例位姿（Blender XY 平面、+Z 上、绕 Z 旋转），`catalog.json` 记组件清单，`asset_manifest.json` 记路径、SHA-256、版本、色板、阶段。
6. **另存优化件并逐组件导出 GLB**：`export_image_format="NONE"`（色板不内嵌，实测线上组件 GLB 的 `images` 恒为 0）；保留 `TEXCOORD_0`（PaletteUV 是颜色的唯一来源，颜色在 Godot 侧由色板贴图 + UV 决定）；关闭自动 LOD、简化阴影网格、顶点压缩（会吃掉小尺寸倒角）。**场景组件不依赖顶点色 `COLOR_0`**——只有烘焙顶点色那一族资产（如绞盘打捞台，SEA-ASSET-R27）才要求 `COLOR_0` 非全白。
7. **重开验收**：见 §7，四视图渲染。
8. **登记**：`assets/registry/ledger_index.json` → `domains.scenes` → `assets/registry/ledgers/scenes.json`；更新 SEA-ASSET 功能账本与 `docs/development/`；跑 `python3 scripts/check_feature_contracts.py --sync` 再跑一次不带参数的检查。

## 7. 验收

保存后重新打开母版与独立包，逐项核：

| 项 | 判定 |
|---|---|
| 组件数 / 实例数 | 与计划一致，同件走实例 |
| 包唯一归属 | 每网格只属一个 AssetID 集合，无空包 |
| 变换 | 母版网格恒等变换、底部中心原点；摆位只在参考装配的实例上 |
| 朝向 | 正面 −Y 一致，倾斜件有完整姿态 |
| UV | 逐面单格 + 安全边 + 有面积，`PaletteUV` 为活动/渲染层 |
| 材质 | ≤4 个 SEA 角色，无废弃材质，自发光独立 |
| 材质节奏 | 面积占比落在 §4 区间（哑光为主，金属与发光压到最小） |
| 倒角 | 硬边为实体倒角 + 加权法线；半径段数与计划登记值对得上（应用后无法读回，靠近景核） |
| 厚度 | 关键板材实测值落在 §3.2 区间 |
| 面数 | 求值后三角数（含实例），两份数字（多边形/三角） |
| GLB | 无内嵌图片、`TEXCOORD_0` 在、无自动 LOD/简化阴影/顶点压缩 |
| 穿插 | 目视无穿透、无浮空、无贴面闪面 |
| 渲染 | 全景 / 近景 / 俯视 / 建筑单体四张，参考镜头同焦距同分辨率 |

自动化（`$BLENDER` 指本机 Blender 可执行文件）：

```bash
"$BLENDER" --background "art_source/scenes/<套件>/v###/<套件>.blend" \
  --python .workbuddy/skills/sea-blender-scene-standard/scripts/validate_sea_scene.py -- \
  --shared-palette "art_source/shared/palettes/sea_cozy_8x8_512.png" \
  --max-materials 4 \
  --json "sea-work/qa/<套件>_v###/validate.json"
```

- `validate_sea_scene.py`：按 `SEA-` 前缀找组件集合；校验 UV 单格（格数默认从色板同名 `.json` 的 `grid` 读取）/安全边/面积/活动层、材质角色与预算、色板外链+`Closest`+未打包、自发光分离、展示支持集合未混入；**报告按实例求值后的三角数**、`SEA_*` 面积占比、非恒等变换与倒角现状。退出码 0/1 可直接接门禁。
- `expand_palette_uv_islands.py`：把点状 UV 批量扩成单格内有面积的小岛（`--grid`，默认 8）；可顺带 `--glb` 导出，导出前自动切到组件母版场景。
- `repair_palette_uv_source.py`：补/标准 `PaletteUV` 层、把散料材质名归一到四个 SEA 角色、按 AssetID 建组件集合、清废弃材质。

源级验收通过 ≠ Godot 接入完成。接入状态单独记录，未接入就保留 `pending`；Godot 侧验证走 `scripts/run_verification.py`。

## 8. 交付

可维护 `.blend` 源 + 优化另存件 + 逐组件独立包 + 四视图 PNG + 计划/清单/manifest + 账本行 + `docs/development/` 记录。报告里写清：组件数、实例数、三角数、材质数、色板路径、未做项与 pending 授权。
