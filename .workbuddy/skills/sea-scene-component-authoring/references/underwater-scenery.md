# 水下观赏建筑／基座差异（underwater）

仅海上主场景里从海面可见的观赏楼和海下基座；**不包含独立海底／潜水玩法场景**。先读[SKILL.md共用尺寸与风格基准](../SKILL.md)，使用同一[机器表authoring_defaults](building_scale.json)，不另建水下数值副本。

- 沿用同样的层高、柱粗、板厚、门窗外观比例、倒角档位及3段默认值。建筑高度由楼层与明确设计决定，不因“水下／远景”自动缩放；用户明确的低面数预算或特殊尺寸在计划登记例外，现有六种观赏楼的单栋预算不扩散成全工程上限。
- 同一公共色板、PaletteUV和最多四材质角色；厚实、圆润、清新风格与水上一致。水色／折射由海水表现处理，不私自复制一套发灰贴图来模拟水下。原已登记的海下色板变体保留，可显式复用，不覆盖其已批准色格或改旧资产。
- 独立观赏楼主体、屋顶放到实际海面下，按参考图安排疏密、深度和朝向，避免与阳光房基座穿插。基座顶板按上方水上平台板底作视觉接合，不能套水上+0.3／+0.1米平台标高；接近水面的顶板不因此取得站立或阻挡资格。需要分段的跨水线源保持pending，不能只改类别当作几何分段完成。
- 全子树只渲染：不制作／导出／挂接角色碰撞、船只阻挡、导航障碍、WalkArea、LandingPoint、交互点、资源产出、升级／收获／仓储、玩法状态或新增玩法存档字段；不作岸线／泡沫来源。资产身份、静态摆放记录和只读环境时间驱动的视觉动画可以保留。
- 视觉上的门窗、柱脚、推进舱只作外观；无须为门窗设置可通行净洞口，不为了满足水上规则新增泊位、灯光交互或平台。纯视觉发光材质与功能入口分开。
- 母版、组件包及运行视觉包装独立维护；作为水上总成的子件时仍保持underwater。接入时显式排除水上父级对它递归派生阻挡／地面／岸线，不在制作Skill里重建正式手改TSCN。
- 源验收核同族比例、倒角、PaletteUV和真实多视图；接入后通过统一runner核世界标高／接合、全子树零空间与玩法功能，记录海面透水及昼夜真实渲染。旧water-layer专项有覆盖缺口，不能代替全部无功能验收；未执行项保持pending。
