# 区块配置（zones.js）说明与校验结果

更新时间：2026-10-17（第二轮：区块拉开到 2 船身宽通航净空）

海面上每块水域现在是一个独立配置对象，全部集中在 `zones.js`。
`gameplay.js` 不再持有任何区块坐标，只消费注册表；增删区块、搬动地块、改上岸点都只改这一份数据。

---

## 一、一个区块包含什么

```js
{
  id: 'zone2',            // 唯一键，state.currentZone / buildSites[].zone 都用它
  name: '横滨铁道',        // UI 显示名
  role: 'station',        // 功能角色：home / station / farm / shore / aquaculture
  purpose: '…',           // 一段话说明这个区块用来干什么
  status: '横滨铁道站台待机', // 小人停在该区块时顶部状态文案
  unlock: 'farSea',       // 可选：解锁条件（目前只有远海）
  origin: [-30, 0, -18],  // 区块锚点（模型 root 摆到这里）
  camera: [0, 1.2, 0],    // 相对 origin 的取景中心
  hover: [0, 5.32, 0],    // 相对 origin 的悬浮提示锚点
  site: [0, 0],           // 可选：区块内平台中心（zone5 的养殖台）
  boat: { park: [-3.27, 'water', 4.92], yaw: -0.92 },
  landing: { dockEdge: [-2.6, 1.17, 2.4], stand: [-2.7, 2.83, -0.3] },
  walk: [                 // 可站立区域：一个或多个地块，每块带高度窗口
    { id: 'zone2_station', y: 2.6, span: [1.1, 3.1], rects: [[-3, -2, -5, 2.5], …] }
  ],
  harbor: [ { kind: 'salvage', label: '…', point: [-12, 'water', 13] } ]
}
```

**坐标是相对 origin 的**（x、z 自动加 origin，y 一律是绝对世界高度）。
所以**搬动一个区块只改 `origin` 一个数字**，区块内部关系完全不动。
`rects` 每项是 `[minX, maxX, minZ, maxZ]`，同样相对。

### 关键设计：`span` 是高度窗口，`y` 只是设计意图

小人脚底高度**永远按模型实测**：行走、上岸、待机时在该地块的 `span` 里取最高的可站立水平面。
所以模型改了、道具挪了、台阶高度变了，角色不会悬空也不会陷进木板；多级平台（露台 3.1 → 屋顶 4.31）
只要窗口覆盖两段就会自动踩到正确那一级；没有支撑面的点直接判为不可达。

`zone5` 的岛面只有 0.03 露出水面，所以它的窗口下限压到 `1.0` —— 这类"贴水"地块别把下限设太高，
而且水位判定阈值必须是 `WATER_LEVEL + 0.02`（+0.05 会把整块台面过滤掉）。

## 二、当前布局与通航净空

船体实际 3.0m 宽（局部 ±1.32 × 1.12 缩放）、6m 长。用户要求区块之间至少 2 个船身宽，
所以下限取 6m；实际做到最窄 8m。

| 区块 | origin | 实体范围 x | 实体范围 z |
|---|---|---|---|
| zone1 晴空水巷 | (0, 0, 0) | −15.3 ~ 10.8 | −12.8 ~ 16.3 |
| zone2 横滨铁道 | (−30, 0, −18) | −44.3 ~ −20.3 | −25.3 ~ −1.3 |
| zone3 圆弧农场 | (−2.25, 0.3, −29) | −10.3 ~ 6.3 | −35.8 ~ −20.2 |
| zone4 远海街町 | (39.5, 0, −41.5) | 29.8 ~ 49.8 | −49.8 ~ −34.8 |
| zone5 浅水养殖台 | (22, 0, 16) | 18.8 ~ 25.8 | 13.3 ~ 19.3 |

两两净距（像素级实测，非包围盒估算）：

| 通道 | 净空 |
|---|---|
| zone1 ⇄ zone3（南北主通道） | **8.0 m** |
| zone2 ⇄ zone3 | 10.0 m |
| zone1 ⇄ zone5 | 10.6 m |
| zone1 ⇄ zone2 | 17.9 m |
| zone3 ⇄ zone4 | 23.7 m |
| 其余 | 34 ~ 52 m |

**唯一的东西向走廊**在 zone1 楼体南界（z = −12.8）与 zone3 北界（z ≈ −20.2）之间，
中线 z = −16.5，净空 7.9m。所有跨区块航线都从这里过。

## 三、校验结果

### `tests/zone-config.cjs` —— 配置是否落在模型上

| 区块 | 船壳侵入 | 上岸点（配置/模型） | 待机点（配置/模型） | 地块覆盖率 | 上岸→待机踩空 |
|---|---|---|---|---|---|
| zone1 | 0% | 2.10 / 2.15 | 2.15 / 2.15 | 100% · 91% | 0% |
| zone2 | 5.4% | 1.17 / 1.17 | 2.83 / 2.83 | 98% | 0% |
| zone3 | 3.2% | 3.10 / 3.10 | 4.31 / 4.31 | 99% | 0% |
| zone4 | 0% | 1.73 / 1.74 | 1.66 / 1.67 | 68% | 0% |
| zone5 | 0% | 1.35 / 1.35 | 1.15 / 1.15 | 100% | 0% |

zone2 / zone3 的 3~5% 船壳擦碰来自区块**内部**的水巷：那里只有 3~4m 宽，6m 长的船做不到 0%。
区块之间的通道不受影响。

### `tests/zone-spacing.cjs` —— 区块间距（新增）

逐区块按模型根栅格化实体占据，算两两最小净距；同时检查背景遗迹不会挤进航道。
当前最窄 8.0m，达标。

### `tests/zone-travel.cjs` —— 真实航行 + 上岸 + 航迹穿模

从木屋出发，依次真实航行到 zone2 / zone3 / zone5 / zone4：

| 区块 | 到站 | 落脚高度 | 模型表面 | 偏差 | 离待机点 | 船离停泊位 | 航迹贴模型 |
|---|---|---|---|---|---|---|---|
| zone2 | ✓ | 2.83 | 2.83 | 0.00 | 0.12 m | 0.00 m | **0%** |
| zone3 | ✓ | 4.31 | 4.31 | 0.00 | 0.09 m | 0.00 m | **0%** |
| zone5 | ✓ | 1.15 | 1.15 | 0.00 | 0.10 m | 0.00 m | **0%** |
| zone4 | ✓ | 1.62 | 1.64 | −0.01 | 0.11 m | 0.00 m | **0%** |

航迹检测口径：航行中每 100ms 记一次船位与朝向，按船壳轮廓取 6 个采样点向下打射线，
只认船体高度带（水面 +0.45 ~ +2.4）内的实体；起终点 12m 内（区块自己的停泊水巷）豁免，
贴水浮叶等装饰也排除。

## 四、增删 / 搬动区块怎么做

**新增**：在 `ZONE_DEFS` 加对象 → 在 `SAIL_ROUTES` 补 `'zoneX>zoneY'` 航点（也可以先不补，走直线 + 障碍绕行）→
建造点把 `zone` 指向新 id → 跑 `tests/zone-config.cjs` + `tests/zone-spacing.cjs`。

**删掉**：删对象；`startSailBetweenZones` 会自动拒绝不存在的 id。注意同时清理挂在该区块的建造点。

**搬动**：**只改 `origin` 的 x/z**。模型、停泊位、上岸点、可站立区域、相机、悬浮锚点全部跟着走。
然后跑 `zone-config`（配置还在模型上吗）、`zone-spacing`（会不会和别人挤在一起）、
`zone-travel`（航线还能不能走通）。

**改功能**：`role` / `purpose` / `status` 决定 UI 文案；`harbor` 决定这个区块能提供打捞还是交易；
`unlock` 决定航行是否放行。

### 岸线水纹会自动跟随

水面 shader 的岸线不再写死坐标，而是吃 `waterSystem.setShore(shapes)` 传进来的一组轮廓：
`water.js` 提供 `uShoreA[32]`（中心 x/z、半宽、半深）+ `uShoreB[32]`（朝向、是否圆形）+ `uShoreCount`，
片元里用循环 SDF 取最近距离，方框与圆形（圆柱楼）都支持。

轮廓本身在 `index.html` 的 `shoreOutline()` 里现算，来源只有两处：

1. **区块地块** `zones.js` 的 `walk[].rects` —— 地块矩形就是平台与水面相接的位置，所以改 `origin` 后水纹自动跟着走；
   矩形是可站立面、比真实甲板小一圈，统一外扩 `EDGE = 0.55` 水线才露得出来。
   地块四角为空、中心实心时判定为圆形建筑（zone3 圆弧农场），岸线改用等半径圆，避免方角在圆楼外鼓出方包。
2. **水街区地标与废墟塔**（`water-district.js` 的 `towers` / `landmarks`）—— 只取**穿过水面的那一层**，
   这样屋顶挑檐不会把水圈撑大，沉在水下的屋顶也不会画水线。

搬动建筑后不需要动 shader；只要移动的是区块地块或 `water-district` 的节点，重开页面即可。

## 五、第二轮一并修掉的问题

1. **zone2 与 zone3 原本互相重叠**（净距 0），zone1 与 zone3 只有 6m。已重排：zone3 移到正南，zone2 留在西北，zone5 东移。
2. **航线穿过 zone1 的木屋和 zone3 的建筑**。原来用 `[[0,0],[-4,-7]…]` 这类航点，`(0,0)` 就在楼里。
   现在所有航线沿 z = −16.5 的走廊走。
3. **背景遗迹挤进航道**：`reference-balcony-residence` 原本在 (4,−25) 正好压在 zone3 新位置的停泊位上；
   `reference-round-garden-building` 在 (−36,0) 与 zone2 北端重叠；`peripheral-ruin-0` 挡住 zone3 南侧。
   三处已移到外围（water-district.js）。
4. **zone1 的模型范围之前被漏算**：`open-industrial-ruin` 实际延伸到 z = −12.8，而 zone-spacing 只算了
   `home_cabin.hitRoots[0]`（到 −6.8），会高估净空。现在 zone1 纳入全部 `open-industrial-ruin`。
5. **区块坐标改成相对 origin**，以后搬动只改一个数字。

### 第三轮（00:00）

6. **岸线水纹完全不跟随区块**：`water.js` 的 `shore()` 把 14 个岛的轮廓写死在 GLSL 里，
   区块搬了水纹还留在原地（浅水养殖台实际 (22,16)、水纹在 (16,15)；圆楼搬到 (−54,12) 后
   水圈还挂在 (−36,0) 的空水面上）。现在改为 `setShore()` 数据驱动，详见上一节。
7. **zone3 圆弧农场离 home 平台太近**（origin z 由 −29 改到 −36，屏幕上移约 30px），
   航线末端航点由 (10,−20)/(10,−23) 延到 (10,−28)；搬近后 `peripheral-ruin-0` 只剩 2m 净距，
   同步挪到 (−19,−51)。现在最窄通道 zone2 | zone3 = 10.59m。

## 六、相关文件

- `zones.js` —— 区块配置与注册表（唯一数据源，坐标相对 origin）
- `gameplay.js` —— 只消费注册表；`probe.stand(x,z,lo,hi)` 可现场查任意点能站多高
- `harbor-layout.js` —— 码头岛屿 / 养殖台 / 屋顶农场按区块点摆放
- `economy-view.js` —— 区块名称与解锁条件也读注册表
- `water-district.js` —— 背景遗迹位置（搬动区块时要让开）
- `tests/zone-config.cjs` —— 配置是否落在模型上的静态校验
- `tests/zone-spacing.cjs` —— 区块间距与航道净空
- `tests/zone-travel.cjs` —— 逐区块真实航行、上岸、航迹穿模
- `outputs/zone-ground.cjs` —— 导出某片区域真实可站立地面，用来画新区块的 `rects`
- `outputs/zone-layout-shots.cjs` —— 总览与各区块停泊近景截图
