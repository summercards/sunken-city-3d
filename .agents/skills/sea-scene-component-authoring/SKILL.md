# sea 场景组件制作

由 `02-battle-room-component-decomposer` 的组件规划、归类与实例规则，以及 `blender-game-prop-standard` 的色板 UV 规则适配。sea 使用治愈系视觉和自身目录，不继承 ShellStorm2 的战局、12 米墙高、5 米模数、紫色金属配色或房间互用率要求。

## 项目入口与所有权

先读 `GDD_V1.0.md`，定位 SEA-ASSET 并读取 `docs/features/asset/{spec,ledger}.md`。必要时读取实际消费者的功能文档。源文件保存在 `art_source/scenes/<套件>/v###/`，公共色板唯一保存在 `art_source/shared/palettes/`；正式运行资源仍为 `godot/assets/`。预览、临时导出和验证输出写入工程外 `sea-work/`，支持 `SEA_WORK_ROOT`。

通过 `assets/registry/ledger_index.json` 的 `domains.scenes` 解析分账本。AssetID 全库唯一，一份资产只有一条主记录；源索引是派生数据。登记实际源路径、SHA-256、manifest、版本、来源授权与验收阶段。新建源不代表正式接入，不以批量重算旧哈希接受未知修改。

## 先判断建筑类别，再加载差异

制作前先确认属于海上主场景；独立海底／潜水玩法场景另行处理，不套本Skill的“水下只观赏”约束。

1. 从`assets/registry/ledger_index.json`进入场景分账本，按稳定AssetID读取`building_class`。新资产在组件计划先写明类别和职责；非建筑不强行分类。不能只凭“沉没”名称、位置在水下或旧water_layer判断类别，更不能将沉错位置的水上功能建筑改成水下来掩盖故障。
2. `above_water`读取[水上功能建筑差异](references/above-water.md)；`underwater`读取[水下观赏建筑差异](references/underwater-scenery.md)。先确认下面共用风格基准，再加载所选类别的差异，不混用空间职责。
3. 混合设施逐总成／组件判断：阳光房设施总成归水上，独立海下基座归水下；分别读取对应差异，按AssetID维护各自职责。水上父级不能递归继承水下模型的碰撞、阻挡或功能。已有登记与用户新要求冲突时记录待修，不能默默改类或宣称验收通过。

两类只在空间职责、接合／摆位及验收上不同；尺寸、比例、倒角、公共色板、PaletteUV与材质角色共用一套。差异附件引用本入口基准，不各自复制数值表。水下不因观赏用途自动缩小、拉长柱子、减薄楼板或改成另一套灰暗材质；既有资产明确的尺寸、配色及面数例外仍保留。

## 计划先行

创建正式网格前写 `component_plan.json`，记录参考图哈希、尺寸假设、组件 AssetID、语义族、类别、原点、正面轴及预算。单套件唯一组件不超过 50；常规同族不超过 3，明确状态轴最多 5。只有配色差异时优先共享几何，用 PaletteUV 或材质实例参数表达。

按局部包络、接口、材质角色、几何指纹判断是否同件，不能仅凭尺寸归并。位置、方向、槽位属于实例，不产生新组件。超限时重整计划，不允许丢弃已获准的不同轮廓来凑数。

两类建筑与花草都必须分离：

- 建筑结构：基础、墩柱、墙壳、木板、屋顶构架。
- 固定设施与陈设：太阳能板、门窗、棚、灯、家具、容器和绳栏。
- 花草：叶簇、藤蔓、花束、棕榈；植物不焊进建筑或花盆。
- 展示支持：相机、背景、照明；不属于游戏组件。

每个计划项只有一份母版 Collection；重复摆放使用 Collection Instance。建筑与花草分别放在清晰的顶层集合，允许独立隐藏与导出。组件根及网格变换恒等，几何在底部中心原点，Collection.instance_offset 为零。组件独立包可单独打开；不导出整屋 GLB 代替组件交付。

## 水上／水下建筑共用尺寸与风格基准

适用于海上主场景中阳光房同族的水上功能建筑、水下观赏楼及海下基座的新建及改造。大尺寸以米、小尺寸以厘米保留一位小数；数值均指最终游戏尺寸，不是未缩放Blender源。下面是新制作默认值；历史实测精度只供溯源，不要求新模型追到多位小数。

| 项目 | 制作基准 |
|---|---|
| 底层净高（板顶到上层板底） | 4.9米 |
| 底层层高（板顶到板顶） | 5.1米 |
| 楼板、露台板、主要铺板厚度 | 0.2米 |
| 底层主柱截面 | 0.5×0.5米 |
| 门体／门框外包围高×宽 | 3.1×1.8米；仅比例参照，不是净门洞 |
| 上层小间／装饰柱高度 | 3.1米 |
| 上层装饰柱截面 | 0.4×0.4米 |
| 主平台板宽／拼缝 | 89.4厘米／2.6厘米；节距由二者相加为92.0厘米 |
| 栈桥板宽／露台板宽 | 75.0厘米／78.0厘米 |

倒角必须有真实几何，默认3段，倒角面平滑、主体平面保持平。下表是**最终游戏尺寸**的倒角宽，不得再乘阳光房原实例倍率：

| 构件 | 倒角宽 |
|---|---|
| 主柱 | 9.5厘米 |
| 主平台板／栈桥板 | 9.4厘米 |
| 屋顶压顶／女儿墙 | 16.4厘米／12.1厘米 |
| 棚柱／廊返 | 5.5厘米／7.8厘米 |
| 露台板／混凝土条 | 4.5厘米／4.4厘米 |
| 同族小摆件／细杆 | 小摆件参考2.0–3.5厘米；细杆参考0.8厘米，并受自身截面限制 |

倒角宽不得达到构件最小厚度的一半；先检查厚度再选档，不能因clamp压扁成薄片。源存在非均匀缩放时，按实际变换核对最终圆角，不能一律乘或除猜测的统一倍率。水上功能建筑需要净门洞时，另定可通行尺寸并验证胶囊，不能将外包围当净洞口；水下门窗只维护视觉比例。

建筑长宽、楼层数和屋顶轮廓按设计，层高、柱粗、板厚和圆角按上表控制；不要求复制阳光房造型。沿用暖木公共色板、厚实圆润轮廓，避免细针柱、薄皮楼板与过密板条。新件按本表；用户明确面数预算时允许登记倒角段数例外。

水线标高只在水上差异附件中应用；水下沿用共用结构比例，但使用水下差异附件的摆位和基座接合规则。

适用边界：玩家拼接套件已有2.8米层高及2段倒角属于既有独立规格，不用本表反改；其它特殊建筑在组件计划登记例外。海上主场景中的水下基座／观赏楼保持同族视觉关系，但不承担行走、阻挡或玩法功能；独立海底／潜水场景不适用本次基准。现有模型、运行板厚及水线不因本次取整自动修改；重导入／接入仍用设施专项核验。

[尺寸附件](references/building-scale.md)与[机器表](references/building_scale.json)保留历史测量和新制作默认值；新制作优先读本节，历史原始数值不能覆盖用户本次一位小数约定。

## 公共方格色板与材质

sea 首版使用 `art_source/shared/palettes/sea_cozy_8x8_512.png`，512×512、8×8 纯色色格，配套 JSON 记录色名、行列和 sRGB。格子边长 64 像素；行号从图像顶部开始。色板由米白、木色、海蓝、植物绿、花色与冷灰构成。修改已使用格子的含义前评估全部消费者。

两类与阳光房同族的建筑默认共用其正式暖木变体 `art_source/shared/palettes/sea_cabin_timber_8x8_512.png`；这是已登记的共享变体，不复制到套件，不改旧色板。建模按上方“水上／水下建筑共用尺寸与风格基准”的一位小数默认值执行，源／最终游戏尺寸口径见引用附件；不能给同族新建筑擅自套常规门高／层高或猜测的统一倍率。用户明确指定不同尺度时登记该资产的例外，不改其他建筑。

- 所有组件外链同一 PNG，不在每个包复制或打包。图片节点使用 `Closest`，明确由 `PaletteUV` 驱动。
- 每个面的 UV 是有面积的小岛，完整位于一个色格内并留至少 8 像素安全边；不压为单点。活动编辑层和渲染层均为 `PaletteUV`。
- 颜色由 UV 决定，质感由最多四个共享角色决定：`SEA_Matte`、`SEA_Metal`、`SEA_Gloss`、`SEA_Emission`。不为每个颜色新增材质。发光几何单独命名并分离。
- 有机叶片、花瓣使用平滑曲面；同族建筑硬边按上方最终尺寸倒角档位执行，默认3段。用户明确低面数预算时登记段数例外并保留实体倒角，不用平滑着色代替几何；不再套未区分源／运行尺度的通用宽度范围。

## 清单、验证与交付

`component_instances.json` 明确 Blender XY 平面、+Z 朝上、绕 Z 旋转的语义；到 Godot 的映射为 `(x,y,z) -> (x,z,-y)`。有倾斜的组件记录完整 Euler XYZ 或矩阵，不能用单一平面角度丢失姿态。正式 TSCN 拥有运行时摆位，实例清单只用于初始化和追溯。

逐组件记录 AssetID、building_class（建筑适用）、已加载差异附件、Collection、bounds、origin、front_axis、允许旋转、实例数、材质角色、源哈希、几何指纹、碰撞责任。自发光从主体网格分离。只服务本套件就登记为 `scene_local`，不虚构共享消费者。

保存后重新打开母版和独立包，核对组件数量、实例复用、集合偏移、根与网格变换、每面 UV 面积/安全格、图片路径、材质角色及非空几何。渲染参考镜头全景、近景、俯视，以及建筑单独视图；目视检查轮廓、密度、穿插与软边；水上核通路／泊位／空间投影，水下核水面透视／基座接合及全子树纯观赏职责。源级验证和 Godot 接入分开记录；Godot 验证必须走 `scripts/run_verification.py`。未做接入就保留 pending，不宣称游戏运行通过。

更新场景分账本、派生源索引、SEA-ASSET 功能账本和 `docs/development/`。运行 `python3 scripts/check_feature_contracts.py --sync`，再运行不带参数的检查；其他工作的哈希漂移应记录并定位，不能顺手覆盖。

当前完整示例为 `art_source/scenes/solar_flower_house/v004/`（48 组件、340 实例、48 个独立包、四视图验收齐全）；`v001`–`v003` 作为历史版本原样保留，不复用来顶替新版交付。制作与源级验收脚本位于 `tools/blender/solar_flower_house/`，按 `--version v00N` 指定版本。这些是新套件工具，不得用来全量重建已有手改 Godot 场景。

工程内不放 `resources/palettes/` 副本：公共色板在版本库中的唯一位置是 `art_source/shared/palettes/`，技能安装副本只用于用户级分发与恢复，避免同一份登记资产出现第二个可漂移的拷贝。

## 用户指定低面数时

面数上限按整场景计算：在最终保存文件的依赖图上读取修改器求值后的网格，三角化并累计每个可见实例；不能只算母版、不能漏算实例，也不能用大 N 边面掩盖实际三角形。显示多边形数与三角形数两项。相机/灯光不计几何，隐藏母版不与实例重复计算。

太阳能花屋 v002 的任务上限为整场景 3000 个三角面，用户明确要求优先于默认倒角段数。简化时保留轮廓和实际倒角，优先删除木纹、螺钉等细碎几何，把花叶改为少量宽厚体块。平台扩建应保持房体尺度，扩大实际铺板面积并以有明确坐标的净空带检查陈设侵入。此 3000 上限是该套件任务约束，不自动套到所有其他场景。
